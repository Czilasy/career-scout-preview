# Feature Specification: 关闭确认自绘化与运行中关闭收尾

**Feature Branch**: `codex/fix/unfinished-flow-recovery`

**Created**: 2026-09-25

**Status**: Draft（2026-09-25；产品口径来自本轮用户讨论拍板；本 SPEC 工件待用户确认冻结后进入 Plan/Tasks）

**Input**: 045 v1（未完成流程统一找回与关闭保存）已实现完毕。本轮只做两件事：一、关闭确认框现在是系统原生弹窗，与应用视觉格格不入，改为应用内自绘并跟随主题；二、v1 只覆盖了「暂停 / 报错 / 未运行」的关闭场景，补上「正在运行中关闭」。

## 冻结依据

### A 组：已定做法（来源：2026-09-25 用户讨论拍板）

**范围与呈现**

- 关闭确认只在**桌面 EXE 版**存在；网页浏览器版与源码版一律不做，关标签页由浏览器默认行为处理。
- 网页版不做的原因：浏览器的关闭拦截无法区分「有未完成流程」和「空闲」，一旦挂上每次关标签都拦，且提示样式与按钮不受应用控制，无法自绘。
- 确认框必须是**应用内自绘**，跟随应用当前主题（boss / 智联 × 明暗四套）。系统原生弹窗一律替换掉。
- 桌面壳所有关闭入口（自绘标题栏关闭键、系统关闭键、系统关闭快捷键）走同一套确认，不得出现某条路径绕过确认。

**未运行场景（暂停 / 报错 / 中断 / 已抓完未保存）**

- 沿用 v1 口径：确认框只给「结束并保存」和「取消」两个选项，不加第三个。
- 选「结束并保存」：先转进 04 结果页落轮，再关闭窗口。
- 选「取消」：不关窗、不改流程状态，现场原样保留。

**正在运行场景（queued / running，含抓取与 AI 筛选）**

- 确认框只给**一个动作键「立即结束」**，取消用右上 ✕ 或 Esc。
- **不提供「等这批抓完」选项**。用户点关闭说明他着急，等待会把窗口拖住，不如直接丢掉这一批。
- 文案：标题「还有任务正在进行中」；说明行「立即结束只保存已抓到的，这一批会丢弃；不着急可以先暂停，落盘后再关闭」；按钮「立即结束」。
- 选「立即结束」：**立即停止，不等当前这一批收尾**，只保存已落盘的岗位，落轮进历史后关闭窗口。
- 选「取消」：回到页面，用户可以自己点暂停、等落盘后再关闭。
- 抓取中与 AI 筛选中共用同一套文案与行为，不做两套。

**通用规则**

- 收尾逻辑**复用既有通用路线**（暂停 → 转 04 结果页落轮 → 进历史），不为关闭确认新增独立存储、状态机、页面或提醒体系。
- 岗位数为 0 时：不弹窗、不报错、不落轮，直接关闭。
- 点下动作键后必须给出**正在等待的反馈**（按钮置灰 + 转圈）；等待期间不得重复触发同一轮收尾。
- 应用内更新重启路径**不弹确认**，静默保存后退出——用户已经点过「立即更新」，再问一次会卡住替换流程。
- 取消必须真的保持现场；v1 存在「点了取消窗口仍然退出」的缺陷，本轮一并收掉。

### B 组：AI 推断与补充

- 无新增产品规则。具体实现位置、复用接口、通道方式与测试分工由 Plan/Tasks 决定。
- 主题维度中的平台（boss / 智联）只在前端运行时存在、不持久化，因此确认框必须由前端渲染，壳侧无法独立还原主题。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 未运行时的关闭确认（自绘化，Priority: P1）

用户在流程暂停 / 报错 / 中断 / 已抓完未保存、且已抓到岗位时点关闭，应用内弹出与当前主题一致的确认框，给「结束并保存」和「取消」两个选项。

**Why this priority**: 这是 v1 已覆盖的主路径，本轮只把承载它的弹窗换成自绘，视觉必须与应用统一。

**Independent Test**: 构造暂停且有岗位的轮次，点关闭；确认弹的是应用内自绘框、主题与当前一致，且保存后落轮关窗、取消后现场不变。

**Acceptance Scenarios**:

1. **Given** 存在未结束且岗位数 > 0 的流程且当前未在跑，**When** 点关闭，**Then** 弹出应用内自绘确认框，视觉与当前主题一致，选项只有「结束并保存」和「取消」。
2. **Given** 用户选「结束并保存」，**When** 保存完成，**Then** 该轮进历史可见，随后窗口关闭。
3. **Given** 用户选「取消」，**When** 确认框关闭，**Then** 窗口不关且流程状态不变。

---

### User Story 2 - 正在运行时的关闭确认（新增场景，Priority: P1）

用户在抓取或 AI 筛选正在跑、且已抓到岗位时点关闭，应用内弹出与当前主题一致的确认框，只给一个动作键「立即结束」，并说明这一批会被丢弃。

**Why this priority**: v1 缺少这个场景，正在跑的流程关闭时要么静默丢轮、要么走不到确认。这是本轮的核心增量。

**Independent Test**: 构造正在抓取且有已落盘岗位的轮次，点关闭；确认只出现「立即结束」一个动作键，选中后立即停止、只保存已落盘的部分、落轮进历史后关窗；取消则流程继续跑。

**Acceptance Scenarios**:

1. **Given** 流程正在运行且已落盘岗位数 > 0，**When** 点关闭，**Then** 弹出应用内自绘确认框，标题说明还有任务正在进行中，且**只有**「立即结束」一个动作键。
2. **Given** 用户选「立即结束」，**When** 收尾执行，**Then** 系统不等当前这一批跑完，只把已抓到的岗位落轮进历史，随后窗口关闭。
3. **Given** 用户选「立即结束」，**When** 收尾进行中，**Then** 动作键置灰并出现正在等待的指示，期间重复触发关闭不会再来一轮。
4. **Given** 用户取消，**When** 确认框关闭，**Then** 窗口不关、流程继续运行，用户可以自行暂停后再关闭。

---

### User Story 3 - 确认框视觉跟随应用主题（Priority: P1）

关闭确认框的配色、圆角、字体、按钮样式与当前应用主题完全一致，不存在任何系统原生弹窗。

**Why this priority**: 原生弹窗与应用界面格格不入是本轮要解决的直接问题。

**Independent Test**: 在 boss / 智联 × 明暗四种主题组合下分别触发关闭确认，逐套比对视觉是否与当前主题一致。

**Acceptance Scenarios**:

1. **Given** 当前是 boss 浅色主题，**When** 触发关闭确认，**Then** 确认框配色与圆角与该主题下的其它对话框一致。
2. **Given** 当前是智联深色主题，**When** 触发关闭确认，**Then** 确认框同样跟随该主题，不出现系统默认样式。
3. **Given** 任意主题下，**When** 触发关闭确认，**Then** 不出现任何系统原生弹窗。

---

### User Story 4 - 网页版不做关闭确认（Priority: P1）

用户在浏览器里使用（网页版 / 源码版）时关闭标签页，应用不做任何拦截，由浏览器默认行为处理。

**Why this priority**: 这是本功能分两端处理的边界，必须明确且不可被后续改动破坏。

**Independent Test**: 浏览器模式下构造未完成流程并关闭标签页，确认没有任何拦截提示。

**Acceptance Scenarios**:

1. **Given** 用户在浏览器模式下且有未完成流程，**When** 关闭标签页，**Then** 不出现任何应用侧拦截提示。
2. **Given** 浏览器模式，**When** 应用运行期间，**Then** 应用不注册任何关闭拦截。

---

### User Story 5 - 应用内更新重启不打扰（Priority: P2）

用户点了「立即更新」后软件自行退出重启，过程中不弹关闭确认，静默保存后退出。

**Why this priority**: 用户已经明确表达要更新，再问一次既多余又会卡住替换流程。

**Independent Test**: 构造未完成流程后走应用内更新重启，确认没有确认框打断且流程已保存。

**Acceptance Scenarios**:

1. **Given** 存在未完成流程且用户点了立即更新，**When** 软件自行退出，**Then** 不弹关闭确认，流程静默保存后退出并完成更新。

### Edge Cases

- 正在运行但已落盘岗位数为 0：不弹窗、不落轮、直接关闭。
- 确认期间流程状态发生变化：以确认动作发生时的最新状态重新判定。
- 落轮失败：不关闭窗口，用户能看到失败原因并可重试。
- 等待收尾期间再次触发关闭：不重复弹窗、不重复收尾。
- 主题为彩蛋主题时：确认框同样跟随该主题，不回退到通用样式。
- 已正常保存过的流程：不因关闭再次提醒。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 桌面版关闭确认 MUST 由应用内自绘组件呈现，MUST 跟随应用当前主题（boss / 智联 × 明暗四套及彩蛋主题）。
- **FR-002**: 关闭确认 MUST NOT 使用系统原生弹窗或系统对话框。
- **FR-003**: 桌面壳所有关闭入口 MUST 走同一套确认，MUST NOT 出现绕过确认的路径。
- **FR-004**: 未运行且岗位数 > 0 时关闭，MUST 弹出确认且选项 MUST 仅包含「结束并保存」和「取消」。
- **FR-005**: 选择「结束并保存」后，系统 MUST 先落轮让该轮可见，再关闭窗口。
- **FR-006**: 正在运行且已落盘岗位数 > 0 时关闭，MUST 弹出确认，且动作键 MUST 仅有「立即结束」，取消 MUST 可用。
- **FR-007**: 正在运行的确认 MUST NOT 提供「等这批抓完」或其它等待类选项。
- **FR-008**: 选择「立即结束」后，系统 MUST 立即停止而 MUST NOT 等待当前批次收尾，只保存已落盘的岗位，落轮进历史后关闭窗口。
- **FR-009**: 正在运行的确认 MUST 明确告知用户这一批会被丢弃、以及可以先暂停再关闭的选择。
- **FR-010**: 抓取中与 AI 筛选中 MUST 共用同一套确认文案与行为。
- **FR-011**: 选择取消后，MUST NOT 关闭窗口且 MUST NOT 改变流程状态。
- **FR-012**: 点下动作键后 MUST 给出正在等待的反馈（动作键置灰 + 等待指示），且等待期间 MUST NOT 重复触发同一轮收尾。
- **FR-013**: 岗位数为 0 时，MUST NOT 弹确认、MUST NOT 落轮，直接关闭。
- **FR-014**: 收尾 MUST 复用既有通用路线（暂停 → 转 04 结果页落轮 → 进历史），MUST NOT 新增独立存储、状态机、页面或提醒体系。
- **FR-015**: 正在运行的判定 MUST 覆盖排队中与运行中两类状态，MUST NOT 因状态字段缺失而漏判。
- **FR-016**: 网页浏览器版与源码版 MUST NOT 做任何关闭确认，MUST NOT 注册任何关闭拦截。
- **FR-017**: 应用内更新重启路径 MUST NOT 弹确认，MUST 静默保存后退出。

## Key Entities

- **关闭场景**: 分为「未运行」（暂停 / 报错 / 中断 / 已抓完未保存）与「正在运行」（排队中 / 运行中，含抓取与 AI 筛选）两类，两套确认文案与选项不同。
- **落轮**: 把已持久化岗位写入现有历史结果轮的动作；是进入历史和关闭保存的唯一收口。
- **已落盘岗位数**: 该流程已经持久化下来的列表岗位数量；用于是否弹窗与是否落轮的唯一判定口径。
- **当前批次**: 正在处理、尚未落盘的这一批岗位；选择「立即结束」即丢弃它。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 桌面版关闭确认 100% 由应用内自绘呈现，四种主题组合下视觉均与应用一致；系统原生弹窗 0 处。
- **SC-002**: 未运行且有岗位时关闭，100% 出现「结束并保存 / 取消」；保存后 100% 先进历史再关窗。
- **SC-003**: 正在运行且有岗位时关闭，100% 出现「立即结束」且无等待类选项；选中后 100% 不等待当前批次，落轮后关窗。
- **SC-004**: 取消 100% 保持现场——窗口不关、流程状态不变。
- **SC-005**: 已落盘岗位数为 0 时，100% 不弹窗、不落轮、直接关闭。
- **SC-006**: 网页浏览器版与源码版 100% 无关闭拦截。
- **SC-007**: 应用内更新重启 100% 不弹确认。
- **SC-008**: 点下动作键后 100% 有等待反馈，且等待期间不产生第二轮回。

## Verification Scope *(mandatory)*

- 开发、调试和返修阶段只运行聚焦测试、原失败用例和直接受影响的必要相邻回归；禁止每次修改机械运行全量。
- 整条交付链收敛后运行一次干净全量。
- 关闭确认是跨层链路，必须在实现完成后用真实应用界面走查四类路径：未运行保存关闭、未运行取消、正在运行立即结束、正在运行取消；每条单独记录实际现象、期望现象和是否一致。
- 主题一致性必须逐套肉眼核验，自动测试不能替代。
- 真实测试使用项目正式启动方式；无法满足环境前置时必须如实报告未执行，不得以自动化冒充。

## Assumptions

- 「未结束流程」沿用现有排队中 / 运行中 / 已暂停口径，不新增状态概念。
- 桌面壳的关闭事件是同步的，而应用内自绘确认是前端异步交互，两者的衔接方式由 Plan 阶段决定并在 `research.md` 记录结论。
- 确认框复用应用内既有对话框基座，不另造一套弹窗样式体系。
- 正式启动方式可运行真实界面时才执行真实界面走查；否则记录阻断。
