# Changes: 045 v1 → v2

本文件说明 `045 v2` 相对根目录 v1 历史基线的变化。**v1 已实现完毕，根目录平铺文档保留只读**；本轮是优化，不是重做。

## 变更概览

本轮只做两件事：

1. 关闭确认的呈现载体：系统原生弹窗 → 应用内自绘并跟随主题；
2. 关闭确认的覆盖范围：只覆盖未运行场景 → 补上正在运行中场景。

## 逐项变化

### 一、确认框自绘化

| 项 | v1 | v2 |
|---|---|---|
| 呈现载体 | Windows 用 tkinter 自绘系统控件、macOS 用系统 AppleScript 框 | 应用内自绘组件，基于既有对话框基座 |
| 主题 | 不跟随应用主题 | 跟随 boss / 智联 × 明暗四套主题及彩蛋主题 |
| 平台实现 | Windows 与 macOS 两套不同实现 | 两端共用同一组件 |
| 按钮文案控制 | 受系统控件限制（原生框按钮文案不可完全自定义） | 完全受控 |

伴随删除：v1 的 tkinter 与 osascript 两条原生弹窗实现路径不再需要。

### 二、运行中场景

| 项 | v1 | v2 |
|---|---|---|
| 运行中关闭 | 未覆盖；因运行中状态查不到岗位数，实际走「零岗位静默关闭」 | 覆盖，弹确认并给出「立即结束」 |
| 运行中收尾 | 无（直接取消任务，轮落 paused，不进历史） | 立即暂停后落轮进历史，再关窗 |
| 等待类选项 | 不存在 | 明确不提供（用户点关闭即代表不打算等） |
| 未运行场景 | 「结束并保存 / 取消」 | 不变 |

### 三、关闭链路形态

| 项 | v1 | v2 |
|---|---|---|
| 时序 | 同步：`closing` 内查询 → 阻塞弹框 → 收尾 → 放行 | 两段式：`closing` 立即取消 → 前端弹框 → 回调后收尾关窗 |
| 取消语义 | 部分路径失效（自绘关闭键与更新重启点了取消仍会退出） | 所有路径一致：取消即保持现场 |
| 更新重启 | 走同一决定器，会弹确认 | 不弹确认，静默保存后退出 |

### 四、判定口径

| 项 | v1 | v2 |
|---|---|---|
| 岗位数来源 | 运行中状态查不到岗位数，视为 0 | 运行中补齐岗位数，与未运行状态共用同一计数口径 |
| 效果 | 运行中一律静默关闭，不弹确认 | 运行中有岗位时正常进入确认 |
| 查询失败 | 保持窗口打开（宁可关不掉） | 放行关闭并记日志——查询失败时坚持不关窗会让用户关不掉软件；数据仍有兜底（轮落 paused 可恢复） |

### 五、网页版

| 项 | v1 | v2 |
|---|---|---|
| 浏览器模式 | 未明确声明，实际无拦截 | 显式规定不做任何关闭确认，禁止注册关闭拦截 |

## 保持不变

- 落轮机制：仍走既有「转 04 结果页落轮 → 进历史」，不新增存储、状态机、页面或提醒体系。
- 未运行场景的选项语义：「结束并保存」先落轮后关窗；「取消」保持现场。
- 零岗位规则：不弹窗、不落轮、直接关闭。
- 启动接回（B103）与分段回归（B104）的结论不在本轮变更范围内。
- 关闭判定仍由桌面壳单一负责，前端只按传入场景呈现。

## 废弃

- 系统原生弹窗路径（Windows tkinter、macOS osascript）整体废弃并删除。
- v1 契约 `contracts/desktop-close.md` 中「按钮由宿主 MessageBox 提供」一条作废，改由本版本 `contracts/close-confirm-bridge.md` 定义。
