# Feature Specification: 未完成流程统一找回与关闭保存

**Feature Branch**: `codex/fix/unfinished-flow-recovery`

**Created**: 2026-09-24

**Status**: Draft（2026-09-24；产品口径来自 roadmap/BACKLOG.md B101–B103 已定做法；本 SPEC 工件未经用户确认冻结）

**Input**: 用户确认 B101–B104 是一个修复整体：任何没有走完的流程都要能找回并进历史；有关闭提示，但只在有岗位且未结束时提醒；正常保存过的不再重复提醒；最终用真实界面完成分段回归。

## 冻结依据

### A 组：已定做法（来源：roadmap/BACKLOG.md B101–B103 讨论拍板）

- 流程没走完时数据可能留在库里，但历史找不到，清理也不会动它；用户必须能在某个入口看到并找回。
- 统一用“先转进 04 结果页落轮，然后结束”处理；不为它另做独立存储、独立状态机、独立页面或独立提醒体系。
- 进历史的分界线是有没有落轮，不是有没有 JD、也不是有没有跑 AI；抓到一条列表岗位就能落轮。
- 正常走了“结束并保存”的流程已经落轮进历史，下次启动不再提醒。
- 没有正常结束的（强杀、崩溃、断电）下次启动提示并可接回。
- 提醒只做提示 + 接回，不承担保存职责；不做启动时抢救式存盘。
- 仅在存在未结束流程（queued / running / paused）时，关闭窗口才弹提示。
- 关闭提示只给“结束并保存”和“取消”两个按钮；不加第三个选项。
- 点“结束并保存”先转进 04 落轮，再关闭。
- 没有未结束流程时正常关闭，不弹窗。
- 岗位数 = 0 时静默关闭，不弹窗、不报错、不落轮；被限流中断但已抓到岗位的流程要正常落轮。
- 分段路径必须在 B101–B103 实现完成后做真实界面走查；自动测试不能代替。
- 三条回归分别是：抓完跳过 AI 直接看结果、抓一半暂停后关闭、强杀进程后重启接回；每条单独跑并单独给结论。

### B 组：AI 推断与补充

- 无新增产品规则。具体实现位置、复用接口与测试方式由 Plan/Tasks 决定。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 未完成流程进历史（B101，Priority: P1）

用户在一轮流程未正常走到结果页后，仍然能在结果入口找回这轮；系统把已抓到的列表岗位转成 04 结果页的历史轮。即使只有列表信息、没有 JD 或 AI 判定，也能查看；后续补筛沿用同一条轮。

**Why this priority**: 数据凭空消失是核心信任问题；没有这一步，关闭和启动提示都无法给出可恢复结果。

**Independent Test**: 构造有已抓岗位且未正常结束的流程，启动应用后接回并查看 04；确认历史出现该轮，且状态是已抓取、未筛选或部分筛选。

**Acceptance Scenarios**:

1. **Given** 流程已抓到至少一条岗位且未正常结束，**When** 用户找回该流程，**Then** 系统先转进 04 结果页落轮，用户可见结果。
2. **Given** 落轮完成，**When** 用户查看历史，**Then** 该流程出现在历史里，不需要 JD 或 AI 结果。
3. **Given** 流程没有抓到任何岗位，**When** 找回或关闭，**Then** 不生成空历史轮，也不报错。

---

### User Story 2 - 关闭前保存未完成结果（B102，Priority: P1）

用户在存在未结束流程时点击窗口关闭，系统先确认用户是否结束并保存。确认后系统把结果落到 04，再关闭；取消则维持现场；无未结束流程或零岗位则不打扰用户。

**Why this priority**: 关闭是主动造成流程未结束的主要入口；在这里收口能最大程度避免数据消失。

**Independent Test**: 构造 paused/running/queued 流程并点击关闭；分别验证提示、落轮后关闭、取消保留现场、无任务关闭和零岗位关闭。

**Acceptance Scenarios**:

1. **Given** 存在未结束流程且岗位数 > 0，**When** 点击窗口关闭，**Then** 出现“结束并保存 / 取消”确认。
2. **Given** 用户选择“结束并保存”，**When** 保存动作完成，**Then** 流程进历史，窗口随后关闭。
3. **Given** 用户选择“取消”，**When** 确认框关闭，**Then** 窗口和流程现场保持原样。
4. **Given** 没有未结束流程，**When** 点击关闭，**Then** 不弹窗且直接关闭。
5. **Given** 未结束流程岗位数为 0，**When** 点击关闭，**Then** 不弹窗、不报错、不落轮并直接关闭。

---

### User Story 3 - 异常退出后启动提示接回（B103，Priority: P1）

应用因强杀、崩溃或断电停止后重新打开，若数据库里仍留着未正常结束且有内容的流程，启动时给一次提示并允许接回。此前已经“结束并保存”的流程不再提醒。

**Why this priority**: 异常退出时用户没有机会收尾，启动是唯一可靠的补救提醒点。

**Independent Test**: 构造未正常收尾的残留流程，重启应用；确认有提示且可接回；再构造已正常保存的流程，重启后不再提示。

**Acceptance Scenarios**:

1. **Given** 进程强杀前有未正常结束且有岗位的流程，**When** 重新打开应用，**Then** 启动提示该流程并可接回。
2. **Given** 用户已经“结束并保存”该流程，**When** 重新打开应用，**Then** 不再因为该流程提醒。
3. **Given** 残留流程岗位数为 0，**When** 重新打开应用，**Then** 不生成空轮，也不提供无内容接回。
4. **Given** 数据抓取过程中进程被杀，**When** 重启应用，**Then** 已持久化的岗位保持可用，不做额外抢救式存盘。

---

### User Story 4 - 分段路径真实回归（B104，Priority: P1）

交付前必须按三条独立清单走真实应用界面：分段抓取直接看结果、抓一半暂停后关闭、强杀后重启接回。每条单独执行并记录“实际现象 / 期望现象 / 是否一致”。

**Why this priority**: 本次修复专门作用于非一条龙路径；缺真实界面回归不能宣布完成。

**Independent Test**: 逐条执行 B104 清单；每条单独给出结论，不一致时记录具体差异。

**Acceptance Scenarios**:

1. **Given** 用户走分段入口只抓取不筛选，**When** 抓完后不进 AI、直接点看结果进 04，**Then** 04 正常出结果，该轮进历史且状态是已抓取、未筛选。
2. **Given** 抓取中途手动暂停，**When** 点窗口关闭并选择“结束并保存”，**Then** 提示只含两个按钮，这一轮进历史后再关闭；选择“取消”时回到原样且流程仍在。
3. **Given** 中途直接强杀进程，**When** 重新打开应用，**Then** 能看到该轮提示并接回；接回后继续跑完，最终进历史。

### Edge Cases

- 已有多枚残留流程时，启动提示和接回沿用既有一次性提醒的“最新优先、不接力”口径。
- 保存动作失败时不关闭窗口，用户能明确看到失败原因并重试。
- 关闭确认期间流程状态变化时，以确认时的最新数据库状态重新判定。
- 同一次应用会话里已正常保存的流程，不因关闭或重启再次提醒。
- 残留状态可能是“运行中”但没有真实工作线程；启动恢复必须能按可恢复处理，而不是永久卡住。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 任何未正常结束且已抓到至少一条列表岗位的流程，MUST 能经统一结果入口转进 04 并落轮。
- **FR-002**: 落轮 MUST 复用现有历史轮机制，MUST NOT 新增独立存储、状态机、页面或提醒体系。
- **FR-003**: 历史入口 MUST 按“是否落轮”判定可见性，MUST NOT 要求先有 JD 或 AI 判定。
- **FR-004**: 0 岗位流程 MUST NOT 落轮、MUST NOT 弹关闭确认。
- **FR-005**: 存在 queued / running / paused 未结束流程且岗位数 > 0 时，窗口关闭 MUST 弹确认；选项 MUST 仅包含“结束并保存”和“取消”。
- **FR-006**: 用户选择“结束并保存”后，系统 MUST 先落轮并让该轮可见，再关闭窗口。
- **FR-007**: 用户选择“取消”后，MUST NOT 关闭窗口且 MUST NOT 改变流程状态。
- **FR-008**: 没有未结束流程时，窗口关闭 MUST 直接执行原有关闭流程。
- **FR-009**: 应用重启时，MUST 能识别异常停止留下的未结束且有岗位的流程并提示接回；已正常落轮保存的流程 MUST NOT 再次提醒。原始 B103 的待确认项（强杀残留运行中状态能否认成可恢复）已在代码中验证，真实界面验证未执行。
- **FR-010**: 启动恢复 MUST 只提示和接回已持久化数据，MUST NOT 新增启动抢救式存盘。
- **FR-011**: B104 的三条路径 MUST 用真实应用界面执行；结果 MUST 单条记录实际现象、期望现象和是否一致。
- **FR-012**: 自动测试 MUST 覆盖落轮、关闭判定、启动恢复和一次性提醒口径，但 MUST NOT 冒充真实界面验收。

## Key Entities

- **未结束流程**: queued / running / paused 的流程；异常退出后的运行态若无真实工作线程，应视为可恢复残留。
- **落轮**: 把已持久化岗位写入现有历史结果轮的动作；是进入历史和关闭保存的唯一收口。
- **岗位数**: 该流程已持久化的列表岗位数量；用于确认与静默关闭判定。
- **提醒水位**: 既有“最新残留流程只提示一次”的机制；本次只扩展适用范围，不重复提醒已保存轮。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 有岗位的未正常结束流程 100% 可接回并出现在历史；0 岗位流程 100% 不产生空轮。
- **SC-002**: 有岗位且未结束时关闭 100% 出现双选项确认；无任务或零岗位关闭 100% 无确认。
- **SC-003**: 选择“结束并保存”后，历史可见与窗口关闭的顺序 100% 符合“先落轮、后关闭”。
- **SC-004**: 强杀重启后，已持久化岗位在接回结果中 100% 可见；无内容残留不打扰用户。
- **SC-005**: 正常保存过的流程在重启后 100% 不再提醒。
- **SC-006**: B104 三条真实界面用例全部执行且有明确“一致/不一致”结论。

## Verification Scope *(mandatory)*

- 开发、调试和返修阶段只运行聚焦测试、原失败用例和直接受影响的必要相邻回归；禁止每次修改机械运行全量。
- B101–B103 实现收敛后，先运行聚焦后端/前端测试，再在整条交付链收敛后运行一次干净全量。
- B104 必须在实现完成后执行，且三条都必须真实界面走查；自动化测试不能替代。
- 真实测试使用项目正式启动方式；无法满足环境前置时必须如实报告未执行，不得以自动化冒充。
- 若使用本地数据，必须先备份或在隔离测试环境执行，不得破坏正式库。（AI 补充，非原始需求）

## Assumptions

- “未结束流程”沿用现有 queued / running / paused 状态口径，不新增状态概念。
- 岗位数按数据库已持久化的流程岗位计数。
- 关闭确认由桌面层发起；Web 浏览器直连场景不属于桌面关闭确认范围。
- 正式启动方式可运行真实界面时才执行 B104；否则记录阻断。
