# Feature Specification: 续跑账号身份修复

**Feature Branch**: `030-fix-resume-account`

**Created**: 2026-08-30

**Status**: Draft

**Input**: User description: "修复任务继续时自动换号逻辑覆盖 R2 角色冻结账号的 bug：创建时快照当前全局账号、自动换号改为双门槛（用户暂停期间主动换过账号 且 暂停码非 AI 类）、旧 run 无快照不自动换、换号写任务事件与续跑日志行；顺带修复旧 run 兜底统一角色解析、job-detail 并发门禁、JD 阶段前重绑浏览器身份。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 续跑沿用任务自己的账号 (Priority: P1)

用户给浏览器账号打角色标记（如 R2 标给账号 b），全局当前账号是另一个账号（如 d）。以 b 冻结身份运行的 AI 筛选任务暂停后，用户点"继续"，任务必须继续使用 b，而不是被静默换成全局账号 d——现状是只要 d ≠ b，每次继续都会把任务身份永久改写成 d，R2 绑定彻底丢失。

**Why this priority**: 这是本次修复的核心缺陷。角色账号是任务身份契约的一部分，被覆盖后整轮筛选的登录环境、风控表现都错位，且不可逆（覆盖后所有后续续跑都错）。

**Independent Test**: 配置全局账号 d、R2 角色 b，发起 BOSS AI 筛选并制造暂停，点"继续"——可独立验证任务继续使用 b 且冻结身份未被改写。

**Acceptance Scenarios**:

1. **Given** 全局账号为 d、R2 角色标记为 b、AI 筛任务冻结账号为 b、暂停期间未更改全局账号，**When** 用户点"继续"，**Then** 任务继续使用 b，任务执行参数中的冻结账号保持为 b。
2. **Given** 同上但暂停原因为 AI 类阻断（AI 限流/额度/密钥/网络），**When** 用户点"继续"（即使暂停期间改过全局账号），**Then** 不自动换号，沿用 b——AI 阻断与浏览器账号无关。
3. **Given** 抓取或重抓任务暂停（冻结账号可能来自 R1 角色解析）、暂停期间未更改全局账号，**When** 用户点"继续"，**Then** 冻结账号不变。
4. **Given** 存量任务没有账号快照字段（旧版本创建），**When** 用户点"继续"，**Then** 不自动换号，沿用冻结身份。
5. **Given** 暂停原因为浏览器/账号类阻断（如源限流、登录失效）且用户在暂停期间主动把全局账号从 a 切到 b，**When** 用户点"继续"且未显式指定账号，**Then** 任务使用 b 继续（既有"面板切号后继续"能力保留）。
6. **Given** 用户在继续请求中显式指定目标账号，**When** 继续执行，**Then** 现有行为与校验完全不变（显式指令始终优先）。

---

### User Story 2 - 自动换号对用户可见 (Priority: P2)

自动换号保留的场景里（用户暂停期间主动切号），切换目前完全静默：用户不知道浏览器身份被换过。换号发生时必须有留痕——任务事件里可审计，任务进度日志里有一行用户能看懂的中文说明。

**Why this priority**: 可见性是信任边界。即使保留自动行为，用户也必须能看到"这轮是用哪个账号跑完的"，否则同类困惑会再次发生。

**Independent Test**: 制造一次满足门槛的自动换号并继续任务——可独立验证任务日志出现换号说明行、任务事件列表新增对应记录。

**Acceptance Scenarios**:

1. **Given** 一次满足双门槛的自动换号发生，**When** 续跑启动，**Then** 任务进度日志出现一行中文说明，包含原账号与新账号的名称。
2. **Given** 同一次换号，**When** 查询任务事件，**Then** 存在一条换号事件记录，含原账号与新账号标识。
3. **Given** 续跑未发生换号，**When** 查看日志与事件，**Then** 不出现换号相关内容。

---

### User Story 3 - 存量任务账号兜底口径统一 (Priority: P3)

旧版本创建的任务可能没有冻结账号字段。对这类任务，两条续跑入口目前给出不同账号：筛选提交入口按 R2 角色解析，统一继续接口借父任务的抓取账号或回退全局账号。同一任务从不同入口续跑会得到不同浏览器身份。

**Why this priority**: 只影响存量旧任务，频率低；但口径统一后两条路径行为可预期，且修复成本低（随本批次顺手完成）。

**Independent Test**: 构造无冻结账号的 BOSS 暂停任务与 R2 角色标记，分别从两个续跑入口触发——可独立验证两入口解析出同一账号。

**Acceptance Scenarios**:

1. **Given** BOSS 存量任务缺冻结账号、R2 角色标记为 b，**When** 从统一继续接口续跑，**Then** 使用 b（与筛选提交续跑入口一致），且解析结果写回任务冻结身份。
2. **Given** 智联平台存量任务缺冻结账号，**When** 续跑，**Then** 保持现有兜底行为不变（智联不受角色影响）。

---

### User Story 4 - 任务运行中浏览器不被其它操作抢用 (Priority: P3)

任务的浏览器身份隔离依赖进程级"当前浏览器目录"。任务运行期间（尤其 AI 粗筛这类无浏览器阶段），用户对旧结果点单岗位 JD 抓取会改写全局目录并启动浏览器，导致后续 JD 阶段用错账号的浏览器、甚至把任务正在用的浏览器关掉重启。

**Why this priority**: 触发需要并发操作，非必现，但一旦发生 JD 数据就采自错误账号环境。修复成本低（一处拒绝 + 一处重绑）。

**Independent Test**: 任务运行中调用单岗位 JD 抓取——可独立验证返回 409 与中文提示；以及全局目录被改后任务 JD 阶段仍使用自己冻结账号的浏览器。

**Acceptance Scenarios**:

1. **Given** 任一任务处于运行或排队状态，**When** 用户对旧结果点单岗位 JD 抓取，**Then** 请求被拒绝，返回 409 与中文提示，提示口径与其它任务入口一致。
2. **Given** AI 筛任务已进入 JD 抓取阶段、期间全局浏览器目录曾被其它请求改写，**When** JD 阶段启动浏览器，**Then** 使用任务冻结账号对应的浏览器身份。

---

### Edge Cases

- 快照字段缺失（旧版本创建的存量任务）：不自动换号，沿用冻结值；用户仍可显式指定目标账号换号。
- 暂停期间用户把全局账号改走又改回（当前值等于快照值）：视为未换号，不自动切换。
- 冻结账号已被从账号簿删除：沿用既有兜底链（角色解析 → 登录态过滤 → 回退），本批次不改变该链路。
- 显式指定的目标账号不存在或身份不可用：保持现有 404/409 校验行为。
- 重抓任务继承父任务账号：同样受快照双门槛保护。
- 智联平台任务：本批次所有账号改动均不影响智联（智联不受角色标记影响）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在任务创建时（抓取、AI 筛选、重抓三类入口）把当时的全局当前账号记录为账号快照，随任务执行参数持久化。
- **FR-002**: 统一继续接口的自动换号 MUST 仅在同时满足以下条件时发生：用户暂停期间主动更改过全局账号（当前全局账号 ≠ 创建时快照），且暂停原因不属于 AI 类阻断。
- **FR-003**: 任务缺少账号快照（存量数据）时，系统 MUST NOT 自动换号。
- **FR-004**: 用户显式指定目标账号的换号路径 MUST 保持现有行为（含账号存在性与浏览器身份校验）不变。
- **FR-005**: 自动换号发生时，系统 MUST 写入一条任务事件（含原账号与新账号标识），并在续跑启动时的任务日志中输出一行中文说明（含账号名称）。
- **FR-006**: 未满足自动换号条件时，续跑 MUST 沿用任务冻结身份，任何路径不得改写执行参数中的账号字段。
- **FR-007**: BOSS 平台存量任务缺冻结账号时，统一继续接口 MUST 与筛选提交续跑入口同口径，按角色标记解析账号；智联平台保持现有兜底不变。
- **FR-008**: 任务处于运行或排队状态时，单岗位 JD 抓取接口 MUST 拒绝请求并返回用户可读的中文提示。
- **FR-009**: AI 筛选的 JD 抓取阶段启动浏览器前，系统 MUST 将浏览器身份重绑到任务冻结账号。
- **FR-010**: 既有"续跑沿用冻结身份"的测试 MUST 全部保持通过（B057 面板切号场景按新门槛重新验证）。

### Key Entities *(include if feature involves data)*

- **任务执行参数**：每个任务 run 的冻结执行上下文，本批次新增"创建时全局账号快照"属性；冻结账号、平台、端口、资料目录键保持既有语义。
- **浏览器账号簿**：账号列表与 R1/R2 角色标记，角色→账号一对一；运行中改角色不影响已创建任务（既有契约）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 全局账号 d、R2 账号 b 场景下，AI 筛任务暂停→继续 100% 沿用 b，冻结身份零改写（回归测试覆盖）。
- **SC-002**: 既有"面板切号后继续"场景在新门槛下 100% 保持可用（既有测试不修改语义即通过）。
- **SC-003**: 每一次自动换号 100% 产生任务事件与中文日志行；未换号的续跑 0 条换号痕迹。
- **SC-004**: 任务运行或排队期间，单岗位 JD 抓取请求 100% 被拒绝且提示为用户可读中文。
- **SC-005**: 全部既有后端测试、前端测试、构建与仓库卫生检查通过，无回归。

## Verification Scope *(mandatory)*

- 功能/重构/拆分交付：验证范围为相关模块聚焦测试、后端全量测试、前端测试、`npm run build`、仓库卫生检查。
- 收口发布任务：默认只做卫生测试、hooks、`git diff --check`、`git status` 和 `scripts/release_check.ps1`（若存在）；不自动要求全量测试。
- 只有用户明确要求"全量/全部测试/完整验证"时，收口任务才执行全量测试。

## Assumptions

- "用户主动换号"以全局当前账号变化为信号：暂停期间用户通过账号面板激活其它账号即视为主动换号；改走又改回视为未换。
- 账号角色标记在任务运行期间可能变化；冻结值优先的既有契约不变（运行中改角色不影响当前任务）。
- 智联平台整体不受本批次影响；B057 显式换号的前端交互不改动。
- 版本提升按 patch 级别随收口批次执行。
- 工程约束（继承自项目宪法）：触及的超预警线文件必须净不增长，账号身份决策逻辑须落入新分域模块并在模块地图登记。
- Out of scope：R2 登录态缓存回退的可见化（记 BACKLOG）、每任务独立浏览器命名空间、前端切号 UI 改动。
