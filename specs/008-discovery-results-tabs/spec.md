# Feature Specification: 发现结果页三 tab 分类与单岗位 JD 补抓

**Feature Directory**：`008-discovery-results-tabs`  
**Created**：2026-07-22  
**Status**：Draft — ready for clarification or planning  
**Input**：用户希望将发现流程第 4 步（结果展示）从单列/单卡逐条审阅改为「匹配 / 不匹配 / 已筛除」三 tab 网格视图，明确感兴趣与不感兴趣的持久化策略差异，并为 JD 抓取失败的岗位提供单岗位补抓入口，补抓后不重跑 AI。

## 目标与产品边界

本功能在 006（卡片网格化）和 007（流程 UX 与筛选优化）已交付的基础上，对发现结果页做信息架构与操作语义收口：

1. **三 tab 分类**：将结果按 AI 精筛结论分为「匹配」「不匹配」「已筛除」三类，tab 切换不跳页，默认显示匹配 tab。
2. **网格 + 边框色区分**：沿用 006 的卡片网格布局，匹配 tab 卡片绿边框、不匹配 tab 卡片红边框，已筛除 tab 用简化卡片。
3. **JD 抓取失败归并不匹配**：JD 抓取失败的岗位归入「不匹配」tab，不单独开第四类；卡片内提供单岗位补抓入口。
4. **单岗位 JD 补抓**：补抓只填充 JD 内容，不重跑 AI 判定；补抓成功后卡片仍留在不匹配 tab，不自动跳到匹配 tab。
5. **持久化策略差异化**：感兴趣永久持久化（保留现状），不感兴趣只在本轮内存存活、不写数据库、下次发现流程自然清空。
6. **移除冗余入口**：移除单卡片逐条审阅 + 上一个/下一个导航，移除底部「AI 粗筛移除」折叠按钮。

本功能的核心用户承诺是：

> 用户完成发现运行后，结果页以三 tab 分类展示岗位，匹配/不匹配/已筛除边界清晰；JD 抓取失败的岗位可单独补抓 JD 但不重跑 AI；感兴趣跨流程保留，不感兴趣仅本轮生效，下次发现自然清空。

本功能不改变发现流程主链路、AI 评估算法、Stage A/Stage B 筛选逻辑和后端结果数据模型（除不感兴趣的持久化策略由持久化改为内存级外）。单岗位补抓复用现有 CDP 抓取能力，不新增抓取架构。

## 与既有规格的关系

- 继承 005 的发现运行、结果交付、AI 评估、反馈端点能力。
- 继承 006 的卡片网格布局、刷新恢复、岗位名称跳转、感兴趣按钮状态。
- **替代 006 FR-006 的持久化语义**：006 规定不感兴趣标灰保留并可通过「恢复」按钮撤销（持久化）；008 将不感兴趣改为本轮内存级（不写数据库），刷新或下次发现流程后自动清空。视觉标灰样式可沿用，但不再调用持久化端点。
- 继承 007 的 Stage A 粗筛 dropped 名单机制（产出「已筛除」类目）和详情抓取并行化（产出 JD 抓取失败标识）。
- 本规格不新增后端结果端点；「单岗位 JD 补抓」若现有端点不支持按岗位 ID 触发一次性抓取，则在 plan 阶段定义补抓端点契约。
- 本规格不改变 Stage A/Stage B 的 AI 评估逻辑，不引入 uncertain 分类，不引入 Stage B 补判。

## Clarifications

### Session 2026-07-22

- Q: 单岗位 JD 补抓使用哪种浏览器形态？ → A: 复用发现流程已登录的 CDP Chrome 实例，在该实例中开新 tab 抓完关闭该 tab（不关闭整个 Chrome）；若 CDP Chrome 未运行则提示用户先启动。
- Q: 「感兴趣」与「不感兴趣」按钮的状态关系？ → A: 互斥，标记其中一个自动取消另一个；不感兴趣覆盖感兴趣时需调用取消端点撤销数据库标记，感兴趣覆盖不感兴趣时仅清内存。
- Q: 「已筛除」卡片移除理由的持久化范围？ → A: 持久化到结果数据，刷新页面或下次发现流程后仍保留，便于用户复核 AI 是否误杀。
- Q: 补抓到的 JD 是否回写后端？ → A: 回写后端结果数据，刷新后保留；分类字段不变，仅 JD 字段更新。
- Q: 「查看详情」按钮与岗位名称跳转的关系？ → A: 两者行为一致（均新标签打开 BOSS 详情页），是同一目标的显式/隐式入口，不重复打开、互不干扰。

## 术语与统一语言

### 三 tab

结果页顶部的三个并排切换按钮：匹配、不匹配、已筛除。同一时刻只有一个 tab 处于激活状态，下方内容区显示该 tab 的卡片网格。

### 匹配（matched）

AI 精筛（Stage B）通过的岗位。展示在「匹配」tab，卡片带绿色边框。

### 不匹配（unmatched）

包含两类岗位的合并集合，均展示在「不匹配」tab，卡片带红色边框：

1. AI 精筛（Stage B）不通过的岗位。
2. JD 抓取失败的岗位（不论 AI 是否判定过，因缺 JD 无法支撑判定或抓取环节失败）。

### 已筛除（dropped）

Stage A 粗筛阶段被移除的岗位。展示在「已筛除」tab，使用简化卡片（只有岗位名 + 移除理由，不带操作按钮）。移除理由**持久化到结果数据**，刷新页面或下次发现流程后仍保留，便于用户复核 AI 决策是否误杀。

### 单岗位 JD 补抓

为单个 JD 抓取失败的岗位，复用发现流程已登录的 CDP Chrome 实例，在该实例中开新 tab 抓取该岗位的 JD 内容，抓完即关闭该 tab（不关闭整个 Chrome 实例）。补抓到的 JD **回写到后端结果数据**，刷新页面或下次发现流程后仍保留。补抓结果只填充该卡片的 JD 区域，不重跑 AI 判定，不改变卡片所在 tab。若 CDP Chrome 实例未运行，提示用户先启动。

### 感兴趣 / 不感兴趣

卡片底部的两个标记按钮，语义差异如下：

| 标记 | 持久化范围 | 写入目标 | 跨刷新 | 跨发现流程 |
|------|-----------|---------|--------|-----------|
| 感兴趣 | 永久 | 数据库 | 保留 | 保留 |
| 不感兴趣 | 本轮内存 | 内存 | 清空 | 清空 |

两个按钮**互斥**：标记其中一个时自动取消另一个。典型场景——用户对一个岗位的心意二选一，避免「已感兴趣 + 已不感兴趣」语义矛盾状态。当不感兴趣覆盖感兴趣时，需调用取消感兴趣端点撤销数据库标记；当感兴趣覆盖不感兴趣时，仅清内存态即可（不感兴趣本就不持久化）。

### 顶部统计行

结果页顶部显示的四个计数：共抓取、匹配、不匹配、已筛除。

## User Scenarios & Testing

### 场景 1：浏览匹配岗位（主流程）

用户完成发现运行后进入结果页，默认显示「匹配」tab。岗位以卡片网格排列（一行 3-4 个），每张卡片带绿色边框，顶部显示岗位名称和条件，中间显示完整 JD，底部有「感兴趣」「不感兴趣」「查看详情」三个按钮。

### 场景 2：浏览不匹配岗位（含 JD 抓取失败）

用户点击「不匹配」tab，下方切换为不匹配岗位的卡片网格，卡片带红色边框。其中 JD 抓取失败的岗位，卡片中间 JD 区域不显示内容，而是显示「抓取失败」提示和「刷新」按钮；其余 AI 精筛不通过的岗位正常显示 JD。

### 场景 3：浏览已筛除岗位

用户点击「已筛除」tab，下方切换为已筛除岗位的简化卡片网格。每张卡片只显示岗位名和 Stage A 给出的移除理由，不带任何操作按钮。

### 场景 4：tab 切换不跳转

用户在三个 tab 之间切换时，页面不发生跳转，仅下方内容区替换。顶部统计行的数字在切换时保持不变。

### 场景 5：单岗位 JD 补抓

用户在「不匹配」tab 中点击某张 JD 抓取失败卡片的「刷新」按钮，系统单独启动一个自动化浏览器抓取该岗位的 JD。抓取过程中按钮显示加载态。抓取完成后，浏览器关闭，卡片 JD 区域填充抓到的内容；卡片仍停留在「不匹配」tab，不跳到「匹配」tab，也不重新跑 AI 判定。

### 场景 6：标记感兴趣（跨流程保留）

用户在「匹配」或「不匹配」tab 点击卡片底部「感兴趣」按钮，按钮状态变为已感兴趣，岗位通过现有反馈端点写入数据库。用户刷新页面或下次再跑发现流程，该岗位仍标记为已感兴趣。

### 场景 7：标记不感兴趣（本轮内存）

用户在「匹配」或「不匹配」tab 点击卡片底部「不感兴趣」按钮，卡片视觉降级（如标灰），按钮状态变为已不感兴趣。用户刷新页面或下次再跑发现流程，该岗位的不感兴趣标记自动清空，卡片恢复正常外观。

### 场景 8：查看详情

用户点击卡片底部「查看详情」按钮，在新标签页打开该岗位的 BOSS 直聘详情页。点击不影响卡片状态，不触发标记。

### 场景 9：移除冗余入口

用户在结果页看不到单卡片逐条审阅界面，看不到「上一个/下一个」导航，看不到底部「AI 粗筛移除」折叠按钮。所有岗位浏览通过 tab + 网格完成。

## Functional Requirements

### FR-001：三 tab 切换

结果页顶部提供三个并排 tab 按钮：匹配、不匹配、已筛除。默认激活「匹配」tab，下方内容区显示该 tab 的卡片网格。点击其他 tab 时，仅下方内容区替换，页面不跳转，顶部统计行数字不变。

**验收条件**：进入结果页默认显示匹配 tab；点击其他 tab 内容切换且无页面跳转；同一时刻只有一个 tab 激活；切换 tab 不影响顶部统计行数字。

### FR-002：顶部统计行

结果页顶部显示四个计数：共抓取、匹配、不匹配、已筛除。统计行始终可见，数字在结果加载完成后一次性填充，tab 切换时不变。

**验收条件**：结果页顶部可见四个计数；四数之和 = 共抓取；切换 tab 时数字不变。

### FR-003：移除单卡逐条审阅与底部折叠

移除原有的单卡片逐条审阅界面和「上一个/下一个」导航，移除底部「AI 粗筛移除」折叠按钮。所有岗位浏览通过三 tab + 网格完成。

**验收条件**：结果页 DOM 中不存在单卡逐条审阅容器、上一个/下一个导航按钮、AI 粗筛移除折叠按钮；岗位浏览完全通过 tab + 网格完成。

### FR-004：网格布局与边框色区分

匹配 tab 与不匹配 tab 的卡片沿用 006 的卡片网格布局（桌面宽度一行 3-4 个，窄屏单列），卡片有相对固定大小。匹配 tab 卡片带绿色边框，不匹配 tab 卡片带红色边框。

**验收条件**：匹配 tab 所有卡片带绿色边框；不匹配 tab 所有卡片带红色边框；桌面宽度下一行 3-4 个卡片；窄屏单列。

### FR-005：已筛除简化卡片

已筛除 tab 的卡片使用简化样式，仅包含两个区域：岗位名称、Stage A 给出的移除理由。简化卡片不带「感兴趣」「不感兴趣」「查看详情」按钮，不带绿色/红色边框。移除理由随结果数据持久化，刷新页面或下次发现流程后仍保留。

**验收条件**：已筛除 tab 所有卡片只显示岗位名和移除理由；卡片中不存在任何操作按钮；卡片不带绿/红边框；刷新页面后移除理由仍可见；下次发现流程后该 run 的已筛除卡片移除理由仍可见。

### FR-006：卡片操作按钮

匹配 tab 和不匹配 tab 的卡片底部保留三个按钮：「感兴趣」「不感兴趣」「查看详情」。已筛除 tab 的卡片不带任何操作按钮。「查看详情」按钮与 006 FR-005 的岗位名称跳转行为一致——均在新标签页打开该岗位的 BOSS 直聘详情页，两者是同一目标的显式按钮入口与隐式岗位名称入口，不重复打开，点击互不干扰。

**验收条件**：匹配 tab 和不匹配 tab 每张卡片底部有三个按钮；已筛除 tab 卡片无按钮；点击「查看详情」在新标签打开 BOSS 直聘详情页；点击岗位名称同样在新标签打开同一详情页；两者不重复打开、互不干扰、不触发标记。

### FR-007：JD 抓取失败归不匹配

JD 抓取失败的岗位归入「不匹配」tab，不单独开第四类。该类岗位的卡片在 JD 区域不显示 JD 内容，而是显示「抓取失败」提示和「刷新」按钮。

**验收条件**：JD 抓取失败的岗位出现在不匹配 tab；该类卡片 JD 区域显示「抓取失败」+「刷新」按钮；不单独开第四个 tab。

### FR-008：单岗位 JD 补抓

用户点击 JD 抓取失败卡片上的「刷新」按钮，系统复用发现流程已登录的 CDP Chrome 实例，在该实例中开新 tab 抓取该岗位的 JD 内容，抓完关闭该 tab（不关闭整个 Chrome 实例）。抓取过程中按钮显示加载态，期间不允许重复点击。JD 内容填充到该卡片的 JD 区域，并回写到后端结果数据。若 CDP Chrome 实例未运行，给出明确提示要求用户先启动，按钮可再次点击。

**验收条件**：点击刷新 → 在已登录的 CDP Chrome 中开新 tab 抓取该岗位 JD → 抓完关闭该 tab（Chrome 实例保持运行）→ 卡片 JD 区域填充内容 + 回写后端结果数据；抓取过程中按钮禁用；抓取失败时给出明确错误提示且按钮可再次点击；CDP Chrome 未运行时给出启动提示且按钮可再次点击；刷新页面后补抓到的 JD 仍可见。

### FR-009：补抓不重跑 AI、不跨 tab

补抓成功后，仅更新该卡片（及后端结果数据）的 JD 字段，不重新跑 AI 判定，不改变该卡片所在的 tab 分类。卡片仍停留在「不匹配」tab，不自动跳到「匹配」tab。后端结果数据中该岗位的分类字段（matched/unmatched/dropped）保持不变，仅 JD 字段被更新。

**验收条件**：补抓后卡片 JD 区域有内容；卡片仍在不匹配 tab；后端结果数据中该岗位分类字段不变、JD 字段已更新；不触发任何 AI 评估调用；tab 不自动切换。

### FR-010：感兴趣持久化（保留现状）

点击「感兴趣」按钮，岗位通过现有反馈端点写入数据库，跨刷新和跨发现流程保留。再次点击可取消。本需求保留 006 已实现的感兴趣持久化行为，不改变其语义。

**验收条件**：标记感兴趣 → 刷新页面后仍为已感兴趣 → 下次发现流程仍为已感兴趣；取消感兴趣 → 刷新后不再标记。

### FR-011：不感兴趣本轮内存

点击「不感兴趣」按钮，标记仅存在于本轮内存中，不写入数据库。卡片视觉降级（如标灰）。刷新页面或下次发现流程后，不感兴趣标记自动清空，卡片恢复正常外观。本轮内再次点击可撤销。

**验收条件**：标记不感兴趣 → 卡片视觉降级 → 刷新页面后标记清空、卡片恢复 → 下次发现流程后标记清空；本轮内再次点击可撤销。

**与 006 的关系**：本需求替代 006 FR-006 中「不感兴趣通过反馈端点持久化」的语义。视觉降级可沿用 006 已实现的标灰样式，但不再调用持久化端点。

### FR-012：感兴趣与不感兴趣互斥

「感兴趣」与「不感兴趣」两个按钮互斥：标记其中一个时自动取消另一个。典型场景为用户对一个岗位的心意二选一，避免「已感兴趣 + 已不感兴趣」语义矛盾状态。

- 标记不感兴趣覆盖感兴趣时：调用取消感兴趣端点撤销数据库标记，同时写入内存态不感兴趣。
- 标记感兴趣覆盖不感兴趣时：清内存态不感兴趣，调用反馈端点写入数据库感兴趣标记。

**验收条件**：已感兴趣的岗位点击不感兴趣 → 数据库感兴趣标记被撤销 + 内存不感兴趣生效 + 卡片视觉降级；已不感兴趣的岗位点击感兴趣 → 内存不感兴趣清空 + 数据库感兴趣标记写入 + 卡片视觉恢复；任一时刻同一张卡片不会同时处于已感兴趣 + 已不感兴趣状态。

### FR-013：明确排除项

本规格明确不做以下事项：

1. 不加「移动到匹配」按钮——卡片在哪个 tab 由 AI 判定决定，人工不移动。
2. 不做 uncertain 单独分类——JD 抓不到直接归「不匹配」。
3. 不做 Stage B 补判——补抓 JD 后不重新跑 AI。

**验收条件**：结果页不存在「移动到匹配」按钮；不存在 uncertain tab 或第四个 tab；补抓 JD 后不触发 Stage B 评估。

## Success Criteria

1. **tab 切换无跳转**：用户在三个 tab 间切换 100% 不发生页面跳转，仅下方内容区替换。
2. **默认 tab 正确**：100% 的发现运行完成后，结果页默认显示「匹配」tab。
3. **分类覆盖率**：所有结果岗位 100% 落入且仅落入一个 tab（匹配/不匹配/已筛除），无遗漏、无重复。
4. **网格密度**：桌面宽度（≥1200px）下匹配/不匹配/已筛除 tab 每行展示 3~4 张卡片，窄屏（<768px）下降为单列。
5. **边框色辨识度**：匹配 tab 卡片绿色边框、不匹配 tab 卡片红色边框，在 3 米外仍可辨识分类。
6. **JD 失败补抓可用性**：JD 抓取失败的岗位点击「刷新」后，≥90% 能在单浏览器会话内补抓到 JD 内容并填充到卡片。
7. **补抓不重跑 AI**：100% 的补抓操作不触发 AI 评估，不改变卡片所在 tab。
8. **持久化策略正确性**：感兴趣标记 100% 跨刷新/跨发现流程保留；不感兴趣标记 100% 在刷新或下次发现流程后清空。
9. **冗余入口清除率**：结果页 100% 不存在单卡逐条审阅、上一个/下一个导航、AI 粗筛移除折叠按钮。

## Assumptions
