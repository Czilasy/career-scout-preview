# Phase 1 Data Model: 测试体系低噪音瘦身

本 Spec 不涉及数据库与产品数据结构变更。以下为治理工作的"工作对象模型"，用于批次台账与验收对账。

## 批次（Batch）

- 字段：`id`（1–5）、`名称`、`范围摘要`、`入口条件`、`完成定义（DoD）`、`验证方式`、`停滞点`
- 状态机：`待启动` → `进行中` → `已完成（待用户确认）` → 用户放行后进入下一批；用户中止则停在当前批
- 说明：批 5 有额外前置——待删清单须经用户逐项同意；批 2 的删除型条目有"引用复查"前置；批 3 有"指纹验证"前置

## 条目（Item）

- 字段：`编号`、`类型`（修复 / 删除 / 合并降级 / 隔离 / 资产删除）、`位置`（文件:行号；行号以实施时内容为准）、`证据`（为什么处理）、`验证方式`（引用复查 / 故障注入指纹 / 回归 / 构建）、`状态`
- 状态机：`待处理` → `已处理（验证通过）` ｜ `退回（验证失败，已回滚并登记）` ｜ `保留（论证后不处理，登记原因）`
- 约束：**删除类**必须先做"引用复查"（全仓检索 0 命中）；**合并/挪动/改写类**必须先做"故障注入指纹"（红集合一致）

## 指纹记录（Fingerprint）

- 字段：`组号`（对应重复组）、`注入点`（产品文件 + 注入方式）、`受影响测试集`、`改动前红集合`、`改动后红集合`、`结论`
- 约束：结论为"不一致"时必须回退该组改动并向用户登记；波动时重跑三次（spec Edge Cases）

## 登记册条目（DeadCode）

- 字段：`编号`（D00N）、`位置`、`内容`、`查证记录`、`建议处置`、`用户同意状态`（未过目 / 已同意 / 不同意 / 剔除）
- 状态机：`候选` → `待删（用户已同意）` → `已删除（全量 + 构建通过）`；或 `剔除`（发现新引用 / 用户不同意 / 复核不成立）
- 存放：`specs/040-test-suite-slimming/dead-code-registry.md`（随发现追加）

## 基线快照（Baseline）

- 字段：后端（文件数 / 行数 / 用例数 / 时长）、前端（同）、采集时间
- 用途：每批收尾对比（SC-005 / SC-006）
- 当前基线（2026-09-11 实测）：后端 127 / 65,697 行 / 3163 例 / 约 19 分钟；前端 52 / 21,402 行 / 872 例 / 约 26 秒

## 批次定义（五批）

| 批次 | 名称 | 范围 | 验证重点 | 特殊前置 |
|---|---|---|---|---|
| 1 | 假保护必修 | 断言不执行/恒真/名实不符/过期门禁/永久跳过（约 20 条） | 修复后能注入变红 | 无（semantic 与前端孤儿已转批 5） |
| 2 | 零风险删除 | 零引用死件、逐字重复用例、未用导入与死参数、资源回收（约 55 条） | 引用复查 0 命中 + 全量不变红 | 每条删前复查引用 |
| 3 | 重复选边 | 多文件重复事实（约 30 组） | 故障注入指纹一致 + 正本断言只增不减 | 每组先建指纹 |
| 4 | 缠结小修 | 状态还原、真实资源隔离、临时目录、定时器、构建指纹、钩子路径（约 15 条） | 单独/换序/重复跑一致；真实资源零触碰 | 无 |
| 5 | 死代码回收 | 登记册 D001–D00N | 全量 + 前端构建全绿 | 清单逐项经用户同意 |
