# Contracts: 批次治理与验证

## 1. 批次契约（五批）

- 顺序冻结：①假保护必修 → ②零风险删除 → ③重复选边 → ④缠结小修 → ⑤死代码回收。
- 每批 DoD（缺一不可）：
  1. 本批条目全部处置（已处理 / 退回 / 保留，均有记录）；
  2. 受影响子集全绿 + 仓库卫生全绿；
  3. 批末：后端全量 + 前端测试 + `npm run build` 全绿；
  4. 统计对比（文件数/行数/用例数/时长）与批末报告；
  5. 死代码登记册更新（本批新发现项已登记）。
- **停滞点**：每批完成后停止；下一批必须等待用户当轮明确指令。

## 2. 条目处理契约

| 条目类型 | 前置 | 通过标准 |
|---|---|---|
| 删除（代码/资产/用例） | 全仓引用复查（记录检索式） | 0 命中；批末全量不变红 |
| 合并/降级（重复选边） | 故障注入指纹（A 先于改动） | A = B；正本断言只增不减；独有断言保留 |
| 修复（假保护） | 先定义"注入什么会红" | 修复后注入必红；修复前不红/不执行 |
| 隔离（缠结） | 无 | 单独/换序/重复跑一致；真实资源零触碰 |
| 删除产品死代码（批五） | 用户逐项同意 | 全量 + 前端 + 构建全绿；符号 0 命中 |

## 3. 指纹验证契约（操作定义）

1. 注入前确认产品文件干净（`git status --short`）。
2. 注入 = 对目标逻辑做最小、可逆的破坏（恒真/恒假/断开调用）。
3. 受影响测试集 = 该产品符号的全部引用方测试文件（含跨包引用）。
4. 记录变红用例清单（精确到用例名），变动前后各一次。
5. 比对必须**完全一致**；波动（并行/顺序差异）重跑三次仍不一致 → 回退该组，登记"不可合并"。
6. 注入必须在同一工作会话内还原并复核 `git status` 干净。

## 4. 报告契约（每批收尾向用户汇报的内容）

1. 改了什么：按类汇总 + 逐条清单（文件:行号 + 动作）。
2. 减了多少：文件数/行数/用例数变化（前后对比）。
3. 验证结果：受影响子集、全量、前端、构建、卫生、指纹一致性实测输出摘要。
4. 异常与偏差：退回条目、保留条目、复核与审计不符项、新发现死代码（登记册编号）。
5. 下一步：等待用户对下一批的指令。
