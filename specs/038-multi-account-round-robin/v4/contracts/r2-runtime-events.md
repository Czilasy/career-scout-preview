# Contract: R2 多账号真实请求与恢复事件

本契约定义 V4 可观察事实。字段名称可在实现阶段遵循项目既有风格调整，但语义、核对关系和敏感信息边界不得改变。

## 兼容原则

- 保留既有账号池快照、账号分配、账号切换和账号接力事件，避免旧任务查看能力失效。
- 既有 `account_allocation` 明确定义为“预留事实”，不得用于回答账号实际抓取数量。
- 新增真实请求开始、真实请求终态、轮询断点异常和账号工作汇总事实。
- 所有事件继续绑定 task id 并保持可排序顺序。

## account_allocation

语义：调度器为账号预留工作量，尚不证明平台请求已启动。

必需信息：阶段、平台、安全账号标识、分配段、轮次、预留数量、预留后剩余配额、待领取尾部数量、`fact_kind=reservation`。

## account_request_start

语义：目标账号已完成绑定并进入真实抓取调用。

必需信息：阶段、平台、安全账号标识、分配段、尝试标识、尝试序号、输入数量、证据标识。

禁止：在账号绑定失败、本地熔断短路或尚未调用抓取源时写入该事件。

## account_request_terminal

语义：一次真实尝试或本地短路已经形成可核对终态。

必需信息：阶段、平台、安全账号标识、分配段、尝试标识、输入数量、成功数、失败数、本地短路数、未完成数、安全失败分类、是否接力。

核对：输入数量必须等于四类终态数量之和。

## account_handoff

语义：未完成岗位从一个账号移交给下一账号。

必需信息：阻断账号、目标账号、移交数量、原因分类、排队/暂停结果、来源尝试标识。

禁止：仅因继承的共享熔断状态把目标账号再次记为平台撞墙。

## account_usage_summary

语义：任务完成或暂停时的按账号真实工作汇总。

每个账号至少包含：预留数、实际请求数、唯一成功数、实际失败数、本地短路数、接入数、移交数。

核对：全部账号唯一成功数之和必须等于详情抓取成功总数；无法核对时必须附带白箱不完整状态，不得输出伪造汇总。

## r2_rotation_checkpoint_invalid

语义：恢复断点缺失、损坏或与冻结任务身份冲突，系统无法安全继续。

必需信息：阶段、平台、安全原因分类、是否可恢复。不得记录账号凭据、Cookie、Token、简历正文或 JD 正文。

## 产物身份

每个 `account_request_start` 对应一个唯一产物身份。浏览器恢复重试、同账号再次尝试、跨账号接力均生成新身份；读取方不得依赖“最后一次覆盖前一次”。
