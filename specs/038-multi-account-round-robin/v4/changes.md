# V4 变化说明

## 相对 V3 的变化

- 保留 V3 已完成的账号弹窗信息架构和手动清除限流标记能力，不修改前端交互。
- 恢复 V2 的最高目标作为本版本验收核心：多个选中账号必须从任务开始按配额真实分摊 R2 详情岗位。
- 新增跨详情分块保持同一轮询状态的约束，禁止配额在每个内部调用中重置。
- 将本地熔断从共享状态明确收紧为账号级独立状态，禁止一个账号的阻断短路其他账号。
- 将“预留/分配”与“实际请求/实际成功”拆分为不同事实，增加按账号可核对的真实工作汇总。
- 要求账号接力、浏览器恢复和重试使用独立证据，禁止覆盖前一次尝试产物。
- 要求暂停恢复延续轮询断点，并在岗位后续成功取得 JD 时清理对应旧失败记录。
- 增加覆盖六账号 1048 条、跨 20 条分块、局部成功后撞墙接力和恢复清理的组合回归。

## 不变内容

- R1/R2 继续共用用户选中的账号池。
- 抓取继续串行执行，不引入多账号并发。
- 轮询顺序、配额含义、末轮零头、全部账号撞墙后暂停等 V2 业务语义不变。
- BOSS 与智联均在范围内。
- V3 的账号弹窗、限流视觉标记和手动清除能力不变。
- 不新增独立白箱产品，不修改平台风控策略，不伪造旧任务历史事实。

## 废弃的错误语义

- 废弃“不同账号可以共享同一个本地熔断状态”的错误测试契约。
- 废弃“每个外层详情分块重新创建一套轮询配额”的实际行为。
- 废弃“账号已预留岗位即可视为账号已经抓取”的解释口径。
- 废弃“跨账号重试可以复用并覆盖同一产物”的行为。
- 废弃“JD 后续成功但旧 JD 失败记录继续保留”的状态残留。
