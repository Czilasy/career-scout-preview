# Feature Specification: 多账号轮询分摊抓取（B091）

**Feature Branch**: `038-multi-account-round-robin`

**Created**: 2026-09-03

**Status**: Draft

**Input**: 用户确认需求（grill-me 边界质询逐条确认冻结，共 25 条）：

B091 · 抓取角色支持多账号分摊（R1 列表 / R2 详情多选 + 每账号分配目标）· 功能/优化 · 已确认（P1，2026-09-03）。原 BACKLOG 标题"BOSS 任务"为误写，实际为通用功能（BOSS + 智联都做）。

问题：账号弹窗里 R1（列表/广泛抓取）与 R2（详情抓取）目前是"角色→账号一对一互斥"，每个角色全程只能绑一个账号，工作量全压单账号上。B057 只在"撞限流墙后才被动换账号"，没有从一开始就把活儿分给多个人。

最高目标：从最开始就把抓取活儿分摊到用户预选的多个账号上，每个账号只暴露一小段请求量就主动换下一个，从源头降低单账号被平台风控盯上的概率；撞墙（验证码/限流）时在用户预选池里顺次切下一个继续，全程不靠用户手动盯。

## 最高目标（用户原话级，验收/任务的唯一衡量尺）

- 用户在账号弹窗里能多选多个账号参与抓取，开抓后系统按轮询把活儿分摊到选中账号上，每个账号每轮只抓固定配额就换下一个，总量不够就自动多轮覆盖，全程不用用户算数、不用用户盯。
- 哪个账号撞了验证码/限流，系统自动在用户预选的账号里顺次切下一个继续抓，不丢活儿；用户在账号列表上一眼能看到哪个账号被限流了（红字 + "限流"方框）。
- 所有预选账号都撞墙了，任务停下走"暂停"，用户自己看到限流标红后决定怎么办（等冷却/加账号/换时间）。
- 用户零配置可用：登录的账号默认全进账号池、默认全选、每账号带默认配额，开抓就是轮询；要调才手动改。

## User Scenarios & Testing

### User Story 1 - 多账号轮询分摊抓取（B091 核心，P1）

用户在浏览器账号弹窗里，R1（列表抓取）和 R2（详情抓取）共用一个账号池；用户多选若干账号参与抓取（不再是角色→单账号一对一互斥单选）。开抓后系统串行按轮询（round-robin）把活儿分摊到选中账号上：每轮每账号只抓固定配额（R1 按页、R2 按 JD 条数）就换下一个，总量不够就回到 1 号再来一轮，自动多轮覆盖任意总量，全程不用用户算数。轮询顺序按用户勾选顺序，第二轮从 1 号开始。

**Why this priority**: P1。这是 B091 区别于已完成的 B057 的核心增量——从"撞墙才被动换账号"升级为"从一开始就主动分摊"，从源头降低单账号风控触发概率，是整条需求的立身之本。

**Independent Test**: 后端聚焦测试——多账号轮询分摊逻辑（配额分摊、多轮覆盖、顺序、余数处理）；可独立于撞墙换号/视觉标识/默认配置单独验证。

**Acceptance Scenarios**:

1. **Given** 账号弹窗，**When** 用户为 R1/R2 多选账号，**Then** R1 和 R2 共用同一批选中账号（不是各自独立池）。
2. **Given** 已多选账号并开抓，**When** 执行列表抓取（R1），**Then** 系统串行按轮询把页数分摊到选中账号，每轮每账号只抓其 R1 配额页数就换下一个。
3. **Given** R1 总页数大于"账号数 × 每账号配额"，**When** 第一轮所有账号抓完各自配额仍未到底，**Then** 自动回到 1 号账号再来一轮，继续抓直到抓完或撞墙，不要求用户介入。
4. **Given** R1 抓完列表进入详情抓取（R2），**When** 执行 R2，**Then** 系统按轮询把 JD 分摊到选中账号，每轮每账号只抓其 R2 配额条数就换下一个。
5. **Given** R2 总岗位数大于"账号数 × 每账号配额"，**When** 第一轮不够，**Then** 自动回到 1 号再来一轮，继续抓直到抓完或撞墙。
6. **Given** 多个账号参与轮询，**When** 观察执行顺序，**Then** 按用户勾选顺序轮转，第二轮从 1 号开始（round-robin 标准）。
7. **Given** 用户未手动设每账号配额，**When** 开抓，**Then** R1 默认 25 页/账号、R2 默认 100 条/账号（取范围中值）。
8. **Given** 轮询末轮剩余不足一轮配额，**When** 抓取，**Then** 由下一个账号抓完零头自然结束，不引入余数分配规则（轮询按账号轮转，非总量÷账号数均分）。
9. **Given** 抓取执行，**When** 观察是否并行，**Then** 串行抓取（一次一个账号实例，不并行多实例）。

### User Story 2 - 撞墙顺次换预选账号兜底（B091 兜底，P1）

轮询分摊过程中，某账号撞到硬阻断信号（验证码、限流等导致自动化进行不下去）时，系统自动在用户预选的账号池里顺次切到下一个账号继续抓，撞墙账号没抓完的份额自动接力转给下一个账号（不丢弃，保总量）。撞墙换号复用已完成的 B057 现有逻辑，只是把"换号来源"从"系统全池自动挑"限定为"用户预选池顺次切"。

**Why this priority**: P1。分摊只降低撞墙概率不消除，撞墙换号在分摊架构里依然必须保留；它是 Story 1 的兜底，没有它分摊架构撞墙就断链。

**Independent Test**: 后端聚焦测试——撞墙信号识别 + 顺次切下一个预选账号 + 剩余份额接力；可独立于轮询分摊/视觉标识单独验证。

**Acceptance Scenarios**:

1. **Given** 轮询中某账号撞到验证码，**When** 系统判定为硬阻断，**Then** 自动切到用户预选池里的下一个账号继续抓。
2. **Given** 轮询中某账号撞到限流，**When** 系统判定为硬阻断，**Then** 自动切到下一个预选账号继续抓。
3. **Given** 撞墙的硬阻断信号（验证码、限流、以及其他导致自动化进行不下去的），**When** 触发，**Then** 都触发换号（硬阻断即换号）。
4. **Given** 某账号撞墙时尚有剩余份额没抓完，**When** 换号，**Then** 剩余份额自动顺次接力转给下一个预选账号继续抓，不丢弃，总量不丢。
5. **Given** 撞墙换号触发，**When** 取号，**Then** 从用户预选的账号池里顺次取下一个（不取用户没选的账号）。
6. **Given** 撞墙换号，**When** 复用现有换号逻辑，**Then** 走 B057 现有那套换号逻辑（不重写），只把取号范围限定到用户预选池。

---

### User Story 3 - 全撞完即停 + 账号限流视觉标识（B091 终态，P1）

所有预选账号都撞墙了，任务停下走现有"暂停"状态（不新增报错字段/弹窗）；用户看到暂停后自己去浏览器界面看，发现所有撞墙账号在账号列表项上字体变红 + 后缀小方框标"限流"，用户自己决定怎么办（等冷却 / 加账号 / 换时间）。

**Why this priority**: P1。它是兜底链的终点，决定"所有账号都失效"时系统怎么收尾、用户怎么知道发生了什么。

**Independent Test**: 前端测试——账号列表项限流视觉标识（红字 + 限流方框）渲染 + 后端全撞完走暂停状态；可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户预选的所有账号都撞墙，**When** 无可用账号，**Then** 任务停下走现有"暂停"状态（不新增报错字段/弹窗）。
2. **Given** 账号撞墙，**When** 用户查看账号弹窗/列表，**Then** 该账号列表项字体颜色变红 + 后缀小方框标"限流"字样。
3. **Given** 多个账号撞墙，**When** 用户查看列表，**Then** 每个撞墙账号都标红 + 限流方框。
4. **Given** 任务因全撞完而暂停，**When** 用户查看，**Then** 看到暂停状态 + 账号标红，自己决定后续（等冷却 / 加账号 / 换时间），系统不弹额外报错。
5. **Given** 限流视觉标识，**When** 实现，**Then** 只用账号列表项字体变红 + 后缀"限流"方框，不新增报错字段、不新增报错弹窗、不新增报错文案体系。

---

### User Story 4 - 默认零配置可用（B091 易用，P2）

用户登录的账号默认全部进入 R1/R2 账号池；用户新增一个账号，自动默认加进 R1、R2 两池（不用手动勾选加入）；R1/R2 池里所有账号默认是全选状态（默认都参与轮询），除非用户手动取消某个账号的勾选；每个账号默认带配额（R1 25 页、R2 100 条）。用户什么都不用设，开抓就是轮询跑；要调才手动改。

**Why this priority**: P2。核心分摊+兜底（Story 1-3）是 P1，零配置易用是锦上添花，但显著降低使用门槛，与核心同批交付。

**Independent Test**: 前端 + 后端测试——新增账号自动进池、默认全选、默认配额生效；可独立验证。

**Acceptance Scenarios**:

1. **Given** 用户已登录若干账号，**When** 打开账号弹窗，**Then** 所有登录账号默认已进入 R1/R2 池且默认全选。
2. **Given** 用户新增一个账号，**When** 保存，**Then** 该账号自动默认加进 R1、R2 两池（默认全选），不用用户手动勾选加入。
3. **Given** R1/R2 池账号默认全选，**When** 用户不手动调整，**Then** 所有账号都参与轮询；用户手动取消某账号勾选，**Then** 该账号不参与轮询。
4. **Given** 账号默认带配额，**When** 用户不改，**Then** R1 默认 25 页/账号、R2 默认 100 条/账号。
5. **Given** 用户全取消了所有账号勾选，**When** 尝试开抓，**Then** 校验阻止（至少 1 个账号选中才能开始）。

---

### Edge Cases

- **R1 总量未知**：R1 列表抓取翻页才知道有多少结果，总量在抓之前未知，轮询自动多轮覆盖，不预先算"够不够"、不预先弹提示。
- **R2 总量在 AI 初筛后才定**：R2 详情抓取总量由 AI 初筛筛完后决定，事前未知，轮询自动多轮覆盖，不预先弹提示、不事后重抓兜底。
- **每页条数平台差异**：BOSS 每页 30 条、智联每页 20 条，平台内部用，用户不感知；配额范围（R1 1-50 页 / R2 1-200 条）两平台一致。
- **末轮零头**：轮询末轮剩余不足一轮配额时，由下一个账号抓完零头自然结束（轮询按账号轮转，非总量÷账号数均分，不设余数规则）。
- **单账号多轮**：轮询下某账号可能抓多轮（如 1 号两轮、2/3 号一轮），每轮每账号都不超其配额，符合降风控初衷。
- **撞墙≠全撞完**：单账号撞墙走换号继续，只有所有预选账号都撞墙才走暂停。
- **新增账号自动进池时机**：新增账号自动默认加入两池（默认全选），无需用户手动操作。
- **旧配置/旧任务**：旧账号配置（角色→单账号互斥）与旧任务不兼容，全删，新 schema 直接上，不做迁移。
- **智联平台**：B091 为通用功能，BOSS + 智联都做（原 BACKLOG 标题"BOSS 任务"为误写，回头修正 BACKLOG）。

## Requirements

### Functional Requirements

- **FR-001**: R1（列表抓取）与 R2（详情抓取）MUST 共用一个账号池，用户多选账号同时参与两个角色（不再角色→单账号一对一互斥单选）。
- **FR-002**: 抓取 MUST 串行执行（一次一个账号实例，不并行多实例）。
- **FR-003**: 系统 MUST 按轮询（round-robin）把抓取量分摊到选中账号：每轮每账号只抓固定配额就换下一个，总量不够自动多轮覆盖。
- **FR-004**: R1 按页轮询分摊，每账号每轮页数配额范围 1–50，默认 25（取中值）。
- **FR-005**: R2 按 JD 条数轮询分摊，每账号每轮 JD 条数配额范围 1–200，默认 100（取中值）。
- **FR-006**: 每页条数（BOSS 30 / 智联 20）MUST 仅系统内部使用，用户不感知；账号弹窗输入框 MUST 用 placeholder 灰字提示配额范围，不暴露每页条数。
- **FR-007**: 轮询顺序 MUST 按用户勾选顺序，第二轮从 1 号开始（round-robin 标准）。
- **FR-008**: 轮询末轮不足一轮配额时，由下一个账号抓完零头自然结束；不设"余数给第一个"规则（Q3 旧均分余数规则被 Q9 轮询取代——轮询按账号轮转、不按总量÷账号数均分，余数概念不适用）。
- **FR-009**: 轮询分摊 MUST 在 R1（总量未知，翻页才知道）与 R2（总量在 AI 初筛后才定）两端都生效，自动多轮覆盖，不预先算"够不够"、不预先弹提示、不事后重抓兜底。
- **FR-010**: 撞墙信号（验证码、限流、以及任何导致自动化进行不下去的硬阻断）触发时，MUST 自动在用户预选账号池里顺次切下一个账号继续抓。
- **FR-011**: 撞墙账号的剩余份额 MUST 自动顺次接力转给下一个预选账号（不丢弃，保总量）。
- **FR-012**: 撞墙换号 MUST 复用 B057 现有换号逻辑，只把取号范围限定到用户预选池顺次切（不重写换号机制）。
- **FR-013**: 所有预选账号都撞墙时，任务 MUST 停下走现有"暂停"状态，MUST NOT 新增报错字段/弹窗/报错文案体系。
- **FR-014**: 撞墙账号在账号列表项上 MUST 字体颜色变红 + 后缀小方框标"限流"字样，作为唯一视觉标识（不新增专门报错 UI）。
- **FR-015**: 用户登录的账号 MUST 默认全部进入 R1/R2 账号池。
- **FR-016**: 用户新增账号 MUST 自动默认加进 R1、R2 两池，默认全选（不用手动勾选加入）。
- **FR-017**: R1/R2 池账号 MUST 默认全选，用户手动取消勾选的账号不参与轮询。
- **FR-018**: 每账号 MUST 默认带配额（R1 25 页、R2 100 条）。
- **FR-019**: 用户全取消所有账号勾选时，MUST 校验阻止开抓（至少 1 个账号选中才能开始）。
- **FR-020**: B091 为通用功能，BOSS + 智联两平台 MUST 都支持。
- **FR-021**: 旧账号配置（角色→单账号互斥）与旧任务 MUST 不做兼容迁移，全删，新 schema 直接上。

### Key Entities

- **账号池（R1/R2 共用）**：用户预选参与轮询的账号集合；R1、R2 共用同一批账号。
- **每轮配额**：R1 每账号每轮抓取页数（1–50，默认 25）、R2 每账号每轮抓取 JD 条数（1–200，默认 100）。
- **轮询顺序**：按用户勾选顺序，第二轮从 1 号开始。
- **撞墙状态**：账号被平台风控盯上（验证码/限流/硬阻断），在账号列表项标红 + "限流"方框。
- **预选池顺次换号**：撞墙后从用户预选账号池顺次取下一个（区别于 B057 的系统全池自动挑）。
- **暂停终态**：所有预选账号撞墙，任务走现有"暂停"状态收尾。

## Success Criteria

### Measurable Outcomes

- **SC-001**: 用户多选账号开抓，R1/R2 按轮询分摊到选中账号，每轮每账号只抓固定配额就换下一个，总量不够自动多轮覆盖，全程不用用户算数。
- **SC-002**: 轮询顺序按勾选顺序，第二轮从 1 号开始；末轮零头由下一个账号自然抓完。
- **SC-003**: R1（总量未知）与 R2（AI 初筛后才知总量）两端轮询都生效，不预先弹提示、不事后重抓兜底。
- **SC-004**: 撞墙（验证码/限流/硬阻断）自动顺次切下一个预选账号，剩余份额接力不丢，全程不靠用户手动盯。
- **SC-005**: 撞墙换号复用 B057 现有逻辑，取号范围限定到用户预选池（不重写换号机制）。
- **SC-006**: 所有预选账号撞墙走现有"暂停"，账号列表项标红 + "限流"方框，不新增报错 UI/字段/文案体系。
- **SC-007**: 用户登录账号默认全进池、新增自动加入、默认全选、带默认配额（R1 25 / R2 100），开抓即轮询，零配置可用。
- **SC-008**: 全取消所有账号勾选时阻止开抓（至少 1 个选中）。
- **SC-009**: BOSS + 智联两平台都支持轮询分摊 + 撞墙换号 + 默认配置。
- **SC-010**: 旧配置/旧任务不兼容，全删，新 schema 直接上，无迁移残留。
- **SC-011**: 聚焦测试 + 后端全量测试 + 前端测试 + `npm run build` + 仓库卫生检查全部通过。

## Verification Scope

- 功能交付：聚焦测试（轮询分摊逻辑、撞墙换号顺次接力、全撞完暂停 + 限流视觉标识、默认配置生效、全取消阻止开抓、两平台通吃）+ 后端全量测试 + 前端测试 + `npm run build` + 仓库卫生检查。
- 用户端到端真跑验证在交付后进行：①多账号多选开抓，R1/R2 轮询分摊，每账号只抓配额就换；②总量超配额自动多轮覆盖；③撞墙自动顺次换号、剩余份额接力；④全撞完暂停 + 账号标红限流方框；⑤登录账号默认全进池全选带默认配额；⑥新增账号自动进池；⑦全取消阻止开抓；⑧BOSS 与智联两平台都验证。

## Assumptions

- **A1（串行执行）**: B091 只做串行抓取（一次一个账号实例），不做并行多实例；提速从来不是这条需求的目标。
- **A2（两层并行）**: 主动分摊（轮询）为主 + 撞墙顺次换预选账号兜底，两层并行不悖；分摊只降低撞墙概率不消除，撞墙换号在分摊架构里依然必须保留。
- **A3（共用账号池）**: R1、R2 共用一个账号池（不分各自独立池）；分两套独立池是第二版的事，第一版不做。
- **A4（每轮配额 vs 总配额）**: 配额是"每轮每账号"的配额，账号可多轮（如 1 号两轮），每轮每账号都不超其配额，符合降风控初衷；轮询消解"量不够"——自动多轮覆盖任意总量。
- **A5（R1 按页、R2 按条）**: R1 按页轮询（列表翻页本质）、R2 按 JD 条数轮询；两角色口径不同是客观现实（R1 总量未知、R2 总量 AI 初筛后才定），强行统一口径是错的。
- **A6（每页条数平台内部用）**: BOSS 每页 30 条、智联每页 20 条，系统内部用，用户不感知；配额范围两平台一致。
- **A7（撞墙换号复用 B057）**: 撞墙换号不重写，复用 B057 现有逻辑，只把取号范围从"系统全池自动挑"限定为"用户预选池顺次切"。
- **A8（全撞完走暂停）**: 所有预选账号撞墙走现有"暂停"状态，不新增报错 UI/字段/文案；撞墙账号唯一视觉标识是账号列表项字体变红 + 后缀"限流"方框。
- **A9（默认零配置）**: 登录账号默认全进池、新增自动加入、默认全选、带默认配额（R1 25 / R2 100，取范围中值）；要调才手动改。
- **A10（至少 1 账号选中）**: 全取消所有账号勾选时校验阻止开抓（质询未明确敲，按合理默认补）。
- **A11（通用平台）**: B091 为通用功能，BOSS + 智联都做；原 BACKLOG 标题"BOSS 任务"为误写，需同步修正。
- **A12（不兼容旧配置）**: 旧账号配置（角色→单账号互斥）与旧任务不兼容，全删，新 schema 直接上，不做迁移。
- **A13（与 B057 关系）**: B057 的"撞墙换号"在 B091 下保留为兜底，不撤；B091 的增量是"主动轮询分摊"+"换号来源限定到用户预选池顺次"。
