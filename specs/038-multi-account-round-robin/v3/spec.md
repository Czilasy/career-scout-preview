# Feature Specification: 多账号轮询弹窗信息架构与限流标记清除（B091 V3）

**Feature Branch**: `038-multi-account-round-robin`

**Spec Version**: `v3`

**Supersedes**: `v2`

**Status**: 已实施，待正式账号端到端验收

**Input**: 用户选定“弹窗紧凑清单”方向，并明确要求保留当前账号弹窗的说明与全部小内容；后续确认弹窗宽度增加 100px、账号池表头固定对齐、平台打开操作仅保留图标、R1/R2 配额上下排列。

## 用户目标

用户仍在现有深色账号弹窗中管理浏览器和账号，而不是进入一个新的完整页面。弹窗顶部保留完整的账号说明，紧接着保留“抓取浏览器 / 自动探测”抽屉入口；账号池在下方以紧凑清单呈现。用户能继续看到并操作参与轮询、R1/R2 配额、每个平台的登录状态与打开入口、当前账号、删除、添加账号、运行占用提示和反馈提示。

当账号显示红色“限流”标记时，用户可把鼠标放到该标记上（或用键盘聚焦），看到一个小叉号。点击叉号只清除该账号的限流标记，不删除账号、不退出登录、不修改浏览器资料、不改变参与轮询或配额。

## 用户故事

### US1 — 在原有弹窗中快速扫读账号池（P1）

用户打开“账号”弹窗，仍先读到既有说明文字和抓取浏览器选择。随后以紧凑清单扫读每个账号的身份、是否参与轮询、R1/R2 配额、平台状态和操作，不必在大量等权的卡片行中来回找信息。

**验收场景**：

1. 打开弹窗时，标题、既有完整说明文字、关闭按钮、抓取浏览器抽屉、账号池、添加账号区都存在。
2. 抓取浏览器抽屉收起时显示“自动探测”或当前选择与“重新探测”入口；展开后仍能使用现有浏览器选择、手动路径、当前生效路径和保存行为。
3. 每个账号仍显示名称、当前/非当前状态、参与轮询、上下排列的 R1/R2 输入、实际可用平台的状态与图标打开按钮；默认账号仍不可删除，其他账号仍可设为当前或删除。
4. 运行占用、空账号、加载与本地成功/失败提示的原有行为不丢失。

### US2 — 手动清除限流视觉标记（P1）

用户看到“限流”标记后，不必删除账号或等下一次任务自愈；可以明确地仅清掉这条人工可撤销的视觉状态。

**验收场景**：

1. `rate_limited=true` 的账号仍保持红色名称/卡片及“限流”标记。
2. 限流标记内的清除按钮平时不可见，悬停标记或键盘聚焦时显示，且具备“清除限流标记”的可访问名称。
3. 点击清除按钮后，前端调用专用删除接口，成功后重新读取账号列表，红色标记消失。
4. 清除后账号 ID、名称、浏览器资料、登录状态、参与轮询和 R1/R2 配额保持不变。
5. 接口失败时保留红色标记，并展示已有的本地错误提示。

## 功能需求

- **FR-001**: MUST 在既有 `BaseDialog` 账号弹窗内实现，不新增独立页面、侧栏或新的账号管理入口。
- **FR-002**: MUST 保留 v2 已有的账号说明、浏览器选择、运行锁定、账号操作、账号池设置、平台状态、添加和删除确认能力。
- **FR-003**: MUST 将账号行按“账号 / 轮询与配额 / 平台 / 操作”的紧凑信息层级重排，表头固定并与下方账号行共用列网格；R1/R2 配额上下排列，平台打开操作只显示图标，并在窄宽度下保持可读与可操作。
- **FR-004**: MUST 保持抓取浏览器为弹窗内的可展开抽屉；重新加载注册表信息不得改变当前选择。
- **FR-005**: MUST 让限流清除按钮仅在标记悬停或焦点进入时可见，且按钮的可访问名称为“清除限流标记”。
- **FR-006**: MUST 提供 `DELETE /api/browser-accounts/<account_id>/rate-limited`；成功时只持久化该账号的 `rate_limited=false`，账号不存在返回 404。
- **FR-007**: MUST NOT 改变 R1/R2 轮询、账号切换/CDP、白箱、登录缓存或灵动岛的业务语义。

## 非功能与边界

- 复用项目深色主题令牌，不引入单独的页面主题或外部字体。
- 清除按钮支持鼠标、键盘焦点和屏幕阅读器；减少动态偏好下不依赖动画传达可用性。
- 后端路由逻辑放入独立账号限流路由模块；`settings_api.py` 仅注册该模块，避免突破 600 行预警线。
- 此版本不验证真实抓取轮询；用户后续单独测试前四项。

## 成功标准

- 组件测试证明现有关键内容仍在，且清除限流标记调用正确接口并刷新为无标记状态。
- HTTP 测试证明清除操作仅修改 `rate_limited`，并处理不存在账号。
- 聚焦后端与前端测试、全量后端测试、前端测试、前端构建和仓库卫生检查均通过；真实浏览器端到端验收由用户按现有正式环境执行。
