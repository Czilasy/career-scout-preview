# Contract: 领域筛选

**关联**：[spec.md](../spec.md)、[plan.md](../plan.md)。本契约定义内部调用与用户可观察行为，不添加外部 API、选择控件或结果字段。

## C1：条件来源与身份

上下文服务接受当前上下文、来源 run、实际筛选条件与平台。通过 `resolve_flow_binding` 的公开返回和 `TaskStore.get_flow(..., profile_id=...)` 定位该 run 的准确 Track，不以最新 Flow 或第一个 Track 兜底。

按 data-model 的优先级保留统一原始组、实际覆盖或旧格式平台标签。显式清空产生无领域选择。快照结构损坏、身份冲突、未知平台注册值经既有错误链反馈，不改成不限。内部输出仅传入粗精筛，不改变外部筛选参数。

## C2：硬条件

`job_hard_mismatch` 的原有签名、返回形状和非行业规则保留。行业码不相交或缺失不再直接给出 mismatch；领域条件仍送给语义判断。薪资、经验、学历、规模、阶段、公司性质、活跃条件等按照对应平台和既有规则处理，不因为领域相关跳过。

## C3：粗筛和精筛输入

- 粗筛：领域信息不足保留后续判断机会；不能以行业码、职位为销售/行政等或缺少关键词提前排除。其他明确冲突照常处理。
- 精筛：领域生效时完整可用 JD 和适配后的已有公司/业务事实到达现有模型调用；不能只发标题与分类，也不能固定只发前 1500 字。
- 共同口径：工作、产品或实际主营业务相关；主营明确相关时通用职能相关；工具要求/宣传偶然提词不是充分证据；组内任何业务和多选任何领域相关即可。
- 原有求职画像明确约束继续生效。没有画像、没有 JD、事实不足或模型失败保持原契约；不新造确定结果。
- 平台事实归一化由 ai_platform_adapter 提供；通用 policy 不含平台名、编码或专属字段。无领域选择时保持旧输入路径与截断行为。

提示词组装必须复用一套领域约束。粗筛文本迁到已有组装模块时保留无选择、非行业和错误解析行为，不能借此修改整个筛选协议。

## C4：判定恢复

内部 policy 定义统一版本与语义摘要。`find_resumable_screen_run` 保持既有外部调用兼容：领域生效时在返回候选前检查当前版本、准确领域语义与身份；候选查找仅使用公开 store 读取和 policy 纯函数重建预期选择，不反向依赖会调用 screen_flow 的 context 服务。不同语义的候选被跳过，允许既有入口正常新建筛选，不先返回旧候选再让 runner 反复失败。runner 在启动阶段再次验证兼容。

`load_resume_verdicts_with_fallback` 在读取自身判定并提前返回之前检查兼容；同源回退也逐条检查版本和语义。可增加仅内部使用的可选上下文参数，旧调用不得偷偷复用旧领域规则结论。调用方传完整派生上下文；缺少该信息时领域旧判定不能被默认为可复用。

新建筛选保留元数据直到后续暂停、续跑，不被 runner 的 create_screening_run 参数组装遗漏。显式续跑不兼容旧领域 run，在元数据覆盖、checkpoint 读取和 AI 阶段推进前阻断并留下现有失败信息；不把清空判定但保留 checkpoint 当作重判。兼容的同版本恢复与无领域选择仍按原路径处理。

已完成历史结果不改写。判定复用需要规则兼容，JD 资料复用不需要；两条通道不能共用 resume_from_run_id 作为开关。

### C4a：JD 资料独立复用

领域新建筛选即使 resume_from_run_id 为空，也通过 context 服务调用无 statuses 的 latest_screen_runs_for_source 和 load_resume_jd(..., include_dropped=True)，读取同抓取来源、同平台、同画像归属、当前岗位 ID 集合内的资料。资料模式合并文件与结果表，底层 load_screening_jd_map 的 include_dropped=True 读取指定 run 所有有效 JD，不能沿用 is_dropped=0 条件；默认 False 保持旧调用行为。过滤活跃/身份不一致记录，按 data-model 优先级补缺；规则版本、行业条件或画像摘要不同不排除客观资料。读取只读、保留来源标识，不删除旧 JD 文件，不载入旧粗精筛 checkpoint 或 verdict。无领域选择维持原恢复路径。

runner 在 run_jd_stage 前传入这些资料；ai_screen_jd 在浏览器准备前计算缺项，全部有 JD 时不执行该阶段浏览器/CDP/抓取，部分缺失只请求缺失岗位，完整原文到精筛。其余身份、来源完整性、暂停/风控规则不变。

必须验证：旧 dropped 判定不复用，但有效 JD 到达新模型；恢复 ID 为空、检查点文件缺失或只有部分数据时，仍从结果表取 is_dropped=1 行的有效 JD（实际临时 TaskStore 验证，而非只让假件返回预期数据）；多个历史运行互补；同 ID 不同平台/画像/来源不复用；当前/较新资料优先；损坏资料可观察失败；缓存齐全无详情调用，部分缓存只抓缺项。

### C4b：兼容失败可观察契约

共享 error_registry 登记 `screening_policy_incompatible`，说明语义为旧判断口径变化、需从现有筛选入口重新判断、已抓资料保留；不固定新 UI 文案，不新建状态或按钮。不归为外部账号/风控错误，不自动重试原判定。

context 内部类型化异常仅带登记分类和安全诊断；runner 在当前版本元数据覆盖和粗精筛 checkpoint 使用前、且失败补偿上下文已初始化时单独捕获，调用 ai_screen_failure.persist_ai_worker_failure 以既有 failed 收口。ai_screen_failure 和 flow_task_state 白名单保留该码，由 error_registry 派生安全说明，避免 close_flow_task_state 映射为 internal_error。不调用 flow_service.public_flow_message 的未知码回退，不修改该 694 行文件。

对外仍使用 run.error_reason、task.error、Track.reason、error_code；重新读取既有 Flow/task 接口及刷新后须看到同一说明。补偿失败沿 FlowStateClosureError，不吞错。已有任务身份/状态图/进度不变。验收检查对外内容及旧 JD/结果未删，再用现有筛选入口建立新 run 验证重判与资料复用。

### C3a：事实输入的完整链路

事实边界以 data-model 来源表为准。测试从列表型 source_result.jobs 和详情 jd/旧 JD 资料进入真实 runner/JD/精筛函数，在模型网络边界用桩捕获输入；不得直接给 match_jds 塞独立公司主营字段代替传递验证。分类相反、完整 JD 后文明确主营相关的通用职能正例，应把列表公司背景与原文一起送到模型。工具/宣传提词反例不得补造主营证据。

## C5：结果与验收映射

| 需求 | 用户可观察契约 | 自动化重点 | 真实验收 |
| --- | --- | --- | --- |
| FR-001 / FR-002 | 分类不同的相关工作进入匹配结果 | 前置过滤、粗精筛调用及事实完整性 | 销售、运营、交付、技术支持相关正例 |
| FR-003 | 主营明确相关公司的通用职能满足领域 | 公司事实传入且不以标题排除 | 行政、人事、财务正例 |
| FR-004 | 工具与宣传提词不能独自使领域成立 | 提示约束和反例契约 | 两类真实反例 |
| FR-005 | 任一所选领域相关即可 | 并集组装、不要求交集 | 只相关第一个/第二个领域各一类 |
| FR-006 | 其他明确条件冲突仍按原规则处理 | 硬条件、画像及无选择回归 | 同相关岗位的条件对照 |
| FR-007 | 整组选项保留原含义，软件也可满足互联网组 | 原始快照、覆盖与平台别名 | 软件业务正例、不同组相同平台码对照 |

结果格式、解释字段与现有页面展示保持。假模型只能检验传递和解析，真实语义判断必须在现有产品入口检查结果内容。
