# Quickstart: B094 验证指南

以下步骤仅供后续获准实施时执行。本轮止于 Tasks，未运行测试、构建、服务、真实账号或模型调用。

## 1. 前置条件与范围

读取本版本 spec、plan、contracts 与 tasks；确认当前主题分支与未提交改动，没有其他工作混入。复核允许文件尺寸；超预警文件新职责必须分流，超红线不得添加逻辑。

自动化使用明确标记的构造岗位、假模型和临时数据库；共用 `tests/ai/harness.py` 与已有 fixture，不复制整段假件。目标是证明条件传递、事实可达、解析和恢复契约，不能称为真实 AI 验收。

真实 E2E 必须使用项目正式启动方式、用户已就绪的配置、账号、画像与真实岗位；只经 Career Scout 对外入口操作。先定义允许写入为本次正常筛选产生的新 run 和结果，不改写已完成历史、不直接操作外部招聘系统。缺少真实正反例、账号、画像或模型配置时，记录缺项并将对应验收标为未验证，不能造样本冒充。

## 2. 开发聚焦检查

新增测试文件完成后，在仓库根目录运行：

```powershell
uv run python -m unittest tests.ai.test_ai_domain_context tests.ai.test_ai_domain_recall tests.ai.test_ai_platform_filters tests.test_ai_prompts tests.test_screen_flow tests.test_error_registry tests.test_b096_production_flow
```

先观察对应新行为失败，再实现并聚焦重跑；若既有完整模块包含超出本次改动的用例，可进一步指定失败测试名。直接相邻自动化流程回归：

```powershell
uv run python -m unittest tests.test_b096_production_flow
```

后者用测试假件和临时数据库，只算流程自动化回归。所有重定向日志只写 `$env:TEMP`，当轮清理自产中转文件，保留必要失败清单供定位。禁止每次修改运行全量。

必须包含：旧规则不兼容但 resume_from_run_id 为空时旧 JD 实际复用（含文件缺失/部分文件与结果表互补，实际临时 TaskStore 中已剔除行的有效 JD 可读且默认旧模式不变）、缓存齐全详情阶段零 CDP/抓取、部分缓存只抓缺项、多候选互补及身份隔离、损坏资料可观察失败；真实 runner/JD/精筛函数到模型桩输入的完整传递；错误分类和安全说明经失败入口到对外 run/task/Track 字段并在刷新后保留；行业码不同仍到达语义判断、主营事实和完整 JD 后文到达模型、组选项软件业务、多领域并集、工具反例、其他条件、V2 覆盖/清空、同码不同组、旧缓存自身提前返回和同源回退、不兼容显式续跑阻断、兼容恢复与无领域选择。公司主营正例必须由已获取完整 JD 原文支持，不能直接给模型入口填入生产链路不存在的公司主营字段。

## 3. 真实进程和环境

按 README 使用 `tools/start.bat` 或 `python webui/app.py` 的项目正式入口，访问 `http://127.0.0.1:5000`。后端变更后重启受影响服务并验证页面与 API 可访问；不使用临时替代服务冒充正式链路。前端构建就绪按项目启动提示处理。

查询正式数据前运行 `uv run python scripts/db_info.py`，确认 env=live 与目标库；正式库为用户目录 `~/.career-scout/webui/webui.db`，不将仓库 `.webui-state` 当正式库。验证只读取既有岗位事实，运行写入仅来自用户界面的正常筛选。

## 4. 用户可见场景

通过现有条件入口选择行业组选项，再进入本次筛选结果查看岗位、判定和解释。其他条件及画像必须满足正例，否则不能把其他条件剔除误判为 B094 失败。

| 场景 | 真实输入前提 | 结果证据 | 覆盖 |
| --- | --- | --- | --- |
| 工作/产品相关 | 行业分类不同，实际销售 AI 产品；另覆盖运营、交付、技术支持 | 匹配结果可见，解释依据实际工作/产品 | SC-001 |
| 通用职能 | 已获得信息明确公司主营相关，行政/人事/财务 | 满足其他条件时岗位可见 | SC-001 |
| 偶然提词 | 工作、产品、主营无关联，仅工具要求或宣传提词 | 不能只以该词判相关 | SC-002 |
| 多选并集 | 同选互联网组和游戏组，分别只有一个领域相关 | 两类岗位均可进入结果 | SC-003 |
| 其他条件 | 同领域相关岗位，其他条件满足/明确冲突对照 | 冲突仍依原规则排除，满足时可见 | SC-004 |
| 整组理解 | 选择互联网/AI/软件/IT服务，软件业务与 AI 无关 | 软件业务仍能满足整组 | SC-005 |
| 原始组与覆盖 | 不同原始组可能映射相同平台编码；存在真实组含义对照 | 不扩大或收窄原始选择；覆盖/清空符合实际选择 | SC-003 / SC-005 |
| 恢复 | 当前规则暂停恢复、旧领域记录不兼容、无领域选择恢复 | 具体说明规则变化/重新判断/资料保留；新 run 复用旧 JD 重判，历史未变 | SC-001 / SC-004 / SC-005 |

旧规则恢复场景须在正常项目入口观察失败说明，并重新读取现有任务/Flow 信息验证刷新后内容一致；随后从既有筛选入口新建同源筛选，在控制的自动化资料测试中证明有效缓存岗位无详情请求，在真实 E2E 中观察已获取原文仍支撑新结果。真实环境缺少可用旧记录时将此场景列未验证，不能造正式历史补齐。

保存 run 标识、来源、平台、选择、已有事实依据及结果可见证据。不得把完整个人资料、凭据或正式岗位正文写进公开测试/规格；验收证据留在允许的本地位置并脱敏。真实样本不足时列出未测场景。

```powershell

```

git status --short --branch
