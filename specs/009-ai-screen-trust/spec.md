# 功能规格：AI 精筛靠谱化（B033）

**功能目录**：`009-ai-screen-trust`

**创建日期**：2026-08-11

**状态**：已冻结（2026-08-11，边界来自 grill-me 质询已确认结论）

**输入**：BACKLOG B033（精筛/求助画像提示词增强）+ 用户 8 轮 grill-me 质询确认的画像双层结构、精筛三通道、靠谱判定与展示方案。本 Spec 只记录需求和验收，不涉及实现代码。

**需求动机（实测数据）**：最新一轮 BOSS 抓取 759 岗位中，匹配 199 条含 60+ 销售/客服/标注/文员岗（"注塑生产跟单文员""五金冲压pmc计划专员"等被 match），骗局话术岗位（"无责底薪6800""一单1万起"）零提醒；flags 靠谱判断输出为 0；精筛模型对硬性条件写"候选人未知"（画像缺学历/薪资/城市）。初筛 216 条剔除 reason 全部规范，判定逻辑不动。

## 用户故事 1 - 画像双层：画像事实（隐藏）+ 求职画像（用户可编辑，最高优先级）

AI 分析简历时一次产出三层数据：筛选条件（现有）、画像事实（新增，隐藏）、求职画像（现有 profile_summary 语义升级，3-5 句，用户可见可编辑）。精筛判断时求职画像优先于画像事实；求职画像未提及的维度用画像事实兜底。

**优先原因**：精筛完全基于画像判断，但现有画像文本缺学历/薪资/城市且含空洞评价，模型硬性判断靠猜（实测"候选人未知"）；用户想扩展方向（"AI 相关行业都可以"）时画像又锁死方向。双层结构让"简历事实"与"用户意愿"分离，各自承担职责。

**独立测试**：构造含/不含学历、薪资、项目的简历文本，验证画像事实字段提取、缺失标"未体现"、宽松验证丢弃无效项；编辑求职画像后画像事实不重生成。

**验收场景**：

1. **假如** 用户上传简历并进入确认筛选条件页，**当** AI 分析完成，**那么** 同时生成筛选条件、画像事实、求职画像三份数据；画像事实完全隐藏，界面只展示筛选条件与求职画像。
2. **假如** AI 生成的求职画像不足 3 句或超过 5 句，**当** 展示给用户，**那么** 生成规则要求 3-5 句；用户可编辑，字数校验沿用现有规则（B032 最小字数校验）。
3. **假如** 用户编辑求职画像（如改为"AI 相关行业都可以，包括教学、运营"），**当** 保存确认，**那么** 只更新求职画像，画像事实保持简历提取值不变，不触发重新分析。
4. **假如** 简历未体现学历或语言能力，**当** 提取画像事实，**那么** 对应字段输出"未体现"，禁止推断补全或编造。
5. **假如** AI 输出画像事实含无效项（类型错误、空字符串），**当** 校验，**那么** 无效项丢弃不阻塞整体；job_type 限定"全职/实习/兼职/未体现"四值。
6. **假如** 求职画像与画像事实冲突（如画像事实技能是 Python，求职画像写"教别人用 AI 都可以"），**当** 精筛判断，**那么** 以求职画像为准；求职画像未提及的维度（如学历）以画像事实为准。

## 用户故事 2 - 精筛三通道：筛选条件 + 画像事实 + 求职画像

精筛（match_jds）输入从"仅求职画像文本"扩展为三通道：筛选条件（学历/经验/薪资/城市，转自然语言）、画像事实（技能/项目/求职类型/语言）、求职画像。硬性条件以基线与筛选条件为准，"未体现"不得推断；方向契合度以求职画像为准。

**优先原因**：现有精筛只收 profile_summary 文本，结构化筛选条件（库里已有）不传给精筛模型，导致 JD 硬性条件判断无基线（实测"供应链专员硬性条件仅为本科及年龄，候选人未知"）。

**独立测试**：构造含硬性学历/年限/语言要求与软性要求的 JD 集，验证"未体现不得推断"、意愿扩展方向不因基线未命中排除、硬性不满足仍 not_match。

**验收场景**：

1. **假如** 岗位 JD 含硬性要求（"必须本科""3 年以上""英语六级"），**当** 精筛判断，**那么** 对照筛选条件与画像事实判断；画像事实标"未体现"的维度不得推断为满足或违反。
2. **假如** 求职画像明确扩展方向（"AI 相关行业都可以"），**当** 精筛判断非开发类岗位（教学/运营），**那么** 不因画像事实技能未命中而排除，差异写入 caveats。
3. **假如** 求职画像未提及某维度（如行业），**当** 精筛判断，**那么** 回退用画像事实与筛选条件判断。
4. **假如** 岗位为注塑跟单/PMC/文案类且求职画像未放宽方向，**当** 精筛判断，**那么** 无画像事实可迁移依据时判 not_match，不再出现"技术岗可迁移"类空想理由。

## 用户故事 3 - 靠谱判定：结构化 flags 与高危强制不匹配

精筛并行输出岗位靠谱判定：按 20 条特征清单（A 中介包装 / B 销售话术 / C 收费培训 / D 薪资雇佣关系 / E 信息矛盾 / F 异常行为）核对，输出结构化 flags `[{code, level: high|medium, reason}]`（必填字段，可空数组）。高危命中 ≥1 或 中危命中 ≥2 → 输出 flags；中危仅 1 条 → 并入 caveats。高危 → 强制 not_match，reason 写"疑似骗局：<命中特征>"。特征清单配置化为常量表，后续加特征不改 prompt 结构。"岗位常年挂着"特征不纳入（依赖在线巡检 B005，另立 Spec）。

**优先原因**：现有 flags 为可选字段 + 命中 2 条阈值，实测 759 岗位 0 输出；方向四定位"靠谱筛选"，骗局岗位必须在匹配列表外。

**独立测试**：构造骗局话术标题（无责底薪/月入XX万/一单XX起）、培训机构招聘、劳务公司包装、标题与 JD 不符、薪资单位异常等样本，验证 flags 输出、高危强制 not_match、中危只标记。

**验收场景**：

1. **假如** 岗位命中高危特征（培训收费、标题与 JD 不符、门槛极低薪资极高、JD 留个人联系方式、薪资单位异常），**当** 精筛，**那么** 命中 1 条即输出 flags（level=high），岗位强制 not_match，reason 以"疑似骗局："开头并引用命中证据。
2. **假如** 岗位命中中危特征（销售话术标题、薪资含提成、劳务派遣、试用期模糊、高薪面议、小公司大角色等），**当** 精筛，**那么** 命中 ≥2 条输出 flags（level=medium），只标记不改 match 判定；仅命中 1 条并入 caveats。
3. **假如** 岗位无任何可疑特征，**当** 精筛，**那么** 输出 flags 空数组，不得省略该字段。
4. **假如** 命中特征需要 JD 时间维度的信息（岗位挂多久），**当** 精筛，**那么** 不判断该特征（不在清单内）。
5. **假如** 新增一条骗局特征，**当** 维护特征清单，**那么** 只改配置常量表，不改精筛 prompt 结构与输出契约。

## 用户故事 4 - 结果页展示：详情高危红字提醒与岗位条预警标记

高危岗位在详情页"AI 判断说明"盒子内显示红色 ⚠ 与红色正文（盒子背景/边框不变），不新增盒子与子块；中危提醒在"软性要求提醒"盒子内与 caveats 并列（黄色系）；岗位列表条在标题前显示 ⚠ 标记（高危红、中危黄）。

**优先原因**：详情页两个盒子（AI 判断说明、软性要求提醒）已能承载提醒；岗位条现有信息单薄，需要一眼可见的骗局预警。

**独立测试**：构造含/不含 flags 的岗位数据，验证详情页红/黄渲染、盒子背景不变、岗位条 ⚠ 标记、历史轮无 flags 不显示。

**验收场景**：

1. **假如** 岗位 flags 含 level=high，**当** 查看详情，**那么** "AI 判断说明"盒子标题与正文文字标红，reason 前显示红色 ⚠ 图标（图标由前端渲染，AI 不输出符号）；盒子背景与边框不变，不新增子块或列表。
2. **假如** 岗位 flags 含 level=medium，**当** 查看详情，**那么** 提醒显示在"软性要求提醒"盒子内，与 caveats 并列，样式为黄色系。
3. **假如** 岗位 flags 含 level=high，**当** 查看岗位列表条，**那么** 标题前显示红色 ⚠；level=medium 显示黄色 ⚠；无 flags 不显示。
4. **假如** 历史轮次岗位数据无 flags，**当** 查看详情与列表，**那么** 不显示任何 ⚠ 标记，其余展示与现有行为一致。

## 用户故事 5 - 初筛输入增加求职画像放宽（初筛逻辑不动）

初筛（screen_jobs）判定逻辑不变，输入从"筛选条件"扩展为"筛选条件 + 求职画像全文"：求职画像中明确放宽的维度（"XX 也可以""不限""接受"）以求职画像为准放宽对应判断；未涉及的维度仍按筛选条件判断。

**优先原因**：用户扩展方向后，初筛若仍按筛选条件硬剔（如城市≠东莞就剔），放宽意愿在精筛前就被误杀，data 放宽失去意义。

**独立测试**：构造求职画像含"东莞、深圳都可以"与不含放宽表述两组，验证初筛剔除差异符合预期。

**验收场景**：

1. **假如** 求职画像含明确放宽表述（"东莞、深圳都可以"），**当** 初筛判断城市维度，**那么** 深圳岗位不被按城市剔除。
2. **假如** 求职画像未提及某维度，**当** 初筛判断该维度，**那么** 仍按筛选条件剔除（如学历高于候选人、经验下界高于候选人上界）。
3. **假如** 初筛判断非硬性维度，**当** 岗位名称或类别可疑，**那么** 行为与现状一致：不得仅凭岗位类别剔除，只剔除明显硬性不符。

## 用户故事 6 - 数据落库与兼容（老轮退化，补筛复用）

screening_runs 新增 profile_facts_json 列（画像事实）；profile_summary 列复用承载求职画像（零迁移）；screening_results 新增 flags_json 列（结构化 flags）。老轮次画像事实为 NULL → 精筛退化为两通道（筛选条件 + 求职画像），行为与现状一致；B038 补筛复用该轮快照画像，不重新分析简历。

**优先原因**：需求涉及存储结构扩展，兼容策略必须明确，避免历史轮次与补筛路径破坏。

**独立测试**：构造老轮次（无画像事实/无 flags）与新轮次数据，验证查看、补筛、回写合并行为。

**验收场景**：

1. **假如** 老轮次无画像事实（profile_facts_json 为 NULL），**当** 查看或补筛该轮，**那么** 精筛输入退化为筛选条件 + 求职画像，行为与现有版本一致，无迁移、无报错。
2. **假如** 新轮次保存，**当** 检查落库，**那么** 画像事实写入 profile_facts_json、求职画像写入 profile_summary、flags 写入 flags_json。
3. **假如** 对历史轮发起补筛（B038），**当** 补筛执行，**那么** 复用该轮快照画像（含画像事实，若为空则退化），不重新分析简历、不新建轮次。
4. **假如** 前端收到后端回写的岗位数据，**当** 合并到结果，**那么** flags 与 caveats 走同一合并路径，JobItem 类型含 flags 字段。

## 明确不做（边界）

- 不新增"人工修正画像事实"功能（画像事实隐藏，提取错误靠求职画像兜底）
- 不做"岗位常年挂着"特征判断（依赖 B005 在线巡检，另立 Spec）
- 不改初筛判定逻辑（仅扩展输入）
- 不做画像实体复用/版本管理（保持每轮快照模式）
- 不改 flags 的中危颜色为红色系（红色只属于高危）
- 批量参数（match_batch_size 等）默认值回调作为独立优化项，不在本 Spec 验收内

## 验收汇总（进入实施后逐项勾选）

- [ ] 画像事实随简历分析生成并隐藏落库，缺失标"未体现"
- [ ] 求职画像 3-5 句可编辑，编辑不触发画像事实重生成
- [ ] 精筛三通道输入生效，"未体现不得推断"、意愿优先规则生效
- [ ] flags 结构化输出（必填字段），高危强制 not_match，中危只标记
- [ ] 详情页高危红字 ⚠（盒子背景不变）、中危黄进软性盒子
- [ ] 岗位条 ⚠ 标记（红/黄）
- [ ] 初筛输入含求职画像放宽，逻辑不变
- [ ] 老轮退化两通道、B038 补筛复用快照，无迁移无报错
