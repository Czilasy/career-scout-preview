# 功能规格：P1 完成度与界面可信度整修

**功能目录**：`006-p1-completion`

**创建日期**：2026-08-09

**状态**：Spec/Plan/Tasks 已执行完成；验收证据见 tasks.md T021-T023

**输入**：用户要求把 BACKLOG 的 P1 全部完成，做成一个大 Spec 并一次性生成到 Tasks。范围限定为 B011、B012、B016、B017、B020；同时修正 BACKLOG 的 P1 总览数量与实际条目不一致的问题。

## 用户场景与测试

### 用户故事 1 - 进度条只随真实完成事件推进（优先级：P1）

用户执行抓取或筛选任务时，进度条不再靠预估时长、随机停顿或阶段权重“假装在走”。10 组任务按真实组数切分，每一组完成推进一组；组内如果存在真实子事件（页、条），则按真实子事件小步推进；没有真实子事件时，该组完成前保持不动，状态区显示真实信息。

**优先原因**：这是 B011 的核心现象，也是用户信任任务进度的基础；假进度会让用户误判任务实际状态。

**独立测试**：构造 10 组抓取任务，验证第 1 组完成前后、第 2 组完成前后、暂停、完成时的百分比；再构造筛选/重抓任务，验证阶段内按条数真实推进。

**验收场景**：

1. **假如** 用户启动 10 组抓取任务，**当** 浏览器检测/登录检查等准备阶段进行中，**那么** 进度最多显示 1%，不再按预估时长爬升。
2. **假如** 10 组任务第 1 组尚未完成，**当** 用户查看进度条，**那么** 显示值不超过 1% 或该组已确认真实子事件对应值，且不出现时间驱动的增长。
3. **假如** 10 组任务第 1 组完成，**当** 用户查看进度条，**那么** 进入 10%；第 2 组完成前不进入 20%，第 2 组完成后才进入 20%。
4. **假如** 任务暂停，**当** 用户查看进度条，**那么** 百分比定格在暂停时的真实值，不继续增长。
5. **假如** 任务完成，**当** 用户查看进度条，**那么** 显示 100%。
6. **假如** 筛选任务处于初筛、抓 JD、精筛阶段，**当** 用户查看进度条，**那么** 阶段内按真实完成条数推进，阶段之间按已确认权重跳转，不使用时间假爬。
7. **假如** 重抓任务执行中，**当** 用户查看进度条，**那么** 按“重抓 JD 完成条数、AI 重新判定完成条数”真实推进，暂停定格、恢复从真实断点继续。

---

### 用户故事 2 - 任务阶段不泄漏英文原始字段（优先级：P1）

任务运行、轮询、刷新接回、暂停、中断或重抓时，界面任何位置都不得出现 `waiting`、`combo_done`、`recrawl_fetch_jd` 这类原始英文阶段；已知阶段显示中文，未知阶段使用中文兜底或隐藏。

**优先原因**：这是 B012 的核心现象；原始字段泄漏会让用户看到内部实现细节，破坏界面可信度。

**独立测试**：分别模拟运行中、刷新接回、暂停恢复、重抓、未知阶段五类快照，检查界面阶段文字。

**验收场景**：

1. **假如** 任务正在运行，**当** 用户查看任务进度面板，**那么** 阶段文字为中文或为空，不出现原始英文 stage。
2. **假如** 用户刷新页面后接回运行中任务，**当** 任务快照首次显示，**那么** 不出现原始英文 stage，也不闪出内部字段名。
3. **假如** 任务暂停或中断后恢复，**当** 用户查看任务进度面板，**那么** 阶段文字仍为中文。
4. **假如** 后端返回未知阶段，**当** 用户查看任务进度面板，**那么** 显示中文兜底或隐藏阶段文字，不显示原始字段。

---

### 用户故事 3 - 应用内更新失败只显示中文与下一步（优先级：P1）

应用内更新的下载、校验、重启失败时，用户只能看到稳定中文原因和可执行动作，不再看到异常类型、堆栈或 `download_failed: xxx` 这类原始异常文本。

**优先原因**：这是 B016 的核心现象；异常文本会让普通用户无法判断下一步。

**独立测试**：模拟下载失败、SHA256 缺失、SHA256 不匹配、重启脚本启动失败，检查弹窗文案与后端日志。

**验收场景**：

1. **假如** 更新包下载失败（网络中断、磁盘错误、超时等），**当** 用户查看更新弹窗，**那么** 显示中文原因和“重试/手动下载”动作，不出现异常类型、堆栈或原始异常文本。
2. **假如** SHA256 校验文件缺失或校验不匹配，**当** 用户查看更新弹窗，**那么** 显示中文原因和可执行动作。
3. **假如** 重启更新脚本启动失败，**当** 用户查看更新弹窗，**那么** 显示中文原因和手动处理动作，不出现 `OSError` 等异常文本。
4. **假如** 上述任一失败发生，**当** 维护者查看日志，**那么** 原始异常只出现在日志中，不进入用户界面。

---

### 用户故事 4 - AI 设置失败提示可读（优先级：P1）

AI 连接测试和模型列表拉取失败时，用户只能看到可读中文原因，不再看到 `auth_failed`、`network_error` 等裸错误码。

**优先原因**：这是 B017 的核心现象；裸错误码无法帮助用户判断如何修改设置。

**独立测试**：模拟认证失败、网络失败、超时、服务端失败、未知错误，检查 AI 设置弹窗提示。

**验收场景**：

1. **假如** AI 连接测试失败，**当** 用户查看 AI 设置弹窗，**那么** 提示为可读中文，不出现原始 `error_code` 或 `warning_codes`。
2. **假如** 模型列表拉取失败，**当** 用户查看 AI 设置弹窗，**那么** 提示为可读中文，不出现原始错误码。
3. **假如** 后端返回未知错误码，**当** 用户查看 AI 设置弹窗，**那么** 显示纯中文兜底文案，兜底文案不得包含原始错误码。

---

### 用户故事 5 - 桌面版首次运行有完整指引（优先级：P1）

首次下载桌面版的用户，能依据主 README 完成第一次运行：知道需要 Chrome/Edge 和 WebView2，知道首次启动解压会偏慢，知道 macOS 如何绕过 Gatekeeper，知道数据目录在哪里，遇到常见问题知道去哪里排错。

**优先原因**：这是 B020 的核心现象；普通用户只看到 README，不会去看打包手册。

**独立测试**：按 README 桌面版章节逐项核对前置条件、首次启动、Gatekeeper、数据目录、常见排错和版本号一致性。

**验收场景**：

1. **假如** 用户下载 Windows 桌面版，**当** 阅读主 README 桌面版章节，**那么** 能看到 Chrome/Edge、WebView2、首次启动解压延迟、数据目录和常见排错。
2. **假如** 用户下载 macOS 桌面版，**当** 阅读主 README 桌面版章节，**那么** 能看到首次打开被 Gatekeeper 拦截的两种处理方式。
3. **假如** 用户遇到杀软误报、WebView2 缺失或首次启动偏慢，**当** 查阅主 README，**那么** 能找到对应说明。
4. **假如** 用户查看主 README 版本信息，**当** 对照当前版本，**那么** 版本引用一致，不再出现标题与桌面版版本不一致。

### 边界情况

- 组合总数为 0 或未知时，进度显示 0 或隐藏，不编造完成量。
- 单个组合也按真实事件推进：1 组任务在组合完成时到 100%，准备阶段最多 1%。
- 组合失败、等待防限流、风控提示、关闭浏览器等阶段不推进百分比，只展示真实状态文字。
- 任务失败或取消时，进度显示当前真实值或 0，不因终态伪造增长。
- 当前列表抓取若没有逐页/逐条真实完成事件，组内保持不涨是本次交付的已知限制；实现阶段先确认是否存在可低成本复用的回调。
- 暂停时没有有效整体百分比时，定格在当前真实值，不因阶段缺失而回退或增长。
- 未知/缺失阶段不显示原始英文；界面可隐藏阶段文字，但状态消息仍显示真实信息。
- 更新下载中途断网、磁盘满、超时、URL 不合法、校验文件缺失/不匹配、重启脚本启动失败，全部映射为稳定中文。
- AI 连接测试和模型列表的认证、网络、超时、限流、服务端、未知错误全部有中文映射。
- README 版本引用必须与当前实际版本一致；文档不得在桌面版与源码模式之间互相矛盾。

## 需求

### 功能需求

- **FR-001**：任务进度百分比只由真实完成事件推进，包括组合完成、JD 条完成、AI 条完成；搜索中、等待中、组合失败不参与增长。
- **FR-002**：抓取任务按真实组合数均分，10 组任务每组完成推进 10%；准备阶段最多象征性显示 1%。
- **FR-003**：组内优先按真实子事件（页、条）推进；平台不提供真实子事件时，该组完成前保持不涨，状态区显示真实信息。
- **FR-004**：前端显示值只能向真实锚点平滑追赶，任何时刻不得超前于已确认真实完成值。
- **FR-005**：任务暂停时进度定格真实值；任务失败或取消时显示当前真实值或 0；任务完成时显示 100%；未知或缺失进度时不编造增长。
- **FR-006**：筛选任务按“初筛 → 抓 JD → 精筛”的真实完成条数推进，阶段间按已确认权重跳转；重抓任务按“重抓 JD → AI 重新判定”真实推进。
- **FR-007**：任务运行、轮询、刷新接回、暂停、中断、重抓等所有路径下，界面不得出现原始英文阶段；未知阶段使用中文兜底或隐藏。
- **FR-008**：应用内更新下载、校验、重启失败时，用户只看到稳定中文原因与可执行动作；原始异常只写日志。
- **FR-009**：AI 连接测试与模型列表失败时，用户只看到中文原因；原始错误码不进入界面，未知错误也有纯中文兜底，兜底文案不得包含原始错误码。
- **FR-010**：主 README 必须包含桌面版首次运行完整指引，并与当前版本号保持一致。
- **FR-011**：BACKLOG 的 P1 总览数量与实际条目一致；实施完成后条目状态同步更新。
- **FR-012**：上述所有新增状态路径必须具备加载、成功、失败反馈，并在桌面与窄屏下可读可操作。

### 关键实体

- **任务进度状态**：任务的当前阶段、真实完成计数、权威整体百分比与暂停/完成状态。
- **阶段展示标签**：内部阶段到用户可见中文文案的映射，以及未知阶段的兜底行为。
- **更新失败原因**：更新下载/校验/重启的稳定错误码、用户文案与可执行动作。
- **AI 失败原因**：AI 连接测试/模型列表的稳定错误码、用户中文文案与兜底。
- **首启指南**：README 中桌面版首次运行所需的前置条件、正常现象、数据目录与排错入口。

## 成功标准

### 可衡量结果

- **SC-001**：在 10 组抓取样本中，第 1 组完成前显示值不超过 1% 或该组真实子事件对应值，第 2 组完成前不进入 2/10 区间，全程不超前于真实锚点，通过率 100%。
- **SC-002**：暂停样本定格真实值、失败/取消样本显示当前真实值或 0、完成样本到 100%、未知阶段不增长，通过率 100%。
- **SC-003**：运行、刷新接回、暂停、中断、重抓、未知阶段样本中，界面出现原始英文 stage 的次数为 0。
- **SC-004**：更新下载、校验、重启失败样本中，界面出现异常类型、堆栈或原始异常文本的次数为 0；每个失败均有中文原因与动作。
- **SC-005**：AI 测试与模型列表失败样本中，界面出现原始 `error_code`/`warning_codes` 的次数为 0；未知错误均有中文兜底。
- **SC-006**：按首启指引清单核对主 README，Windows/macOS 首次运行所需条目覆盖率为 100%，版本引用一致。

## 假设与依赖

- P1 范围严格限定为 B011、B012、B016、B017、B020；B021（下载页模板）属于 P2，不在本 Spec 范围内。
- 抓取平台当前不提供逐页/逐条真实完成事件时，组内保持不涨是本次交付的已知限制；实现阶段先确认是否存在可低成本复用的回调，不把新增平台抓取能力列为本轮必须项。
- 筛选/重抓阶段权重定为初筛 25%、抓 JD 50%、精筛 25%；验收同时约束阶段内真实条数与阶段间跳转。
- B020 是对现有 README 的补全与一致性修正，不是整篇重写。
- 原始异常只进日志，稳定中文文案不包含异常文本。
- 本 Spec 只覆盖代码、测试与本地文档修改，不覆盖仓库同步动作。

## 范围外

- B021、B005、B006、B010、B014、B018、B022、B023、B024、B025、B026 等其它 BACKLOG 条目。
- 修改抓取策略、AI 算法、更新下载协议或桌面壳/打包配置。
- 进度条视觉动效的重新设计（只改进度语义与追赶行为）。
- 新建下载页模板或执行任何仓库同步动作。
