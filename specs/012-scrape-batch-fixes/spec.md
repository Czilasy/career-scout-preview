## 用户场景与测试

### 用户故事 1 - 详情抓取失败不再被吞、不再误报浏览器失联（B050/B053，优先级：P1）

BOSS 详情并行抓取时，工作线程异常必须透出到主流程并形成批次失败；空批次必须保留真实输出，`source.py` 不得把空批次直接判为调试浏览器失联。请求计数按单次抓取运行隔离，上限 999，命中时返回显式失败码。

**优先原因**：当前线程静默死亡会把空批次伪装成成功返回，编排层再误判为 `source_cdp_unavailable` 并错误暂停；2026-08-11 与 2026-08-14 已造成 123 个岗位缺 JD。

**独立测试**：构造 worker 抛 `RequestLimitExceededError`、`CDPUnavailableError`、普通异常三类场景，验证主流程透出、部分结果保留、退出码与失败码映射；构造连续两轮 in-process 抓取验证计数不跨轮累计。

**验收场景**：

1. **假如** 5 个工作线程全部因请求上限异常死亡，**当** 详情批结束，**那么** 主流程收到该异常并以显式失败码结束，不返回空成功。
2. **假如** 请求计数在列表+详情整轮中累计，**当** 命中 999 上限，**那么** 抛出带显式失败码的异常，进入统一错误码注册表，编排层暂停并保留已抓部分。
3. **假如** 新开一轮抓取，**当** 计数开始，**那么** 从 0 重新计数，不继承上一轮累计值。
4. **假如** worker 因真实 CDP 断线死亡，**当** 主流程收口，**那么** 仍映射 `source_cdp_unavailable`，维持现有自动重启一次语义。
5. **假如** worker 因其他意外异常死亡，**当** 主流程收口，**那么** 按原异常类型透出，最终映射 `source_unknown_error`，不再伪装成 `source_cdp_unavailable`。
6. **假如** 部分岗位已成功抓到 JD 后某 worker 异常，**当** 整批失败收口，**那么** 已抓部分照常写盘保留，未完成部分以失败码暂停。
7. **假如** JD 详情批退出码为 0 且无事件，**当** `source.py` 处理结果，**那么** 不再直接判为 `source_cdp_unavailable`；列表阶段空批次判定保持不变。

### 用户故事 2 - 待确认全部重抓不再被整批拦截（B051，优先级：P1）

前端“全部重抓”发送待确认区所有岗位 ID；后端只校验岗位属于该 source run 的结果快照且无最终判定，并支持“缺 JD 补抓、有 JD 重跑精筛”分流，不得整批拒绝。

**优先原因**：提前结束保存后，已有 JD 但未精筛的岗位不在 `screening_pending_results` 里，整批请求返回 `non_pending_job_ids`，真正缺 JD 的岗位也被一起卡住。

**独立测试**：构造同时含“缺 JD 待确认”和“有 JD 未精筛”的 source run，验证全部重抓可启动、两类岗位分别走补抓与精筛；构造已有最终判定/不在快照的 ID，验证仍返回 `non_pending_job_ids`。

**验收场景**：

1. **假如** 待确认区包含已有 JD 但未精筛的岗位，**当** 点击“全部重抓”，**那么** 请求成功启动，不再整批返回 `non_pending_job_ids`。
2. **假如** 同一批包含缺 JD 与有 JD 的待确认岗位，**当** 重抓任务执行，**那么** 缺 JD 的先补抓、有 JD 的用画像重跑精筛。
3. **假如** 请求包含已有 match/not_match 判定或不属于该 source run 快照的 ID，**当** 后端校验，**那么** 返回 409 `non_pending_job_ids`，任务不启动。
4. **假如** `job_ids` 缺省或为 `"auto"`，**当** 发起重抓，**那么** 维持现有“从待确认集合自动读取”语义。

### 用户故事 3 - 报错/暂停提示统一中文原因 + 红色错误字段内联（B052，优先级：P2）

暂停/失败提示统一为 `中文原因 · 错误字段`，字段跟在中文后面标红内联；不新增单独盒子，不提供复制诊断信息按钮；任何可见错误码都必须带中文前缀，禁止只展示裸字段。

**优先原因**：当前暂停态只显示中文原因，错误码单独放在诊断盒且提供复制按钮，信息层级割裂。

**独立测试**：前端组件测试覆盖暂停/失败两态的内联文案、红色字段、无诊断盒、无复制按钮、无错误码时仅显示中文原因。

**验收场景**：

1. **假如** 任务暂停且带 `error_code`，**当** 查看进度面板，**那么** 显示 `中文原因 · error_code`，错误字段红色内联。
2. **假如** 任务失败且带 `error_code`，**当** 查看进度面板，**那么** 同样显示 `中文原因 · error_code`，错误字段红色内联。
3. **假如** 暂停/失败状态没有错误码，**当** 查看进度面板，**那么** 只显示中文原因，不显示空字段。
4. **假如** 任务暂停/失败，**当** 查看进度面板，**那么** 不存在单独诊断盒，不存在“复制诊断信息”按钮。

## 边界情况

- B050/B053：只修 BOSS `scripts/boss_cdp_raw.py`；智联并行路径不动。
- B050/B053：列表阶段“0 页事件 + 0 结果 → `source_cdp_unavailable`”的现有判定保持不变。
- B050/B053：worker 异常按原类型透出；`CDPUnavailableError` 维持自动重启语义，`RequestLimitExceededError` 不自动重试。
- B050/B053：部分成功结果保留并写盘，未完成岗位以批次失败码进入暂停路径。
- B051：`non_pending_job_ids` 错误码保留，用于“不在快照或已有最终判定”的 ID。
- B052：没有错误码时不显示空字段；不改变后端错误码与 `pause_info` 数据契约。

## 需求

### 功能需求

- **FR-001**：BOSS 详情并行抓取的工作线程异常必须透出到主流程；线程静默死亡不得再被吞掉。
- **FR-002**：工作线程异常导致批次失败时，已成功写入的部分结果必须保留。
- **FR-003**：请求计数按单次抓取运行隔离；新一轮从 0 开始，上限为 999。
- **FR-004**：命中请求上限返回显式失败码 `source_request_limit_exceeded`，并进入统一错误码注册表、前端错误码镜像与系统性阻断集合。
- **FR-005**：`RequestLimitExceededError` 通过 CLI 显式退出码（11）与 in-process 返回码透出；`source.py` 据此分类为 `source_request_limit_exceeded`。
- **FR-006**：`CDPUnavailableError` 仍映射 `source_cdp_unavailable`，维持自动重启一次语义。
- **FR-007**：其他 worker 意外异常按原类型透出，最终分类为 `source_unknown_error`，不得伪装成 `source_cdp_unavailable`。
- **FR-008**：JD 详情批不再以“退出码 0 + 无事件 + 无详情”直接判定 `source_cdp_unavailable`；列表阶段空批次判定不变。
- **FR-009**：`/api/pipeline/recrawl` 接受“属于该 source run 结果快照且无最终判定”的岗位 ID，不要求必须存在于 `screening_pending_results`。
- **FR-010**：重抓任务按 JD 有无分流：缺 JD 补抓，有 JD 用画像重跑 AI 精筛。
- **FR-011**：请求包含不在快照或已有最终判定的 ID 时返回 409 `non_pending_job_ids`，任务不启动。
- **FR-012**：`job_ids` 缺省或 `"auto"` 时维持现有自动读取语义。
- **FR-013**：暂停与失败状态统一内联展示 `中文原因 · 错误字段`，错误字段红色。
- **FR-014**：无错误码时仅显示中文原因，不显示空字段。
- **FR-015**：移除单独诊断盒与“复制诊断信息”按钮。

### 关键实体

- **抓取运行计数**：单次抓取运行（列表+详情整轮或单独详情批）内累计的 API 请求次数，运行结束即废弃。
- **工作线程失败**：并行详情 worker 异常透出后的批次级失败，携带原始异常类型与失败码。
- **重抓目标集合**：source run 结果快照中无最终判定（match/not_match 之外）的岗位，按 JD 有无分为补抓组与精筛组。
- **暂停/失败提示**：由中文原因与错误字段组成的单行内联提示。
