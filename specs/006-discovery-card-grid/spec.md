# Feature Specification: 发现结果页卡片网格化与体验修复

**Feature Directory**：`006-discovery-card-grid`  
**Created**：2026-07-22  
**Status**：Draft — ready for clarification or planning  
**Input**：用户希望将发现流程第 4 步（结果展示）从竖向列表改为卡片网格，清理顶部遗留的死元素和横条，修复刷新丢失结果的问题，并确保感兴趣/不感兴趣标记后的卡片状态可读、可撤销。

## 目标与产品边界

本功能对 `005-fast-resume-discovery` 已交付的发现结果页做前端体验收口：

1. **布局收口**：将竖向单列岗位列表改为自适应卡片网格，每张卡片完整展示岗位名称、薪资条件与 JD 内容，不再截断 JD。
2. **顶部清理**：移除旧流程遗留的死元素（方向选择/分类筛选头部、方向反馈工具条）和「简历驱动发现」横条，将「重新上传」入口归并到顶部操作栏。
3. **刷新恢复**：修复页面刷新后结果丢失的问题，使已完成的发现运行在刷新后自动恢复到结果视图。
4. **标记可读性**：不感兴趣标记后卡片标灰保留（不消失），可撤销恢复；感兴趣标记后按钮状态清晰可辨。

本功能的核心用户承诺是：

> 用户完成发现运行后，结果页以紧凑的卡片网格展示全部岗位及完整 JD，顶部无冗余元素，刷新不丢数据，标记操作有清晰视觉反馈且可撤销。

本功能不改变后端 API、数据模型、发现流程逻辑和 AI 评估能力。所有改动限于前端单文件。

## 与既有规格的关系

- 继承 spec 005 的发现运行、结果交付、渐进展示和反馈桥接能力。
- 本规格仅覆盖结果页的前端布局、顶部元素、刷新恢复和卡片视觉状态；005 的后端端点、数据模型、状态机和合约继续有效。
- 本规格不新增任何后端端点或数据表。
- 感兴趣/不感兴趣的反馈端点（`POST /api/discovery/feedback`）和桥接机制（`_bridge_discovery_feedback_to_legacy`）已在 005 中实现并继续使用，本规格不重复定义。

## 术语与统一语言

### 结果页

发现流程第 4 步的岗位展示区域（`discoveryResultsList`），用户在此浏览 AI 评估后的岗位列表并做感兴趣/不感兴趣决策。

### 卡片网格

将岗位以卡片形式按行排列的展示方式。每行卡片数量根据可用宽度自动调整，不写死列数。

### 死元素

旧流程遗留的 DOM 元素，当前流程已不使用但仍在页面上渲染，导致出现空白区域。包括：方向选择/分类筛选头部（`discoveryResultsHeader`）和方向反馈工具条（`discovery-feedback-tools`）。

### 标灰保留

用户标记「不感兴趣」后，卡片不从列表中移除，而是降低不透明度并加灰度滤镜，同时显示「恢复」按钮允许撤销。

## User Scenarios & Testing

### 场景 1：查看发现结果（主流程）

用户完成发现运行后进入结果页，看到岗位以卡片网格排列。每张卡片顶部显示岗位名称和薪资/城市/经验/学历/规模等条件，中间区域显示完整 JD（可滚动），底部有「感兴趣」和「不感兴趣」按钮。拖动浏览器窗口宽度时，每行卡片数量自动增减。

### 场景 2：从卡片跳转 BOSS 直聘

用户点击卡片中的岗位名称，在新标签页打开该岗位的 BOSS 直聘详情页。点击不影响卡片状态，不触发标记。

### 场景 3：标记感兴趣

用户点击卡片底部「感兴趣」按钮，按钮文字变为「已感兴趣」，该岗位通过已有反馈端点写入持久状态，并出现在筛选工作台的感兴趣区。再次点击可取消。

### 场景 4：标记不感兴趣并恢复

用户点击卡片底部「不感兴趣」按钮，卡片标灰（降低不透明度 + 灰度滤镜）但不消失，底部出现「恢复」按钮。用户点击「恢复」后卡片恢复正常外观，撤销不感兴趣标记。

### 场景 5：刷新页面恢复结果

用户在结果页按 F5 或刷新浏览器，页面重新加载后自动恢复到上一次发现运行的结果视图，卡片网格重新渲染。无需重新上传简历或重新运行发现。

### 场景 6：顶部无冗余

用户在结果页看不到「简历驱动发现」横条、方向选择/分类筛选头部、方向反馈工具条。顶部操作栏只有「重新上传」和「AI 设置」两个按钮以及连接状态。

## Functional Requirements

### FR-001：卡片网格布局

结果页岗位以卡片网格形式展示，每行卡片数量根据可用宽度自动调整。每张卡片仅包含三个区域：

1. **顶部**：岗位名称 + 薪资 + 条件（经验/学历/地点等）。不含公司名。
2. **中间**：完整 JD，高度自适应内容，不设固定 max-height，不做截断。
3. **底部**：感兴趣 / 不感兴趣按钮。

现有卡片中的 badges（匹配类别/分数）、completeness（完整度）、source（原始链接/抓取时间）、sort（排序依据）、explanation（正向依据/差距分析）和 company（公司名）区块**全部删除**，不渲染。

**验收条件**：结果页至少展示 10 条岗位时，桌面宽度下每行不少于 2 张卡片；窄屏下降为单列；JD 完整展示不截断；卡片中不存在 badges/completeness/source/sort/explanation/company 区块。

### FR-002：删除死元素

结果页不再渲染方向选择/分类筛选头部（`discoveryResultsHeader`）和方向反馈工具条（`discovery-feedback-tools`）。这些元素从 DOM 中移除，而非仅隐藏。

**验收条件**：结果页 DOM 中不存在上述元素；页面顶部无空白间隙。

### FR-003：移除横条并重排按钮

「简历驱动发现」横条（含 eyebrow 文案和「上传简历 · 确认方向 · 发现岗位」标题）整体移除。「重新上传」按钮移至顶部操作栏，与「AI 设置」按钮并排。

**验收条件**：结果页不可见横条；「重新上传」按钮位于「AI 设置」按钮左侧；点击「重新上传」可回到上传简历步骤。

### FR-004：刷新恢复结果

页面加载时自动检查是否存在已完成的发现运行，若存在则恢复到结果视图并渲染卡片。恢复依赖 localStorage 中存储的 run_id 和后端持久化的结果数据。

**验收条件**：完成发现运行 → 刷新页面 → 结果页自动恢复并渲染卡片；切换画像后若 run_id 不属于当前画像则不恢复。

### FR-005：岗位名称跳转

点击卡片中的岗位名称，在新标签页打开 BOSS 直聘详情页。仅限 `zhipin.com` 域名。

**验收条件**：点击岗位名称 → 新标签打开 BOSS 直聘；点击不触发标记或其他副作用。

### FR-006：标记后标灰保留

点击「不感兴趣」后，卡片标灰（降低不透明度 + 灰度滤镜）但不从列表移除，底部显示「恢复」按钮。点击「恢复」撤销标记，卡片恢复正常外观。

**验收条件**：标记不感兴趣 → 卡片可见但标灰 → 出现「恢复」按钮 → 点击恢复 → 卡片恢复正常。

### FR-007：感兴趣按钮状态

点击「感兴趣」后，按钮文字变为「已感兴趣」，岗位通过反馈端点持久化并桥接至筛选工作台感兴趣区。再次点击可取消感兴趣。

**验收条件**：标记感兴趣 → 按钮显示「已感兴趣」→ 筛选工作台感兴趣区出现该岗位 → 取消感兴趣 → 按钮恢复 → 工作台感兴趣区不再显示。

## Success Criteria

1. **布局密度**：桌面宽度（≥1200px）下结果页每行展示 3~4 张卡片，窄屏（<768px）下降为单列。
2. **JD 完整性**：所有卡片的 JD 区域展示完整 JD 内容，无截断。
3. **顶部洁净度**：结果页顶部无可见的死元素、横条或空白间隙。
4. **刷新恢复率**：刷新页面后，100% 的已完成发现运行能自动恢复到结果视图。
5. **标记可读性**：不感兴趣标记后卡片在 3 米外仍可辨识为「已标记」状态（灰度 + 低透明度）。
6. **撤销可用性**：所有标记操作（感兴趣/不感兴趣）均可通过按钮撤销，撤销后卡片视觉状态完全恢复。

## Assumptions

- 发现结果 API（`GET /api/discovery/runs/<run_id>/results`）返回的每个 item 已包含完整 `jd` 字段，无需额外请求。
- 感兴趣/不感兴趣反馈端点（`POST /api/discovery/feedback`）和桥接机制已在 005 中实现并可用。
- `restoreDiscoveryRun()` 函数已存在于前端代码中，仅未在初始化时调用。
- 所有改动限于 `webui/index.html` 单文件，不涉及后端、数据模型或新增端点。
- 现有测试（`tests.test_chrome_setup` 等）不直接测试前端 UI，本次改动不引入后端回归。
