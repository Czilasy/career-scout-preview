## 用户场景与测试

### 用户故事 1 - 空城市时两个开始入口统一确认后按全国（B042，优先级：P1）

用户填写了关键词但未填城市时，"单独抓取"和"开始筛选并 AI 优化"两个入口行为必须一致：弹应用内确认框，确认后按全国抓取，取消则不执行。关键词也为空时不弹框，维持现有补齐提示。

**优先原因**：这是同一页面上两个入口的行为冲突，用户会得到互相矛盾的结果，属于信任与可用性问题。

**独立测试**：两个入口分别构造空城市场景，验证弹框、取消、确认提交三条路径。

**验收场景**：

1. **假如** 关键词已填写、城市为空，**当** 用户点击"单独抓取"，**那么** 显示应用内确认框，提示"未填写城市，将按全国范围抓取，是否继续？"，且不发起请求。
2. **假如** 关键词已填写、城市为空，**当** 用户点击"开始筛选并 AI 优化"，**那么** 显示同一确认框，且不发起请求。
3. **假如** 确认框已显示，**当** 用户取消，**那么** 不发起任何请求。
4. **假如** 确认框已显示，**当** 用户确认继续，**那么** 按现有启动流程提交城市 `["全国"]`，城市输入框内容不被改写。
5. **假如** 关键词和城市都为空，**当** 用户点击任一入口，**那么** 不显示确认框，维持现有"请先补齐关键词和城市"提示。
6. **假如** 当前平台为智联，**当** 城市为空且关键词已填写，**那么** 与 BOSS 行为一致，确认后按全国提交。

### 用户故事 2 - 统一错误码注册表（B043，优先级：P2）

系统所有错误码集中到一个注册表：后端、AI、前端、数据库历史错误码都来自同一来源；旧常量只保留为兼容导出；未知码在测试中直接失败，运行时不再静默变成 `internal_error`。

**优先原因**：错误码分散在多处，同一个错误在不同层出现不同码，排障和前端展示都会失真。

**独立测试**：注册表提供全量码表；未知码测试失败；旧别名可继续引用；前端镜像与后端一致。

**验收场景**：

1. **假如** 某错误码已存在于任一现有集合，**当** 查询注册表，**那么** 能定位到唯一注册项，且旧常量名仍可兼容引用。
2. **假如** 调用方使用注册表未收录的码，**当** 执行测试，**那么** 测试直接失败，不再静默映射成 `internal_error`。
3. **假如** 运行时遇到未收录码，**当** 处理错误，**那么** 保留 `internal_error` 兜底，并产生 warning 与结构化日志/事件。
4. **假如** 数据库历史记录中存在已出现过的 `failed_code`，**当** 建立注册表，**那么** 这些码全部收录为已知码。
5. **假如** 前端错误码发生变化，**当** 运行一致性测试，**那么** 后端注册表与前端镜像不一致时测试失败。
6. **假如** 注册表新增错误码，**当** 检查旧语义集合，**那么** `SAFE_FAILURE_CODES`、`ERROR_TAXONOMY`、`SYSTEMIC_BLOCK_CODES` 等导出与注册表保持一致。

### 用户故事 3 - AI 原始响应全部内容落盘（B044，优先级：P2）

AI 调用后，把 JSON 解析前的完整原始响应正文写入本地轮转日志，每个重试尝试都记录；排障时能看到是哪一次返回、什么内容导致解析失败。日志不进入仓库，不记录 API Key/Cookie。

**优先原因**：AI 解析失败缺少现场，只能看到错误码，无法判断是空响应、截断还是格式变化。

**独立测试**：构造成功、失败、超长、多次重试的 AI 响应，验证日志内容、脱敏、截断与轮转。

**验收场景**：

1. **假如** AI 调用完成，**当** 检查本地日志，**那么** 存在 JSON 解析前的完整原始响应正文，并带有 `correlation_id`。
2. **假如** AI 调用发生重试，**当** 检查日志，**那么** 每次尝试都有独立记录，并带 `attempt_index`。
3. **假如** 原始响应超过 500KB，**当** 写入日志，**那么** 记录截断标记与原始长度，不把超长内容一次性写入。
4. **假如** 原始响应包含 API Key/Cookie，**当** 写入日志，**那么** 对应片段被脱敏，不出现明文。
5. **假如** 调优实验调用 AI，**当** 检查日志，**那么** 同样记录原始响应；测试运行默认关闭或写入临时日志目录。
6. **假如** 日志轮转触发，**当** 检查日志目录，**那么** 与现有本地日志轮转策略一致。

### 用户故事 4 - AI 重试策略调整（B045，优先级：P2）

AI 自动重试改为按错误码退避 + 抖动 + 总等待上限；`invalid_response` 只对精筛单条保留 1 次重试；系统性暂停码不自动重试；调优 manifest 与默认策略统一。

**优先原因**：当前重试策略与错误码、调优配置存在多处定义，行为不可控，且失败现场不足。

**独立测试**：构造网络错误、限流、非法响应、系统性错误，验证退避、总上限、重试次数与暂停语义。

**验收场景**：

1. **假如** 发生 `ai_network_error`，**当** 自动重试，**那么** 按 2s/4s/8s + 抖动退避，最多重试 3 次（共 4 次尝试）。
2. **假如** 发生 `ai_rate_limited`，**当** 自动重试，**那么** 按 5s/15s/30s + 抖动退避，最多重试 3 次（共 4 次尝试）。
3. **假如** 精筛单条返回 `invalid_response`，**当** 重试，**那么** 只重试 1 次，间隔 1s。
4. **假如** 初筛或批量返回 `invalid_response`，**当** 处理结果，**那么** 不新增额外重试。
5. **假如** 多次重试累计等待超过 60s，**当** 继续处理，**那么** 停止重试并按现有失败语义结束。
6. **假如** 发生验证码、登录失效、CDP 失联、配额耗尽等系统性错误，**当** 处理任务，**那么** 不自动重试，维持现有暂停语义。
7. **假如** 调优 manifest 提供重试参数，**当** 执行实验，**那么** 参数可覆盖默认策略；缺失或非法时回退默认并校验。

## 边界情况

- B042：确认框只覆盖关键词有、城市为空；关键词为空不弹框；城市已有值不弹框；确认后不把"全国"写回输入框。
- B042：两个平台行为一致；不使用浏览器原生确认框；不新增后端接口。
- B043：未知码的运行时兜底保留，但必须可见（warning + 结构化日志/事件），测试仍直接失败。
- B043：注册表字段采用已确认结构：`code`、`category`、`blocking`、`retryable`、`user_message`、`impact`、`reason`、`resume_condition`、`aliases`。
- B044：原始响应指流式拼接后的最终正文，不含 HTTP 头；重试时每次 attempt 都记录。
- B044：单条上限 500KB，超长记录截断标记和原始长度；只脱敏 API Key/Cookie，简历/JD 保留在本地日志。
- B044：测试默认不写用户日志，通过日志目录环境变量指向临时目录。
- B045：60s 总等待上限只计算重试之间等待，不包含单次请求连接/读取超时。
- B045：截断拆半逻辑保持不变，本次不重写输入截断算法。
- B045：`invalid_response` 的 1 次重试只作用于精筛单条，不扩大到初筛与批量。

### 关键实体

- **错误码注册项**：唯一错误码及其分类、阻断性、可重试性、用户文案、诊断说明、恢复条件与旧码/旧常量别名。
- **原始 AI 响应日志**：JSON 解析前的流式拼接正文，按调用、重试次数和关联 ID 可追溯；只存在于本地日志目录。
- **AI 重试策略**：按错误码定义退避序列、抖动、总等待上限与适用阶段；默认策略与调优 manifest 同构。
