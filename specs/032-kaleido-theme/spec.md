# Feature Specification: 万花筒彩蛋主题模块

**Feature Branch**: `032-kaleido-theme`

**Created**: 2026-08-30

**Status**: Draft

**Input**: User description: "将 design/kaleido/page1-4.html 定稿设计实现为独立前端主题模块，入口为现有主题长按弹层占位处新增「万花筒」选项，按钮原有逻辑不变，主题持久化链路扩展 kaleido 合法值，轻量换肤转场，未覆盖界面降级用暗色，prefers-reduced-motion 全降级。进入 spec 前用户已豁免 grill-me 质询（需求冻结：主题替换，按钮逻辑照旧）。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 长按进入彩蛋并整站换肤 (Priority: P1)

用户长按顶栏明暗切换按钮约 1 秒（现有蓄力契约），弹出主题选择框；选择框在现有占位处显示「亮 / 暗 / 万花筒」三个选项并标识当前主题；点击「万花筒」后整站换为万花筒视觉。普通点击按钮仍是明暗切换，行为与现状完全一致。

**Why this priority**: 这是彩蛋主题的核心入口路径，没有它主题无法触达。

**Independent Test**: 长按主题钮→弹出选择框→点「万花筒」→四页视觉变化且全部原有交互可用，可独立演示与验证。

**Acceptance Scenarios**:

1. **Given** 当前为亮色主题，**When** 长按主题钮至蓄力完成，**Then** 弹出主题选择框（亮/暗/万花筒三项，当前项有标识），且普通明暗切换不触发
2. **Given** 主题选择框打开，**When** 点击「万花筒」，**Then** 整站切换为万花筒主题视觉，原有全部按钮/输入/流程行为与切换前完全一致
3. **Given** 已选择万花筒主题，**When** 重启应用，**Then** 仍处于万花筒主题（持久化生效）
4. **Given** 主题选择框打开，**When** 点击面板外区域或 Esc，**Then** 选择框收起且主题不变

---

### User Story 2 - 四页视觉与设计定稿一致 (Priority: P1)

万花筒主题下，四个主流程页面（① 上传简历 / ② 广泛抓取 / ③ AI 筛选 / ④ 查看与整理岗位）的视觉与设计定稿一致：暗膛光场（光轮＋碎玻璃＋注视之眼）、切面几何、光谱流动色、宋体标题、等宽数字；页面骨架布局与文字内容逐字逐位保持不变。

**Why this priority**: 视觉一致性是"主题替换"需求的主体；设计定稿（`design/kaleido/page1-4.html`）是视觉唯一权威。

**Independent Test**: 万花筒主题下逐页打开，与 `page1.html`~`page4.html` 对照核对布局、文案、视觉三要素。

**Acceptance Scenarios**:

1. **Given** 万花筒主题，**When** 打开任一主流程页，**Then** 视觉与对应定稿设计一致（布局骨架不变、文字逐字一致、模块位置不变）
2. **Given** 万花筒主题，**When** 操作页面上任何原有按钮/输入/列表，**Then** 行为与亮暗主题下完全一致，无新增或缺失的交互

---

### User Story 3 - 动效层与无障碍降级 (Priority: P2)

万花筒主题包含常驻动效（光轮多层异速自转、颜色轮回、本轮漂移、呼吸变焦、瞳孔追踪与苏醒、流动色）与交互动效（点击空白转筒、点 logo 逃生舱短暂静止）；系统声明「减少动态」时全部动效停为静态呈现，功能不受影响。

**Why this priority**: 动效是主题灵魂与怪诞感的来源，但属于体验增强层，可独立于换肤主路径交付。

**Independent Test**: 关闭系统"减少动态"后观察常驻/交互动效；开启"减少动态"后确认页面静态且可用。

**Acceptance Scenarios**:

1. **Given** 万花筒主题且未声明减少动态，**When** 打开任一页，**Then** 常驻动效按定稿运行（自转/轮回/漂移/变焦/流动色）
2. **Given** 万花筒主题，**When** 点击页面空白处，**Then** 转筒动效触发；**When** 点击左上角 logo，**Then** 光场短暂静止（逃生舱）
3. **Given** 系统声明减少动态，**When** 打开万花筒主题，**Then** 全部动效停为静态，页面功能与信息完整可用

---

### User Story 4 - 轻量换肤转场 (Priority: P3)

首次从亮/暗主题进入万花筒时播放轻量转场：暗幕落下→光场光轮旋开→界面浮现→瞳孔睁开（约 0.7~1 秒，无屏幕碎裂）；此后再切换主题只做简短过渡；亮/暗之间互切保持现有切换表现不变；转场期间忽略重复触发。

**Why this priority**: 仪式感是彩蛋点睛，但非必需路径，可在主题可用后独立补充。

**Independent Test**: 首次进入观察完整转场；再次切换观察简短过渡；亮暗互切确认原有表现不变。

**Acceptance Scenarios**:

1. **Given** 当前为亮/暗主题且本次会话首次进入万花筒，**When** 选择万花筒，**Then** 播放轻量转场后进入万花筒主题
2. **Given** 本次会话已进入过万花筒主题，**When** 再次切换主题，**Then** 仅简短过渡，不重复完整转场
3. **Given** 万花筒主题，**When** 切回亮/暗，**Then** 简短过渡恢复，原明暗切换表现（ripple 等）保持现状

---

### User Story 5 - 退出与未覆盖界面降级 (Priority: P2)

用户可随时通过同一入口从万花筒切回亮/暗主题；万花筒主题下设计稿未覆盖的界面（设置类弹窗、收藏/历史抽屉、通知等）降级为暗色样式呈现，不出现样式断裂或不可读。

**Why this priority**: 退出自由与全站不破版是主题可上线的底线。

**Independent Test**: 万花筒主题下逐一打开未主题化的弹窗/抽屉确认暗色降级；长按切回暗色确认全站恢复。

**Acceptance Scenarios**:

1. **Given** 万花筒主题，**When** 长按主题钮选择「暗」或「亮」，**Then** 全站恢复对应主题，无残留万花筒样式
2. **Given** 万花筒主题，**When** 打开任意设计稿未覆盖的弹窗/抽屉/通知，**Then** 以暗色降级样式呈现，文字可读、交互可用

### Edge Cases

- 后端主题偏好接口不可达或拒绝 kaleido 值时：本地持久化兜底生效，主题切换不受阻
- 转场动画期间快速连点主题钮：转场期间忽略重复触发，不产生叠加动画
- 长列表大数据量下动画性能：动效仅使用合成层属性；如出现明显掉帧，动效自动降级为静态，功能不受影响
- 系统声明减少动态时使用长按入口：蓄力发光保留、抖动去掉（沿用现有蓄力契约），弹层与选择照常可用

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在现有主题选择弹层的占位处提供「万花筒」选项，与「亮」「暗」并列显示，并标识当前生效主题
- **FR-002**: 选择万花筒后，四个主流程页面 MUST 呈现与设计定稿一致的视觉；页面骨架、模块位置、文字内容逐字逐位保持不变
- **FR-003**: 主题实现 MUST 独立为主题模块目录（主题容器＋注册口＋子主题模块），MUST NOT 向既有超大文件追加主题逻辑
- **FR-004**: 万花筒主题下所有既有交互（按钮、输入、列表、流程）MUST 与亮暗主题下行为完全一致；明暗切换按钮的普通点击行为与长按蓄力契约 MUST 保持现状
- **FR-005**: 主题选择 MUST 持久化（本地＋后端主题偏好）；后端偏好接口 MUST 接受万花筒为合法值；后端不可达时本地值兜底生效
- **FR-006**: 常驻动效与交互动效 MUST 按定稿实现；系统声明减少动态时 MUST 全部降为静态
- **FR-007**: 首次进入万花筒 MUST 播放轻量换肤转场（暗幕＋光轮旋开＋瞳孔睁开，约 1 秒内，无屏幕碎裂）；后续切换与亮暗互切 MUST 使用简短过渡且不改变既有表现
- **FR-008**: 设计稿未覆盖的界面在万花筒主题下 MUST 以暗色样式降级呈现
- **FR-009**: 主题模块 MUST 可整体插拔：移除模块目录与注册项后，亮/暗主题行为与现状完全一致

### Key Entities *(include if feature involves data)*

- **主题模式（Theme Mode）**: 用户选择的外观偏好，值域由 `light | dark` 扩展为 `light | dark | kaleido`；持久化于本地与后端，后端为启动权威、本地为兜底
- **主题注册表**: 主题容器内的登记口，登记可用主题及其样式/组件/动效入口；亮与暗同样登记，长按弹层按注册表渲染选项
- **主题模块（万花筒）**: 自包含子目录——主题样式层、光场组件、动效脚本；仅通过注册表对外生效

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 四页在万花筒主题下与设计定稿逐页对照通过（布局、文案、视觉三查无偏差）
- **SC-002**: 万花筒主题下主流程全部原有交互可用（上传、抓取参数、筛选条件、结果查看与操作），与亮暗主题行为一致
- **SC-003**: 从点击「万花筒」到主题完全生效不超过 1 秒（不含转场动画）；转场动画本身不超过 1 秒
- **SC-004**: 系统声明减少动态时，万花筒主题页面无任何动画运行
- **SC-005**: 重启应用后主题选择保持；后端接口不可达时切换仍可用
- **SC-006**: 既有前端测试、构建与仓库卫生检查全部通过；亮/暗主题下无任何视觉或行为回归

## Verification Scope *(mandatory)*

- 功能/重构/拆分交付：验证范围为相关模块聚焦测试、后端全量测试、前端测试、`npm run build`、仓库卫生检查。
- 收口发布任务：默认只做卫生测试、hooks、`git diff --check`、`git status` 和 `scripts/release_check.ps1`（若存在）；不自动要求全量测试。
- 只有用户明确要求“全量/全部测试/完整验证”时，收口任务才执行全量测试。

## Assumptions

- 视觉唯一权威为 `design/kaleido/page1-4.html`（含全部动效），实现以逐页对照验收；`design/README.md` 规则（图优先于代码）继续适用
- 质询豁免已由用户声明（2026-08-30）：需求冻结为"主题替换、按钮逻辑照旧"，边界以 `design/kaleido/direction-approved.md` 全部决议为准
- 设计稿未覆盖的界面以暗色降级为既定策略，本 Spec 不为其新增设计
- 标题衬线字体在离线桌面环境使用系统字体栈兜底，不引入网络字体依赖；如视觉对照发现系统字体缺口，再议打包字体
- 动效性能策略：仅使用合成层属性（transform/opacity/filter）；未设计界面的降级样式与性能降级为模块内自兜底
