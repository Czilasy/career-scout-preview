**Feature Branch**: `029-desktop-window-browsers`

**Created**: 2026-08-29

**Status**: Draft

**Input**: User description: "B082 桌面壳窗口记忆修复批（三项打包，BACKLOG P1 第 2 条）：①固定初始值与首开默认状态；②最大化关闭导致拖动记忆丢失修复；③多 Chromium 内核浏览器支持。需求已于 2026-08-29 grill-me 边界质询冻结。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 窗口状态记忆可信（最大化不再破坏记忆） (Priority: P1)

用户把应用窗口拖拽/缩放成自己喜欢的位置和大小后正常使用。当用户在**最大化状态**下关闭应用再打开时，应用恢复为最大化；当用户把窗口**还原回普通态**时，窗口回到用户之前拖好的普通矩形（位置+尺寸），而不是变成一个"全屏大小的普通窗口"。用户拖好的记忆在任何关闭方式下都不会被覆盖丢失；任何启动路径下窗口可见部分都不超出屏幕。

**Why this priority**: 这是本批要修的核心 Bug——现状下最大化关窗会用全屏矩形覆盖用户拖好的普通记忆，导致重启后窗口错乱、拖标题栏整框跟鼠标移动，是日常使用中每天都会撞上的问题。

**Independent Test**: 拖动窗口到任意位置并缩放 → 最大化 → 关闭 → 重开（应最大化）→ 还原（应回到拖好的矩形）→ 关闭 → 重开（应与还原后一致）。全程无需其他功能参与即可验证。

**Acceptance Scenarios**:

1. **Given** 窗口处于用户拖好的普通矩形（位置 A、尺寸 B），**When** 用户最大化窗口后关闭应用，**Then** 记忆文件中保存的是普通矩形 A/B 与"最大化"标记（全屏矩形不得写入记忆），**And** 再次启动时窗口直接以最大化打开。
2. **Given** 应用以最大化启动，**When** 用户点击还原（或拖拽标题栏）回到普通态，**Then** 窗口回到记忆中的普通矩形 A/B（而非全屏大小）。
3. **Given** 窗口处于普通态，**When** 用户拖动/缩放后关闭应用，**Then** 重启后窗口位置尺寸与关闭前一致（行为与现有版本一致，不回退）。
4. **Given** 记忆文件中的普通矩形宽高超出当前任一显示器工作区（如换接了更小的显示器），**When** 应用启动，**Then** 尺寸被钳回工作区内（居中），不会开出超屏窗口。
5. **Given** 记忆文件中的位置坐标不在任何显示器工作区内，**When** 应用启动，**Then** 窗口在主屏工作区居中（现有越界回退行为保留）。
6. **Given** 旧版本记忆文件（schema 2）宽高超出工作区（即已被 Bug 污染的全屏矩形），**When** 新版本首次启动，**Then** 该记忆视同无记忆，按全新安装处理（见 User Story 2），不做破坏性静默覆盖之外的额外迁移。
7. **Given** 窗口最大化期间用户未拖过普通态，**When** 关闭时，**Then** 记忆中保存默认普通尺寸（1545×900，受屏幕钳制）与最大化标记。

### User Story 2 - 全新安装首开体验（默认最大化 + 普通默认 1545×900） (Priority: P2)

任何人、任何版本、全新安装后首次打开应用：窗口直接以**最大化**打开（Windows 标准最大化，任务栏可见）。当用户从最大化还原、或窗口处于普通态但无记忆时，窗口落到**普通态默认尺寸 1545×900、居中**。记忆文件丢失或损坏时，等同于全新安装处理。

**Why this priority**: 首开是所有用户的第一印象；1545×900 作为普通态默认比旧值 1366×768 更适配主流屏幕。它与 User Story 1 共享同一套记忆机制，但"首开给什么"可以独立验收。

**Independent Test**: 删除（或指向空目录）记忆文件后启动应用 → 应最大化开窗；还原窗口 → 应为 1545×900 居中。

**Acceptance Scenarios**:

1. **Given** 无记忆文件（全新安装 / 文件被删除），**When** 应用启动，**Then** 窗口以最大化打开。
2. **Given** 无普通态记忆，**When** 用户从最大化还原窗口，**Then** 窗口为 1545×900、位于屏幕工作区居中。
3. **Given** 显示器工作区小于 1545×900（如 1366×768 屏幕），**When** 窗口落到普通态默认尺寸，**Then** 尺寸被钳到工作区内（仍居中），不超屏。
4. **Given** 记忆文件存在但 JSON 非法 / 字段缺失或非法，**When** 应用启动，**Then** 视同无记忆：最大化开窗。
5. **Given** 记忆文件中存在用户自定义的普通默认尺寸（default_* 覆盖机制，现有能力），**When** 窗口落到普通态默认，**Then** 使用用户自定义值（该机制保留，同样受工作区钳制）。

### User Story 3 - 自选 Chromium 内核浏览器执行抓取 (Priority: P3)

用户不装 Chrome 也能用抓取功能：系统自动探测本机已安装的 Chromium 系浏览器（Brave、Vivaldi、Opera、360 极速、QQ 浏览器、夸克等），用户在设置里下拉选择一个；注册表清单之外、但用户知道路径的浏览器，可以手动指定可执行文件路径。选定的浏览器用于启动抓取专用调试实例（独立数据目录隔离，不碰用户日常浏览器配置）。选错内核（非 Chromium，如 Firefox）或路径无效时，给出明确、可读的报错，而不是莫名的启动失败。

**Why this priority**: 功能扩展，扩大可安装人群；依赖真实浏览器环境验证，成本与不确定性高于前两个故事，故排后。前两个故事不依赖本故事即可交付。

**Independent Test**: 在设置中从探测列表选一个浏览器（或手填路径）→ 启动一次抓取登录流程 → 专用浏览器实例以所选浏览器打开。全程不依赖窗口记忆故事。

**Acceptance Scenarios**:

1. **Given** 本机装有注册表清单内的浏览器，**When** 用户打开设置的浏览器选择界面，**Then** 能看到探测到的浏览器列表（含名称与探测到的路径），并从中选择一个。
2. **Given** 用户选择了某个已探测到的浏览器，**When** 执行抓取，**Then** 抓取专用浏览器实例由该浏览器可执行文件启动，且使用独立数据目录（不影响日常浏览器的配置与登录态）。
3. **Given** 探测列表不含目标浏览器，**When** 用户手动指定可执行文件路径，**Then** 系统校验该路径指向可运行的可执行文件（校验失败给出明确提示），校验通过后同样可用于抓取。
4. **Given** 手动指定的路径指向非 Chromium 内核浏览器（如 Firefox），**When** 用户保存或启动抓取，**Then** 系统在内核校验阶段明确报错"该浏览器内核不兼容"，不出现无从下手的失败。
5. **Given** 用户从浏览器 A 切换到浏览器 B，**When** 再次执行抓取，**Then** 各账号在浏览器 B 的独立数据目录下重新开始（需重新登录一次）；浏览器 A 的数据目录原样保留——切回 A 无需重新登录。
6. **Given** 所选浏览器已被卸载（路径失效），**When** 执行抓取，**Then** 明确报错并指引重新选择，回退行为可预期。
7. **Given** 本机一个注册表浏览器都没装，**When** 用户打开浏览器选择界面，**Then** 界面给出"未探测到，请手动指定路径"的指引，功能可用（手动路径兜底）。

### Edge Cases

- 最大化状态下用户修改显示器配置（拔掉副屏）后关窗：以关窗时刻能枚举到的工作区做钳制校验，启动时再次校验钳制，双保险。
- 记忆文件被手工编辑成半合法 JSON（如缺一个字段）：缺失字段视同无记忆，整体视同无记忆处理，不崩溃。
- 手动指定路径指向同名但非浏览器的可执行文件：可执行性校验（版本参数探活）或内核校验环节拒绝，报错明确。
- 夸克等国产浏览器探测到但调试端口无法建立：按"浏览器不兼容/启动失败"明确报错，不无限等待（现有 90 秒等待与死进程提前退出逻辑保持）。
- schema 2 旧记忆文件升级：正常范围内的旧记忆（宽高未超工作区）无损继承为普通态记忆；超工作区的污染记忆视同无记忆。
- 切换浏览器后立即切回：旧数据目录未清理，登录态仍有效。

## Requirements *(mandatory)*

### Functional Requirements

**窗口记忆（User Story 1 & 2）**

- **FR-001**: 系统 MUST 在窗口处于普通态时实时记住其位置与尺寸（拖动、缩放均更新），关闭时写入记忆文件。
- **FR-002**: 系统 MUST 在窗口处于最大化状态时保留"最后一次普通矩形"不被全屏矩形覆盖；最大化状态下关闭，记忆文件保存最后一次普通矩形与最大化标记。
- **FR-003**: 系统 MUST 支持记忆文件表达"上次关闭时处于最大化"，并在下次启动时直接以最大化开窗；用户随后还原窗口时回到记忆中的普通矩形。
- **FR-004**: 系统 MUST 保证写入记忆的普通矩形与启动读取的记忆值都不超出当前显示器工作区（宽高钳制 + 位置越界回退主屏居中）。
- **FR-005**: 无记忆文件 / 文件损坏 / 记忆字段无效 / 旧版本污染记忆（超工作区）MUST 一律按全新安装处理：最大化开窗。
- **FR-006**: 普通态默认尺寸 MUST 为 1545×900（屏幕不足时钳到工作区），居中；无普通记忆时（从最大化还原等）落到该默认。
- **FR-007**: 用户自定义普通默认尺寸的覆盖机制（记忆文件 default_* 字段）MUST 保留，语义不变（同样受工作区钳制）。
- **FR-008**: 记忆文件格式 MUST 从旧版本平滑升级：正常旧记忆无损继承；被污染记忆视同无记忆。旧版本记忆文件不得出现读取崩溃或静默生成错乱窗口。

**多浏览器（User Story 3）**

- **FR-009**: 系统 MUST 内置 Chromium 系浏览器注册表，v1 收录 8 家：Chrome、Edge、Brave、Vivaldi、Opera、360 极速、QQ 浏览器、夸克；每条含名称、常见安装路径候选、可执行文件名、独立数据目录标识。
- **FR-010**: 系统 MUST 自动探测本机已安装浏览器（按注册表路径候选探测），供设置界面展示与选择；一个都没探测到时指引手动指定路径。
- **FR-011**: 用户 MUST 能在设置界面以全局单选方式选定抓取用浏览器；选择持久化，重启后保持。
- **FR-012**: 用户 MUST 能手动指定浏览器可执行文件路径；系统 MUST 校验该路径指向可运行的可执行文件，失败时提示明确。
- **FR-013**: 系统 MUST 在保存选择或启动抓取时校验所选浏览器为 Chromium 内核（调试端点探活校验），非 Chromium 内核 MUST 给出明确的"内核不兼容"报错。
- **FR-014**: 抓取专用浏览器 MUST 按浏览器隔离数据目录命名空间（每个浏览器一套根目录，账号在各自浏览器命名空间内继续隔离）；切换浏览器后各账号需重新登录一次，旧浏览器的数据目录与登录态 MUST 原样保留、可回退。
- **FR-015**: 系统 MUST NOT 实现跨浏览器登录态复制（复制机制已废弃且跨内核不可靠）。
- **FR-016**: 系统 MUST NOT 支持 Firefox / Safari（非 Chromium 内核，协议不兼容；备忘见 BACKLOG B083）。
- **FR-017**: 探测、选择、校验的报错文案 MUST 用户可读，指明下一步动作（换一个浏览器 / 手动指定路径 / 重新选择）。

### Key Entities *(include if feature involves data)*

- **窗口状态记忆文件**（用户数据目录下的本地文件）：记录普通矩形（位置+尺寸）、最大化标记、用户自定义普通默认尺寸、格式版本号；格式升级需向后兼容。
- **浏览器注册表条目**：名称、安装路径候选列表、可执行文件名、数据目录命名空间标识；随注册表内置，可后续增补。
- **浏览器选择设置**：全局单值——选中的注册表浏览器标识，或手动指定的可执行文件路径；跨会话持久。
- **浏览器账号数据目录**：现有按账号隔离的调试实例数据目录，新增按浏览器命名空间一层归属。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: User Story 1 验收场景 1–7 全部通过：最大化关窗 → 重启最大化 → 还原回拖好的矩形 → 再重启保持一致，零记忆丢失。
- **SC-002**: 全新安装（删除记忆文件）首开即为最大化，普通态落点 1545×900 居中（超小屏钳制）。
- **SC-003**: 任意启动路径（含换小屏显示器、手工损坏记忆文件）下，窗口可见部分不超出屏幕工作区。
- **SC-004**: 注册表 8 家浏览器的探测与配置正确性由自动化测试覆盖；真机冒烟覆盖本机实际安装的 Chrome 与 Edge。
- **SC-005**: 用户从探测列表选择浏览器或手动指定有效路径后，可完成一次真实抓取登录流程；选错内核时在启动阶段即得到明确报错（无 90 秒级无反馈等待）。
- **SC-006**: 窗口记忆与多浏览器相关纯逻辑全部有单元测试；既有桌面壳测试全绿，无回归。

## Verification Scope *(mandatory)*

- 功能/重构/拆分交付：验证范围为相关模块聚焦测试、后端全量测试、前端测试、`npm run build`、仓库卫生检查。
- 收口发布任务：默认只做卫生测试、hooks、`git diff --check`、`git status` 和 `scripts/release_check.ps1`（若存在）；不自动要求全量测试。
- 只有用户明确要求"全量/全部测试/完整验证"时，收口任务才执行全量测试。
- 本 Spec 特别约定：窗口记忆真机冒烟（最大化/还原/拖拽记忆）需在 Windows 实机执行一次并记录结果；多浏览器真机冒烟仅覆盖本机已安装的浏览器（2026-08-29 确认为 Chrome、Edge），其余注册表条目以配置正确性单测兜底。

## Assumptions

- 桌面壳运行于 Windows 为主（窗口记忆逻辑三平台通用，但验收以 Windows 实机为准；macOS 侧仅保证不回归）。
- 浏览器选择是全局单选（不区分账号），切换浏览器是低频操作，切换后重新登录一次可接受。
- 用户本机实际安装的浏览器为 Chrome 与 Edge，其余 6 家的验证依赖注册表配置正确性与手动路径校验兜底，不做真机全量冒烟。
- 窗口事件监听依赖桌面壳框架的事件 API（项目已约束框架版本 ≥ 6.0，所需事件在该版本起可用；若个别事件在特定后端不触发，以关窗时刻的兜底保存为准，不阻塞交付）。
- 每个抓取账号的数据目录本就按账号隔离，本批仅增加"按浏览器"一层命名空间，不改变账号隔离语义。
