# Feature Specification: Windows 桌面窗口拉伸与原生式顶栏拖动

**Feature Branch**: `codex/feature/desktop-window-resize`

**Created**: 2026-09-14

**Status**: Frozen

**Input**: 用户要求在现有 Windows 自绘无边框桌面壳上，只补齐窗口边缘拉伸、顶栏拖动还原/顶边最大化，以及用户调整后窗口大小与位置的记忆；不重新设计标题栏，不扩展为完整窗口贴靠系统。

## 已确认需求边界

### A 组：用户原话与逐项确认

- 现有自绘桌面壳没有拖拉调整大小，本轮要补上拉伸。
- 拉伸既要覆盖边框，也要包含边角“手柄头”，即四边与四角都能调整窗口大小。
- 最大化窗口时，按住顶栏向下拖动能够缩小为普通窗口并继续跟随鼠标。
- 普通窗口拖住顶栏向屏幕顶部移动并释放能够放大为最大化窗口。
- 用户手动拖动后的窗口大小需要记忆。
- 不再逐项追问低价值细节；其余边界采用质询阶段给出的推荐选项。

### B 组：已接受的推荐补充

- 本轮只支持 Windows 桌面版；macOS 原生标题栏与浏览器模式保持不变。
- 支持左、右、上、下四条边及四个角，共八方向拉伸；命中区域不显示可见手柄。
- 顶栏拖动最大化窗口向下时，还原到上一次普通窗口大小，并尽量保持用户抓住的相对位置，拖动不中断。
- 普通窗口只有拖到当前显示器顶部并释放才最大化；不增加左右半屏、四角四分屏或自定义预览。
- 可拖动区域限于现有 36px 自绘标题栏的空白区域与标题文字区域；窗口按钮及其他可交互控件不得触发拖动。
- 双击标题栏最大化/还原、最小化、最大化/还原、关闭按钮均保持现有行为。
- 默认普通窗口大小为 1400×800；常规最小窗口大小为 1024×700。
- 普通窗口不得大于当前显示器可用工作区；工作区小于常规最小尺寸时，允许临时缩小到工作区以内，确保窗口完整可操作。
- 拉伸时实时更新内容布局，不缩放页面，不以拉伸结束后才刷新代替实时反馈。
- 任务运行中或应用内对话框存在时，仍允许移动和拉伸桌面窗口；后台任务不因窗口操作暂停、重启或丢失。
- 全局只记忆一个最近普通窗口矩形，不为每个显示器分别保存。
- 保持既有启动语义：首次启动最大化；最大化状态关闭后仍以最大化重开；普通状态关闭后恢复最近普通窗口位置和大小。
- 最大化时的屏幕矩形不得覆盖最近普通窗口矩形。
- 本轮不改变标题栏高度、主题、阴影、圆角、按钮样式或页面视觉设计。
- 不接受覆盖页面内容的透明拉伸层，也不接受导致系统标题栏、边框或非客户区重新出现的方案。
- 拉伸、拖动还原、顶边最大化和窗口记忆作为一个整体交付；任何一个关键真机门禁失败，都不得把其余部分当作可发布完成品。
- 正式真机范围为 Windows 10 与 Windows 11。

## 最高目标

Windows 用户面对现有自绘无边框桌面壳时，可以像操作正常桌面窗口一样，从任意边或角平滑调整大小，也可以用顶栏完成最大化窗口拖动还原和普通窗口拖顶最大化；用户调整后的普通窗口位置与大小在重启后可靠恢复，同时不破坏任务栏边界、页面可用性、后台任务或既有标题栏行为。

## User Scenarios & Testing

### User Story 1 - 从四边四角自然调整窗口大小（Priority: P1）

Windows 用户把指针移到无边框窗口的任一边或任一角时，能够得到符合方向的拉伸反馈并连续调整窗口大小。窗口内容在拉伸过程中实时重排，视觉上仍是现有自绘桌面壳，不出现额外手柄、透明遮挡层或系统标题栏。

**Why this priority**: 这是用户提出的直接缺口，也是普通桌面窗口最基础的可用性能力。

**Independent Test**: 在 Windows 10 与 Windows 11 的真实桌面包中，分别从四条边和四个角执行缩小、放大与反向拉伸，验证八个方向全部有效、指针反馈正确、内容实时重排且页面控件不被遮挡。

**Acceptance Scenarios**:

1. **Given** 普通窗口未达到尺寸边界，**When** 用户从左、右、上、下任一边拖动，**Then** 仅相应方向改变窗口矩形，拖动连续且内容实时重排。
2. **Given** 普通窗口未达到尺寸边界，**When** 用户从左上、右上、左下、右下任一角拖动，**Then** 两个相邻方向同时改变，形成符合该角方向的对角拉伸。
3. **Given** 指针位于可拉伸边缘或角落，**When** 用户尚未按下，**Then** 指针显示与该方向一致的系统拉伸形态；离开命中区域后恢复正常。
4. **Given** 指针位于页面内容、标题栏按钮或其他交互控件上，**When** 用户点击或拖动，**Then** 不误触发边缘拉伸，原控件交互保持可用。
5. **Given** 用户正在拉伸窗口，**When** 窗口尺寸连续变化，**Then** 页面按新可用空间实时布局，不缩放整页，也不等待松手后才统一刷新。

### User Story 2 - 用顶栏拖动完成还原与最大化（Priority: P1）

Windows 用户可以按住现有自绘标题栏的可拖动区域移动普通窗口；从最大化状态向下拖动时，窗口立即还原到最近普通大小并继续跟随指针；把普通窗口拖到当前显示器顶部并释放时，窗口最大化到该显示器工作区。

**Why this priority**: 用户把“手柄头”和顶栏拖动视为同一套完整窗口体验；缺少任一项都会让自绘壳继续显得不可靠。

**Independent Test**: 在不同大小、不同位置与不同显示器上往返执行“最大化→向下拖动还原→继续移动→拖顶释放最大化”，验证抓取位置连续、无跳变、最大化不覆盖任务栏，并确认非拖动控件不受影响。

**Acceptance Scenarios**:

1. **Given** 窗口处于最大化，且已有最近普通窗口矩形，**When** 用户按住标题栏可拖动区域向下移动，**Then** 窗口还原到最近普通大小并在同一次按压中继续跟随指针。
2. **Given** 用户从最大化标题栏的某一横向位置开始拖动，**When** 窗口还原，**Then** 指针仍大致位于窗口中与原抓取比例对应的位置，不发生窗口突然跳到指针之外的明显错位。
3. **Given** 普通窗口正在移动，**When** 用户把标题栏拖到当前显示器顶部并释放，**Then** 窗口最大化到当前显示器工作区且不覆盖任务栏。
4. **Given** 普通窗口仅经过屏幕顶部但未在顶部释放，**When** 用户继续移动或在别处释放，**Then** 窗口保持普通状态。
5. **Given** 普通窗口拖到显示器左、右或角落并释放，**When** 操作结束，**Then** 不触发本轮未包含的半屏或四分屏贴靠。
6. **Given** 用户双击标题栏或点击现有窗口按钮，**When** 执行最大化、还原、最小化或关闭，**Then** 既有行为与图标状态保持正确。
7. **Given** 用户在标题栏按钮或其他顶栏交互控件上按下并移动，**When** 操作发生，**Then** 不把该操作识别为窗口拖动。

### User Story 3 - 重启后恢复用户最后的普通窗口（Priority: P1）

用户调整普通窗口的大小与位置后关闭应用，下次打开时仍遵循既有最大化启动规则；当应用进入普通状态时，恢复最近一次有效的普通窗口矩形。最大化本身不会污染这份记忆。

**Why this priority**: 拉伸若不能可靠记忆，用户每次启动都要重复整理窗口，功能价值会大幅下降。

**Independent Test**: 先在普通状态调整窗口矩形并关闭、重开验证；再最大化后关闭、重开并还原验证；最后跨显示器移动和改变工作区后重开，确认有效记忆恢复且失效记忆被安全约束。

**Acceptance Scenarios**:

1. **Given** 用户在普通状态调整过窗口大小和位置，**When** 关闭并重新启动应用，**Then** 应用保持既有启动状态语义，进入普通状态时恢复最近有效的普通窗口矩形。
2. **Given** 用户先调整普通窗口再最大化并关闭，**When** 重新启动后还原窗口，**Then** 恢复最大化前的普通窗口矩形，而不是最大化矩形。
3. **Given** 用户从未保存过有效窗口记忆，**When** 首次启动，**Then** 使用 1400×800 的默认普通大小并按既有规则最大化启动。
4. **Given** 保存的普通窗口矩形在当前显示器布局中部分或全部不可见，**When** 应用启动或还原，**Then** 窗口被约束到可操作的显示器工作区内，而不是在屏幕外打开。
5. **Given** 用户把窗口移动到另一台显示器并调整大小，**When** 保存状态，**Then** 全局最近普通窗口矩形被更新，不额外建立每显示器独立记忆。

---

### User Story 4 - 小窗口与运行中任务仍然可用（Priority: P2）

用户把窗口缩小到允许的下限，或在任务执行、对话框打开期间调整窗口时，应用的核心内容和控制仍可访问；窗口操作不改变后台任务生命周期。

**Why this priority**: 拉伸能力必须服务实际使用，不能以页面溢出、双滚动条或任务中断换取表面上的窗口可调整。

**Independent Test**: 在最小尺寸和小于常规下限的狭小工作区中走查主要页面与对话框；同时启动任务并反复移动、拉伸、最大化和还原，验证任务状态与结果连续。

**Acceptance Scenarios**:

1. **Given** 当前工作区足以容纳 1024×700，**When** 用户继续缩小窗口，**Then** 窗口在 1024×700 停止缩小。
2. **Given** 当前显示器工作区小于 1024×700，**When** 窗口启动、还原或跨入该显示器，**Then** 可以临时小于常规下限以完整留在工作区内，且关键窗口控制可触达。
3. **Given** 窗口处于允许的最小尺寸，**When** 用户浏览主要页面或打开对话框，**Then** 核心操作仍可访问，不出现阻断使用的横向溢出、内容大面积裁切或嵌套双滚动条。
4. **Given** 后台任务正在运行，**When** 用户移动、拉伸、最大化或还原窗口，**Then** 任务不中断、不重启、不丢进度，结果仍可恢复。
5. **Given** 应用内对话框已经打开，**When** 用户调整窗口大小或位置，**Then** 对话框保持可见、可操作，并随可用空间合理约束。

### Edge Cases

- 窗口已处于最大化时，边缘拉伸不应产生普通窗口尺寸污染或异常抖动。
- 用户在拖动过程中跨越不同缩放比例、不同分辨率的显示器时，窗口应继续可控，并以当前指针所在显示器的工作区作为顶部最大化与边界判断基准。
- 任务栏位于屏幕上、下、左或右侧时，最大化与普通窗口约束都必须尊重实际工作区。
- 保存状态时应用异常退出、记忆缺失或记忆损坏，不得导致下次启动失败；应回到既有安全默认行为。
- 标题栏可拖动区与边缘拉伸区在顶边或顶角相邻时，顶角优先表达拉伸，标题栏内部表达移动，不能随机切换。
- 快速连续执行拉伸、最大化、还原、跨屏移动时，最终普通窗口记忆只记录最后一个稳定有效的普通矩形。
- 正常窗口被放大到接近工作区尺寸时，仍属于普通状态；只有明确的最大化动作才改变最大化记忆。
- 窗口失去焦点、重新获得焦点或页面正在加载时，边缘命中不得永久卡住或持续截获页面输入。

## Requirements

### Functional Requirements

- **FR-001**: Windows 自绘无边框桌面窗口 MUST 支持左、右、上、下及四角共八方向拉伸。
- **FR-002**: 各边与角的有效命中范围 MUST 连续可用且互不冲突，角区域 MUST 优先提供对应的对角拉伸。
- **FR-003**: 可拉伸区域 MUST 使用方向一致的系统指针反馈，但 MUST NOT 显示常驻或悬浮的可见手柄。
- **FR-004**: 拉伸 MUST 实时改变窗口与内容可用空间；页面 MUST 自然重排，MUST NOT 通过整体缩放代替响应式布局。
- **FR-005**: 常规最小普通窗口大小 MUST 为 1024×700；默认普通窗口大小 MUST 为 1400×800。
- **FR-006**: 普通窗口的最大宽高 MUST 受当前显示器工作区限制，窗口不得因放大而遮住任务栏或完全失去可操作区域。
- **FR-007**: 当显示器工作区小于 1024×700 时，系统 MUST 临时允许窗口缩至工作区可容纳范围，优先保证窗口完整可见和窗口控制可操作。
- **FR-008**: 现有 36px 自绘标题栏的空白区域与标题文字区域 MUST 可用于移动窗口；窗口按钮及其他交互控件 MUST 排除在拖动区域外。
- **FR-009**: 最大化窗口从标题栏向下拖动时 MUST 在同一次持续按压中还原到最近普通大小并继续移动，且 MUST 尽量保持抓取位置的横向相对关系。
- **FR-010**: 普通窗口拖到当前显示器顶部并在那里释放时 MUST 最大化；仅经过顶部或在其他位置释放 MUST NOT 最大化。
- **FR-011**: 本轮 MUST NOT 增加左/右半屏、角落四分屏或自定义贴靠预览。
- **FR-012**: 双击标题栏最大化/还原及最小化、最大化/还原、关闭按钮 MUST 保持现有行为，不得因新拖动能力回归。
- **FR-013**: 系统 MUST 持久保存一个全局最近普通窗口矩形，至少包含位置与大小；普通状态下用户完成移动或拉伸后，该矩形 MUST 更新。
- **FR-014**: 最大化窗口的矩形 MUST NOT 覆盖最近普通窗口矩形；从最大化还原或拖动还原时 MUST 使用最近有效普通窗口矩形。
- **FR-015**: 首次启动、最大化关闭后重开、普通关闭后重开的状态语义 MUST 与现有产品一致。
- **FR-016**: 保存的窗口矩形在当前显示器布局中失效时，系统 MUST 将其约束到可用工作区；记忆缺失或损坏时 MUST 使用安全默认值启动。
- **FR-017**: 移动、拉伸、最大化和还原 MUST NOT 暂停、重启、取消或丢失后台任务，也 MUST NOT 改变打开中的对话框业务状态。
- **FR-018**: 在 1024×700 及可用工作区更小时，主要页面和对话框的核心操作 MUST 可访问，MUST NOT 出现阻断使用的横向溢出、大面积裁切或嵌套双滚动条。
- **FR-019**: 本轮窗口交互 MUST 仅在 Windows 桌面版生效；macOS 原生标题栏与浏览器模式 MUST 保持现状。
- **FR-020**: 本轮 MUST 保持现有标题栏高度、主题、阴影、圆角、按钮样式与页面视觉，不得借机改版。
- **FR-021**: 拉伸能力 MUST NOT 依赖覆盖页面内容的透明交互层，也 MUST NOT 使系统标题栏、系统边框或额外非客户区重新可见。
- **FR-022**: 八方向拉伸、最大化拖动还原、顶边释放最大化与普通窗口记忆 MUST 作为同一交付单元通过验证；任一关键真机门禁失败时，本功能 MUST 整体停止交付并报告失败事实。
- **FR-023**: 在全面集成前，候选窗口交互 MUST 先在与正式 Windows 桌面包一致的壳层与页面承载环境中通过真实操作门禁；门禁失败时 MUST NOT 自动改用历史上已失败的交互方案。
- **FR-024**: 正式兼容性验收 MUST 同时覆盖 Windows 10 与 Windows 11。

### Key Entities

- **最近普通窗口矩形**: 用户最近一次稳定普通状态的窗口位置与大小；全局唯一，在移动或拉伸完成后更新，最大化矩形不得覆盖它。
- **窗口显示状态**: 普通、最大化或最小化；决定启动恢复、顶栏拖动和普通矩形是否可更新。
- **当前显示器工作区**: 当前指针或窗口操作所对应显示器中扣除任务栏后的可用矩形；约束最大化、普通窗口上限、跨屏与小工作区行为。
- **窗口交互区域**: 四边、四角、标题栏可拖动区及被排除的控件区；同一位置在同一时刻只能表达一种明确交互。
- **窗口记忆**: 最近普通窗口矩形与既有最大化标记的持久状态；二者职责分离但共同决定下次启动和还原结果。

## Success Criteria

### Measurable Outcomes

- **SC-001**: Windows 10 与 Windows 11 真机上，四边与四角共 8 个方向逐项操作全部能够连续改变窗口尺寸，方向正确率为 8/8。
- **SC-002**: 连续完成 10 次“最大化→向下拖动还原→继续移动→拖到顶部释放最大化”往返，10 次均无拖动中断、明显跳离指针或覆盖任务栏。
- **SC-003**: 普通窗口移动与拉伸后重启、最大化关闭后重启并还原、跨显示器后重启三组记忆场景全部恢复到有效普通矩形，最大化矩形污染次数为 0。
- **SC-004**: 在工作区足够时，窗口无法缩小到 1024×700 以下；在工作区不足时，窗口 100% 留在工作区内且标题栏和关闭按钮可操作。
- **SC-005**: 拉伸过程中页面连续响应尺寸变化；在 1024×700 下走查全部主要页面和对话框，阻断核心操作的横向溢出、大面积裁切和嵌套双滚动条数量均为 0。
- **SC-006**: 在后台任务运行期间连续执行至少 20 次移动、拉伸、最大化与还原操作，任务中断、重启、进度丢失和结果不可恢复次数均为 0。
- **SC-007**: 标题栏双击及最小化、最大化/还原、关闭按钮的既有验收项全部通过；macOS 与浏览器模式的窗口行为变更数量为 0。
- **SC-008**: 正式 Windows 桌面包中不出现可见拉伸手柄、页面透明遮挡层、系统标题栏或额外系统边框。
- **SC-009**: 与正式包一致的壳层门禁在全面集成前通过全部核心交互；若未通过，则交付状态明确为停止，且不产生部分功能已完成的结论。

## Verification Scope

- **门禁 1——精确壳层可行性**：在与正式 Windows 桌面包一致的运行时、页面承载方式和无边框设置下，先验证四边四角命中、标题栏移动、最大化拖动还原、顶边释放最大化、按钮排除与页面点击均可共存。任一核心项失败即停止，不进入全面功能集成。
- **聚焦自动化验证**：覆盖普通矩形与最大化状态分离、移动/拉伸后的持久化、损坏记忆与工作区约束、最小尺寸例外、现有标题栏控制回归，以及不支持平台保持原状。
- **前端验证**：在 `webui/` 执行前端测试与构建，并对所有主要页面及对话框执行 1024×700 的布局回归；检查核心操作、横向溢出、大面积裁切与嵌套双滚动条。
- **后端与仓库门禁**：开发与返修阶段只跑聚焦测试、原失败用例及直接受影响回归；R0 前置拆分与 036 v2 视为同一交付链，不分别重复全量。整条交付链收敛后才运行一次干净的后端全量、前端测试、前端构建和仓库卫生检查；全量失败后先按失败清单聚焦返修，禁止无相关改动重跑全量。
- **真实端到端验收**：Windows 10 与 Windows 11 均使用真实桌面包，从用户入口完成八方向拉伸、顶栏拖动往返、跨屏、任务栏工作区、记忆重启、小窗口页面、对话框和运行中任务全链路验证。低层单元或临时壳层结果不得冒充该验收。
- 本 Spec 不授权版本提升、提交、推送、打包发布或修改外部数据。

## Assumptions

- **A1（既有视觉为基线）**: 当前自绘标题栏的 36px 高度、外观、按钮与主题已经验收，本轮只补窗口交互能力。
- **A2（单用户桌面环境）**: 窗口记忆属于本机当前用户，不涉及账号同步、云同步或多用户冲突。
- **A3（一个最近普通矩形）**: 用户已接受全局单份记忆；更换或移除显示器时通过工作区约束恢复可用性，不建立每屏历史。
- **A4（顶部最大化语义）**: “拖到顶部”以释放时指针所在显示器的可用工作区顶边为准，不要求自定义预览。
- **A5（狭小工作区优先可操作）**: 当物理工作区与常规最小尺寸冲突时，完整可见和可关闭优先于坚持 1024×700。
- **A6（完整交付优先）**: 用户明确不接受残缺窗口体验，因此任何关键门禁失败都需要重新回到方案决策，而不是自动降级或部分上线。

## Out of Scope

- macOS 原生标题栏、Linux 桌面壳和浏览器模式窗口能力。
- 左右半屏、四角四分屏、窗口布局组、自定义贴靠预览或完整复刻操作系统所有贴靠功能。
- 标题栏、窗口按钮、主题、阴影、圆角、页面布局风格的视觉重设计。
- 每显示器独立的窗口大小和位置记忆，以及跨设备或账号同步。
- 灵动岛状态、提醒入口及原 036 中其他顶栏业务能力的新增或调整。
- 自动尝试已知会造成系统非客户区回归、透明层遮挡或全页面误拖动的历史方案。
- 为容纳本功能而顺便拆分超限文件；该工程还债必须使用独立 Spec 与独立实施批次。
