# Contract: Windows 桌面窗口交互

本合同定义 036 v2 的内部可观察契约，不代表新增公共网络 API。

## 1. 安装合同

输入是已创建且可见的单个 Career Scout 顶层 Windows 窗口、既有日志入口、36px 标题栏与 1024×700 常规下限。输出必须包含 `installed`、稳定错误码 `reason` 和 `hwnd_found`。

同一 HWND 重复安装必须幂等；回调和原过程引用必须存活到窗口关闭；未处理消息必须转发给原过程；**实现只允许一条 WndProc hook（顶层 `WM_GETMINMAXINFO` 链）**，拉伸/移动不得新增 hook；安装失败不得阻断非 Windows 模式启动，但 Gate 1 必须把 Windows 安装失败判为阻断。

## 2. 命中合同（页面判定，宿主执行）

### 普通状态

| 区域 | 结果 |
|---|---|
| 左上、右上、左下、右下角 | 对应对角拉伸 |
| 左、右、上、下边 | 对应单轴拉伸 |
| 36px 标题栏空白/标题文字，扣除最外层顶边 | 标题栏移动 |
| 三个窗口按钮与其他内容 | 客户区点击 |

最大化状态不提供边缘拉伸，标题栏空白区仍允许移动，三个窗口按钮仍为客户区。角优先于边，边优先于标题栏。

判定发生在页面的 CSS 像素空间（DOM 事件），命中后只发起**一次**调用；宿主在原生边界按当前 DPI 一次性换算为物理像素，窗口矩形始终按物理像素解释。页面不得逐帧回传指针位置。

## 3. 移动与最大化合同

- 普通标题栏拖动连续跟随指针（宿主循环驱动，不使用系统 `SC_MOVE` 循环）。
- 最大化标题栏向下拖动在同一次按压内还原并继续移动，横向抓取比例保持。
- 只有当前显示器工作区顶部释放产生最大化。
- 左、右和角落释放不得留下半屏或四分屏状态（宿主不调用系统贴靠路径）。
- 最大化使用工作区而非整屏，任务栏位于任一边都不得被覆盖。

若正式壳层无法同时满足以上项目，Gate 1 失败；不得增加未确认的左右贴靠、透明边缘层或系统边框来换取拖动。

## 4. 最小/最大跟踪合同

给定当前显示器工作区 `work_w × work_h`：常规最小跟踪尺寸为 1024×700 经当前 DPI 转换后逐轴与工作区取较小值；最大跟踪尺寸为工作区；最大化位置和尺寸也使用工作区。逻辑值与物理值只在原生边界转换一次。

## 5. 窗口记忆合同

- 文件 schema 保持 3。
- `width/height/x/y` 永远是最近普通矩形，`maximized` 只描述关闭时显示状态。
- 普通移动和拉伸更新 Tracker；最大化和最小化期间不更新普通矩形。
- closing 时沿既有单一入口写盘，不在每次移动/拉伸时写盘。
- 读取旧的合法 schema 3 记忆保持兼容；超出当前布局时按工作区修正。

## 6. 标题栏合同

- `WindowTitleBar.vue` 继续只在桌面模式渲染，并作为桌面窗口交互的页面侧入口（标题带移动 + 边缘区域上报 + 指针反馈）。
- 标题、36px 高度、主题、按钮、悬停、关闭中状态和最大化图标语义保持不变。
- 移除 `.pywebview-drag-region`：不再使用 pywebview 自带拖动机制，避免同一按压存在两套移动逻辑。
- 标题带按下 → 一次 `window_begin_move`；边缘按下 → 一次 `window_begin_resize`；命中判定不新增任何覆盖页面内容的可见元素。
- 窗口尺寸变化后（含拖下还原、顶部最大化）最大化图标必须与真实状态一致。
- 双击和三按钮现有行为必须回归通过；测试验证最终用户行为，不强制旧 JS 调用路径。

## 7. 失败停止合同

8 个拉伸方向任一不可用、页面点击被截获、拖下还原不连续、顶部释放失败、产生左右/四角最终贴靠、DPI/跨屏持续错位、宿主循环导致鼠标被永久捕获或崩溃，均阻断 036 v2。失败后只记录证据并回到方案决策，不得自动启动备用实现。
