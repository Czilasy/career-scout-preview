# 研究与设计决策

## AI 输出合同

决定：简历解析、关键词生成、JD 排序和反馈更新全部要求 JSON，并在应用端验证字段、长度、枚举与数量。若配置服务支持结构化输出则使用该能力；否则仍验证 JSON 文本，不合格时失败或回退。

理由：AI 输出将影响关键词、城市和排序，不能直接进入抓取器。OpenAI 官方文档说明结构化输出可遵循 JSON Schema，而 JSON 模式仍需要应用处理不完整对象，因此服务端和应用端都需要校验。

替代方案：只依赖提示词要求 JSON。拒绝，格式正确不代表字段安全或完整。

官方依据：https://developers.openai.com/api/docs/guides/structured-outputs

## AI 服务设置

决定：界面只要求 URL 与 API Key。URL 指向一个已配置默认模型的兼容服务端点；系统不内置模型名、不猜测供应商协议，保存后先测试连接。

理由：这是用户要求的最少配置。不同供应商对模型字段不一致，连接测试是唯一可靠确认。

## 流程权与反馈

决定：程序负责人工条件优先、城市必填、60 条 JD 预算、去重、链接校验、任务状态、保存和撤销。AI 只给建议与排序。

决定：每条兴趣反馈都关联画像、岗位、运行和可选原因。即时更新可见列表；每 5 条未撤销新反馈再请求 AI 更新偏好，只影响未展示岗位和未来运行。

## JD 预算

决定：最多 3 个关键词收集列表，但一个父运行完整 JD 总数上限为 60。每条有效 JD 与排序结果完成后即可显示。

理由：详情抓取较慢；预算控制运行时长，流式展示让用户尽早看到完整大卡片。

## 粗略提示词合同

简历解析：仅使用简历明确内容，返回画像名、城市、岗位方向、技能、关键词和每个建议的来源或不确定标记。无依据时返回空数组；禁止编造经历、学历、薪资、证书或项目。

JD 排序：接收已确认画像、人工条件与最多 10 条 JD；返回输入 job_id 的内部排序和可空标签。不得生成链接、改变人工条件或返回未输入 job_id。前端不展示这些字段。

偏好更新：接收当前画像、最近 5 条有效反馈与岗位摘要；返回正向词、负向词、关键词权重和不确定项。一次反馈不得形成永久黑名单。

## 实施前需实测

- 用户提供的 URL 是否接受本工作台 JSON 调用合同。
- 目标 Windows 环境是否可用系统凭据库与 PDF、DOCX 解析依赖。
- 真实 BOSS 返回字段与详情加载速度。
