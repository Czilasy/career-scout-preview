# AI 求职工作台：实施设计

功能规格：spec.md
状态：设计完成，待任务拆分
日期：2026-07-11

## 技术上下文

现有项目使用本地 Flask WebUI、SQLite 状态库、单工作线程和 Chrome CDP 抓取器。抓取器已支持关键词、城市、筛选、独立输出路径、详情抓取与 max-details 限制；新功能复用这些能力，不重写抓取器。

用户填写 AI 服务 URL 与 API Key。该 URL 必须指向已配置默认模型、可接受本工作台 JSON 请求的服务端点；系统不猜测模型名或修改用户填写的 URL。连接测试失败时，只有在用户已填人工关键词的情况下才能跳过 AI 继续搜索。

## 架构

浏览器工作台连接 Flask 本地服务；Flask 负责画像、简历、AI 适配、搜索编排、反馈和 SQLite 数据。单工作线程顺序调用 Chrome CDP 抓取器，每个关键词拥有独立的列表与详情输出文件。

AI 只输出受限的画像建议、关键词、JD 排序和偏好更新。程序负责人工条件优先、城市必填、60 条 JD 总预算、去重、链接校验、状态推进、产物验证、保存与撤销。

## 搜索运行

1. 用户选择画像并点击搜索。
2. 服务冻结画像与人工条件，创建父搜索运行。
3. 有人工关键词时直接使用；否则 AI 生成最多 3 个关键词。没有可用城市时要求用户选择城市。
4. 每个关键词顺序执行，并拥有独立列表与详情产物。
5. 运行跨查询去重，父运行总计最多提交 60 条岗位获取完整 JD。
6. 每获得一条 JD，AI 以每批最多 10 条进行排序；完成的岗位立刻写入并返回前端。
7. 前端轮询增量事件与新岗位，持续插入卡片，不等待全部查询结束。
8. 成功、部分成功、失败和取消均持久化；刷新页面只重新连接运行。

父运行状态为 queued、running、succeeded、partial、failed、interrupted。全部子查询有有效产物时为 succeeded，即使结果为空。有效子查询与失败或系统中断子查询并存时为 partial。用户取消始终为 interrupted，但保留此前已写入岗位。

## 前端设计

### 桌面

- 顶部细状态栏显示当前画像、开始搜索、运行状态和已发现岗位数。
- 左侧为 280 至 320 像素可折叠面板，包含画像、简历、AI URL 与 Key、可选人工筛选、收藏和投递历史入口。
- 主区是单列职位阅读流，不使用仪表盘式小卡片矩阵。
- 搜索中显示当前关键词、完成查询数、JD 数和活动指示；完成 JD 的岗位即时加入。
- 历史入口只切换结果流数据，不改变阅读布局。

### 岗位大卡片

- 卡片固定视觉高度：桌面约 280 至 320 像素，窄屏约 300 至 340 像素。
- 顶部显示岗位名称，次行显示公司、薪资与地点。
- JD 是主体文字，使用多行截断和省略号；不提供项目内详情页，不显示评分或推荐理由。
- 点击阅读区在新标签页打开经后端校验的 BOSS 链接。
- 底部有感兴趣与不感兴趣按钮，按钮不会触发跳转。
- 不感兴趣在 300 毫秒内淡出收起并提供临时撤销；感兴趣仅更新当前卡片状态并写入历史。
- 新卡片仅短距离淡入上移，不改变已展示卡片的相对顺序。

### 窄屏

- 设置面板收为抽屉，结果流始终为主要区域。
- 保留顶部搜索与运行状态。
- 单列卡片，所有触控操作至少 44 像素。
- 不依赖悬停发现功能。

## 安全与验证门

API Key 仅进入操作系统凭据库；数据库只存凭据引用和连接状态。简历、Key 和反馈不得进入任务参数、日志、CSV 或错误响应。简历删除必须删除文件、文本、文件名、哈希和未确认建议。BOSS 链接仅允许 HTTPS 及预期域名。

实现先后为：迁移与画像安全基础；AI 适配和输出校验；父子搜索运行与流式岗位；反馈与清理；前端工作台；完整自动测试与已登录 Chrome 的真实来源冒烟。每一步通过验证前不得标记后续完成。
