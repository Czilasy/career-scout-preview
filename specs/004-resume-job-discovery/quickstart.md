# Quickstart Validation Guide: 简历驱动的岗位发现

本文件是实施完成后的验收运行指南，不是当前已通过记录。任何命令只有实际执行并保存输出后才能写成“通过”。

## 1. 验收边界

### 测试范围

- 一份脱敏简历的证据提取、方向生成和一次确认。
- 多方向搜索计划、真实岗位列表和详情页。
- 硬约束三态、按方向评估、结果组合和安全解释。
- 反馈、取消、部分成功、中断恢复和简历删除。
- 桌面 1366×768 与窄屏 720px。

### 允许写入

- 临时 SQLite 数据库和临时结果目录。
- 专用测试简历目录。
- 受控的真实 E2E 结果目录。
- 不写入真实用户简历、生产状态库或非项目路径。

### 成功标准

- 自动化、迁移、黄金样本、浏览器和真实来源 E2E 各自达到 [spec.md](spec.md) 的成功标准。
- 已知硬约束违规进入推荐结果为 0。
- 高度匹配中不存在关键详情未知或未完成评估的岗位。
- 中断恢复不丢失、不重复已保存结果。
- 普通日志和响应不出现简历正文、凭据或模型原始输出。
- AI 已配置且用户同意时，分析从真实用户入口进入 queued/analyzing/ready 或明确安全失败，不出现内部组件缺失错误。
- 每项已持久化证据的安全摘录与程序生成的来源位置一致，重复或不匹配摘录不能支撑方向。
- 已接受发现运行在 5 秒内进入 planning 或显示明确调度失败；取消和恢复会真实影响未完成工作。

### 阻断标准

- 迁移破坏旧表或旧数据。
- 方向或解释引用不存在的证据。
- 文件 checkpoint 与完整输入不一致仍被恢复。
- AI 异常岗位进入高度匹配。
- 静态/模拟/smoke 被用来替代真实浏览器或真实来源 E2E。
- HTTP/运行集成测试绕过真实 provider 构建或运行调度接缝，只直接注入 fake 后宣称主流程可用。
- 运行只创建数据库记录或修改状态，没有实际提交、取消或恢复工作。
- AI 认证、超时、网络、无效输出和证据引用错误被统一吞成无从追踪的失败。

## 2. 前置条件

1. Python 3.10+ 和项目依赖已安装。
2. AI 设置使用测试凭据，且用户已同意脱敏简历发送范围。
3. 测试简历、岗位 fixture 和人工标注不含真实个人敏感信息。
4. 真实来源 E2E 使用隔离且已登录的 Chrome/CDP 配置。
5. 运行前记录数据库 schema 版本、Git commit/工作树状态和测试输入哈希。

## 3. 自动化回归

基线命令：

```powershell
python -m unittest discover -s tests -v
```

004 专项应覆盖：

```powershell
python -m unittest tests.test_candidate -v
python -m unittest tests.test_discovery -v
python -m unittest tests.test_discovery_contracts -v
python -m unittest tests.test_discovery_store -v
python -m unittest tests.test_discovery_integration -v
python -m unittest tests.test_discovery_frontend -v
python -m unittest tests.test_boss_discovery_source -v
```

预期：全部通过；测试总数和耗时以本次真实输出为准，不沿用003历史数字。

专项输出还必须证明：

1. 配置 AI、同意分析并从真实 HTTP 入口提交时，不会触发未定义 provider；分析会进入持久化状态。
2. provider 单元测试使用真实 provider 类，只替换网络传输，并覆盖两个版本化契约和安全错误映射。
3. locator 测试能够拒绝“数值在范围内但摘录不对应”、重复摘录无法消歧、敏感摘录和未知引用。
4. 运行入口提交后由真实 runtime 推进；取消后不再启动新工作，恢复会重新提交未完成项。
5. `test_discovery_contracts.py` 中分析、运行、反馈、取消/恢复场景均为真实请求断言，不存在恒真占位。

## 4. 迁移验收

使用一份 schema-version-10 的脱敏旧库副本：

1. 记录旧表名称、行数和代表性历史搜索/筛选/兴趣/垃圾桶数据。
2. 启动新版本并升级到 migration 013。
3. 再次打开数据库验证迁移幂等。
4. 确认旧行未改写为 discovery 数据。
5. 创建分析、确认、运行、搜索项、详情快照和评估。
6. 模拟重启，确认活动运行变为可恢复中断，checkpoint 保留。
7. 删除测试简历，确认派生证据/解释删除而受保护岗位/反馈保留。

## 5. 黄金样本验收

至少准备规格列出的七类脱敏简历，每份配套：

- 人工认可/拒绝的方向和依据；
- 可搜索岗位集合及相关性标签；
- 硬约束和未知项；
- 候选人证据与岗位证据；
- 合理能力缺口。

计算并保存：

- 默认方向接受率；
- Precision@20；
- 相关岗位召回率；
- 硬约束违规率；
- 多方向覆盖率；
- 解释证据忠实度。

邻近/发展型分类阈值必须根据黄金样本校准并形成新的 `policy_version`；未达到 SC-003–SC-009 时不得进入真实发布验收。

## 6. 本地浏览器验收

启动后端：

```powershell
python webui/app.py
```

打开 `http://127.0.0.1:5000`，使用 fixture/fake source 完成：

1. 默认首页只呈现“上传—确认—进度—结果”主线。
2. AI 理解页区分事实、推断、未知和用户确认。
3. 关闭方向、修改城市/最低薪资后冻结确认。
4. 运行时切换页面，状态和结果保持。
5. 验证成功、部分成功、无结果、失败、待确认、取消和恢复。
6. 查看多方向结果、安全依据、缺口、详情链接和反馈撤销。
7. 高级设置可访问，但关键词、页数和来源编码不阻断默认流程。

分别验证：

- 1366×768：信息顺序、首屏岗位可读性、主操作和进度。
- 720×768：无横向滚动，方向/分类/详情/反馈均可触达。

截图和交互记录必须标明 viewport、运行 ID 和数据来源；静态 HTML 断言不能代替这一步。

## 7. 真实来源 smoke

专用 Chrome 首次使用优先由用户本人登录。若另一个已授权的 CDP Chrome 已存在有效 BOSS 会话，可执行一次域名级会话导入：

```powershell
python scripts/boss_cdp_raw.py --import-boss-session `
  --source-cdp-port 9223 `
  --cdp-port 9222 `
  --confirm-session-import
```

安全边界：

- 源端口和目标端口必须不同，目标端口必须属于 BOSS 专用持久 profile。
- 只读取并写入 `zhipin.com` 及其子域 cookie；不复制 `Local State`、Cookies 数据库、密码或其他域名数据。
- cookie 值只在内存中存在，不进入日志、SQLite、JSON、异常文本或测试产物。
- 导入后必须通过真实登录主动探测；探测失败会回滚目标端的 BOSS cookie。
- `--copy-login-state` 已停用并在任何文件/进程操作前拒绝。
- 若 BOSS 安全验证、设备绑定会话或验证码阻断，必须由用户在浏览器中完成，不得把 cookie 存在称为登录成功。

```powershell
python scripts/boss_cdp_raw.py --check
python scripts/boss_cdp_raw.py --smoke-test
```

这里只证明 CDP、登录态和一页来源字段可用，不证明004端到端通过。

在真实来源 E2E 前，还必须使用脱敏合成简历和合成岗位输入，对当前配置的 AI 服务分别执行一次候选人分析和岗位评估契约 smoke。通过标准是结构、证据引用、来源摘录和失败映射全部合规；仅 HTTP 请求成功不算通过。记录 endpoint 基础路径、模型标识、时间和结果摘要，但不得记录 API Key、完整 prompt、完整简历或原始响应。

## 8. 真实来源端到端

推荐命令：

```powershell
python tests/fixtures/discovery/e2e_real_boss.py --close-browser-after
```

浏览器生命周期规则：若 9222 未运行，E2E 会使用固定持久 profile 自动启动专用 Chrome，并在成功、阻塞或异常退出时自动关闭；若 9222 在运行前已经存在，则默认复用且不关闭，避免误关用户窗口。正式自动化使用上面的 `--close-browser-after`，可在明确授权下连复用实例也一并关闭。关闭前必须确认端口属于 BOSS 专用 profile，优先发送 CDP `Browser.close`，超时后仅终止该专用 profile 的进程。结果文件的 `browser_lifecycle` 记录 `mode` 与 `close_status`；关闭失败会记录 `browser_close_failed` 并使命令非零退出。

使用一份脱敏测试简历和受控预算：

1. 从默认用户页面上传简历并提交 AI 同意；轮询持久化分析状态，确认通过真实 provider 获得至少两个有证据方向。
2. 完成方向确认后从默认用户页面启动发现运行；确认运行真实离开 created 并进入 planning，而非手工调用内部编排函数。
3. 验证生成多路搜索计划和完整输入哈希。
4. 获取至少两个查询/方向的真实列表，跨查询去重。
5. 获取真实详情并形成完整/部分/失效状态。
6. 验证硬约束和按方向评估，打开原始安全详情链接。
7. 标记岗位和方向反馈，再创建一次新运行验证影响范围。
8. 在列表或详情阶段从用户入口取消或制造受控中断，确认未开始工作停止；重启后从用户入口恢复并重新提交保存节点后的工作。
9. 对比恢复前后 job ID、snapshot hash、评估数量，确认无丢失/重复。

记录：

- 简历/确认/运行 ID 与输入哈希；
- 每方向搜索项数、页数、来源数、去重数、详情数；
- 五类结果计数和待确认失败码；
- 中断节点、恢复节点和重复数；
- 成功标准逐项证据。
- provider 构建、runtime 提交、首个阶段事件、取消信号、恢复提交和每类安全 AI 失败的证据。

## 9. 隐私与删除验收

1. 在测试简历中放入可识别的虚构敏感标记。
2. 检查普通日志、HTTP 响应、结果卡片、运行事件和错误消息，命中数必须为0。
3. 删除简历，确认源文件、提取文本、证据、候选人模型、方向和解释不可再读取。
4. 确认岗位身份、感兴趣/垃圾桶和显式反馈仍可见，但历史解释显示不可用。
