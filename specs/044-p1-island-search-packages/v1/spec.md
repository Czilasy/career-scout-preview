# Feature Specification: P1 灵动岛分析态修复与常用搜索配置包

**Feature Branch**: `codex/spec/saved-search-packages`

**Created**: 2026-09-21

**Status**: Frozen — Implemented in working tree; verification pending

**Input**: 本 SPEC 统一承载 Bug 单当前两个 P1：修复灵动岛“分析中”状态的胶囊宽度和状态点显示；增加可显式保存并从第一页直接复用的常用搜索配置包。

## 冻结依据

### A 组：用户原话与已确认边界

- 简历分析期间，灵动岛切到“分析中”状态后，胶囊宽度必须立即按当前内容重新测量，不能沿用前一状态的空壳宽度。
- “分析中”状态点必须可见，并与抓取、JD、精筛等运行状态可区分。
- 保存对象是一次已经形成的通用搜索身份，而不是某个平台的搜索配置。
- 配置包只保存关键词、城市、简历画像及画像背后的相关内容和结构化数据。
- 第三页筛选条件不进入配置包。
- 配置包支持多套并列存在，不保留同一配置包的历史修订或回滚版本。
- 只有用户在第二页主动点击保存才落库，不自动生成配置包。
- 用户从已有配置包进入并修改后，再次保存也创建新包；原配置包保持不变，由用户自行删除。
- 配置包名称由系统生成默认值，用户可以修改。
- 第一页显示一个小型“使用已有配置”按钮，并与“跳过简历，直接手动搜索”并排；点击后弹出较大的配置包选择框并展示全部配置包。
- 点击有效配置包后立即进入第二页，回填保存内容；不上传简历、不重新执行 AI 分析，也不自动开始搜索。
- 配置包选择成功和保存成功均沿现有灵动岛通知链给出简短成功提示。
- 重命名和删除位于配置包选择框内；删除前必须二次确认。
- 配置包校验失败时不进入第二页，灵动岛以红点加错误信息报告失败。

### B 组：AI 推断与补充

- 无新增产品规则。未被 A 组确认的页面文案、排序方式、数量上限、存储方案与接口形态留待 Plan 决定，不在本 SPEC 中冻结。

## Clarifications

### Session 2026-09-21

- Q: 配置包是否按平台拆分？ → A: 不拆分；关键词、城市和画像是 BOSS 与智联共用的通用版本。
- Q: 多版本是并列配置还是同一配置的历史版本？ → A: 多套并列配置，不做历史回滚。
- Q: 配置包何时生成？ → A: 仅在第二页由用户主动点击保存时生成新的独立配置包。
- Q: 配置包保存哪些内容？ → A: 保存关键词、城市、画像及画像背后的数据，不保存第三页筛选条件。
- Q: 新一轮从哪里复用？ → A: 第一页的小按钮打开配置包选择框，点击包后进入第二页并回填。
- Q: 加载失败如何处理？ → A: 留在第一页，灵动岛显示红点和错误信息。
- Q: 删除如何处理？ → A: 在配置包选择框内删除，删除前二次确认。

- P1 第二项：B100 常用搜索配置包；其中 Bug 单旧描述与本次对话冲突的字段范围、平台拆分和失效处理，全部以本 SPEC 上述确认结果为准。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在第二页保存当前搜索身份 (Priority: P1)

用户第一次完成简历分析并在第二页准备好关键词、城市和简历画像后，可以主动把这套内容保存成一个配置包，以便下一轮直接复用。系统不会因为进入第二页、完成分析或开始搜索而自动保存。

**Why this priority**: 没有可靠的配置包，下一轮仍然要重复上传简历、等待分析并重新填写内容，功能目标无法成立。

**Independent Test**: 在第二页准备关键词、城市和画像后点击保存，结束当前流程并开始新一轮，确认第一页能找到该配置包；未点击保存的另一套临时内容不会出现在列表中。

**Acceptance Scenarios**:

1. **Given** 用户在第二页已有关键词、城市、画像及其背后数据，**When** 用户首次点击保存，**Then** 系统创建一套新的配置包并使其可从第一页选择。
2. **Given** 用户只填写或修改了第二页内容但没有点击保存，**When** 用户离开当前流程并开始新一轮，**Then** 系统不得自动创建配置包。
3. **Given** 用户由某个已有配置包进入第二页并修改内容，**When** 用户点击保存，**Then** 系统创建一套独立并列的新配置包，原配置包保持不变。
4. **Given** 用户连续保存两次，**When** 两次保存均成功，**Then** 系统保留两套独立配置包，用户可以在配置包选择框中自行删除旧包。
5. **Given** 用户点击保存，**When** 保存界面出现，**Then** 系统在居中的小型命名弹窗中提供可编辑的默认名称，用户无需从空白开始命名。
6. **Given** 用户确认保存成功，**When** 新配置包创建完成，**Then** 灵动岛提示“已保存常用配置”。

---

### User Story 2 - 从第一页选择配置包开始新一轮 (Priority: P1)

用户开始新一轮时，在第一页点击一个小入口按钮即可打开配置包选择框。用户选择某个配置包后，系统立即进入第二页并恢复关键词、城市、简历画像及画像背后的数据。用户不需要重新上传简历或等待 AI 分析，可以检查、修改后再主动开始搜索。

**Why this priority**: 这是功能直接解决的核心问题——把重复准备搜索身份的操作缩减为从第一页选择一次配置包。

**Independent Test**: 预先保存一套配置包，开始新一轮后从第一页打开选择框并点击该包，确认直接进入第二页、所有纳入范围的内容准确回填、没有出现简历上传或 AI 分析步骤，也没有自动开始搜索。

**Acceptance Scenarios**:

1. **Given** 用户拥有至少一套已保存配置包并处于新一轮第一页，**When** 用户点击配置包入口，**Then** 系统弹出配置包选择框并展示全部已保存配置包。
2. **Given** 配置包有效，**When** 用户点击该配置包，**Then** 系统立即进入第二页并准确回填关键词、城市、画像及画像背后的数据。
3. **Given** 用户通过配置包进入第二页，**When** 页面完成回填，**Then** 用户无需上传简历或重新执行 AI 分析，并且搜索不会自动启动。
4. **Given** 同一配置包曾用于 BOSS，**When** 用户在智联的新一轮中选择该包，**Then** 系统仍使用同一套关键词、城市和画像内容，不要求平台专属副本。
5. **Given** 配置包中没有第三页筛选条件，**When** 用户通过该包进入第二页并继续后续流程，**Then** 系统不从配置包恢复旧的第三页筛选条件。
6. **Given** 配置包完整载入，**When** 页面进入第二页，**Then** 灵动岛提示“已使用常用配置”。

---

### User Story 3 - 在选择框内管理配置包 (Priority: P2)

用户可以在第一页打开的配置包选择框中重命名或删除配置包。删除属于不可轻率执行的操作，必须先让用户确认。

**Why this priority**: 多套并列配置需要基本管理能力，否则名称变化和废弃配置会让列表越来越难以辨认。

**Independent Test**: 在配置包选择框中重命名一套配置并删除另一套配置，确认新名称可见；删除必须经过确认，取消确认不会删除。

**Acceptance Scenarios**:

1. **Given** 配置包选择框已打开，**When** 用户重命名某个配置包，**Then** 列表显示新名称，配置包内容不变。
2. **Given** 用户对某个配置包执行删除，**When** 二次确认尚未完成，**Then** 配置包仍然存在。
3. **Given** 用户确认删除，**When** 删除完成，**Then** 该配置包不再出现在选择列表中，其它配置包不受影响。

---

### User Story 4 - 配置包无法使用时明确报错 (Priority: P2)

配置包通常可以直接使用；如果加载或校验确实失败，系统不进入第二页、不部分回填，也不静默改写内容，而是在灵动岛用红点和简短错误信息告诉用户。

**Why this priority**: 即使这是低频异常，也必须避免用户误以为已经使用了完整配置包并带着错误身份继续搜索。

**Independent Test**: 构造一套无法完整加载的配置包并从第一页选择，确认页面留在第一页、第二页未被部分覆盖，灵动岛出现红点和可读错误信息。

**Acceptance Scenarios**:

1. **Given** 配置包无法完整加载或校验失败，**When** 用户点击该包，**Then** 系统留在第一页且不改变第二页现有内容。
2. **Given** 配置包选择失败，**When** 系统报告错误，**Then** 灵动岛显示红点及用户可理解的错误信息。
3. **Given** 配置包只有部分内容可读取，**When** 用户点击该包，**Then** 系统不得部分应用或静默修补，整次选择按失败处理。

---

### User Story 5 - 灵动岛“分析中”状态正确显示 (Priority: P1)

用户上传简历并开始分析后，灵动岛立即收缩或展开到适合“分析中”文案的宽度，左侧状态点清晰可见；分析完成并切换状态后，胶囊继续按新内容正常测量。

**Why this priority**: 这是当前可稳定复现的 P1 界面缺陷，直接造成顶栏出现半条空白胶囊和不可见状态点。

**Independent Test**: 从非分析状态进入“分析中”，确认内容键变化会触发宽度重测、文案不顶边、状态点有明确颜色；再退出分析状态，确认后续宽度仍正确。

**Acceptance Scenarios**:

1. **Given** 灵动岛当前处于任一其它状态，**When** 简历分析开始并切到“分析中”，**Then** 胶囊立即按“分析中”内容重新测量宽度。
2. **Given** 灵动岛处于“分析中”，**When** 用户查看状态点，**Then** 状态点清晰可见且与抓取、JD 和精筛状态可区分。
3. **Given** 简历分析结束，**When** 灵动岛切换到后续状态，**Then** 胶囊继续按后续内容正常测量，不残留分析态宽度。

### Edge Cases

- 用户取消保存时，不创建配置包，也不修改已有配置包。
- 用户取消删除确认时，配置包及其内容保持不变。
- 用户重命名配置包时，只改变展示名称，不改变关键词、城市或画像内容。
- 用户加载配置包后修改第二页内容但未保存时，只影响当前新一轮，不反向改写配置包。
- 配置包加载失败时采用全有或全无语义，不允许只恢复关键词或城市后继续。
- 从任一长文案状态切入或离开“分析中”时，都必须重新测量胶囊宽度。
- 用户启用减少动态效果时，状态点仍必须通过静态颜色可见，不依赖呼吸动画表达状态。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 仅在用户于第二页明确执行“保存为常用配置”时持久化配置包；任何页面进入、分析完成或搜索启动事件均不得自动创建配置包。
- **FR-002**: 每个配置包 MUST 保存该次操作确认的关键词、城市、简历画像文本，以及无需重新分析即可完整恢复该画像所需的背后数据。
- **FR-003**: 配置包 MUST NOT 保存或恢复第三页筛选条件。
- **FR-004**: 系统 MUST 支持多套并列配置包；配置包之间相互独立，且不提供同一配置包的历史版本或回滚链。
- **FR-005**: 每次保存时，系统 MUST 提供可编辑的默认名称；用户 MUST 能修改配置包名称。
- **FR-005a**: 命名交互 MUST 使用不撑开第二页卡片的居中小型弹窗；保存按钮 MUST 保持紧凑。
- **FR-006**: 每次保存 MUST 创建一个新的配置包并保留已有配置包；系统 MUST NOT 提供或调用当前包更新接口。
- **FR-007**: 第一页 MUST 提供一个小型配置包入口；点击后 MUST 打开能够展示全部已保存配置包的选择框。
- **FR-008**: 用户点击有效配置包后，系统 MUST 直接进入第二页并准确回填 FR-002 规定的全部内容。
- **FR-009**: 通过配置包进入第二页的流程 MUST 跳过简历上传和 AI 分析，且 MUST NOT 自动启动搜索；用户可以先检查或修改内容。
- **FR-010**: 同一配置包 MUST 能在 BOSS 与智联的新一轮流程中共用，不得按平台复制或拆分关键词、城市与画像数据。
- **FR-011**: 用户 MUST 能在配置包选择框内重命名和删除配置包；删除 MUST 在用户二次确认后才生效。
- **FR-012**: 配置包加载或完整性校验失败时，系统 MUST 留在第一页、不得部分应用，并 MUST 通过灵动岛以红点加错误信息报告失败。
- **FR-013**: 用户加载配置包后对第二页所做的未保存修改 MUST 只属于当前轮，不得反向修改原配置包。
- **FR-014**: 灵动岛“分析中”状态 MUST 拥有独立且稳定的内容身份，使进入和离开该状态都会触发宽度重测。
- **FR-015**: 灵动岛“分析中”状态点 MUST 具有明确可见的颜色，并与抓取、JD 抓取和精筛状态可辨。
- **FR-016**: “分析中”状态的宽度重测与状态点样式 MUST 有自动测试覆盖。
- **FR-017**: 第一页配置包入口 MUST 显示为“使用已有配置”，并与跳过简历入口保持同一行。
- **FR-018**: 配置包成功载入和成功保存 MUST 分别通过现有灵动岛通知链提示“已使用常用配置”和“已保存常用配置”。

### Key Entities

- **搜索配置包**：一套可在新一轮复用的通用搜索身份，包含唯一身份、展示名称、关键词、城市、简历画像文本和画像背后数据；不包含平台专属副本或第三页筛选条件。
- **已载入配置包**：用户从第一页选中并载入第二页的配置包；仅用于回填当前页面，不改变后续保存始终创建新包的语义。
- **配置包选择结果**：一次从第一页选择配置包的完整结果；只允许“全部加载成功并进入第二页”或“加载失败并留在第一页”两种状态。
- **灵动岛分析中态**：简历分析执行期间的顶栏状态，拥有独立内容键、当前文案所需宽度和可见状态点样式。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在已有配置包的前提下，开始新一轮时只需打开一次选择框并点击一次配置包，即可到达已完整回填的第二页；简历上传次数与 AI 分析次数均为 0。
- **SC-002**: 对每套成功保存并重新载入的配置包，关键词、城市、画像文本和画像背后数据的恢复一致率为 100%。
- **SC-003**: 通过配置包开始的新一轮中，第三页旧筛选条件的恢复数量为 0，平台专属配置副本的创建数量为 0。
- **SC-004**: 未主动点击保存的第二页内容自动生成配置包的次数为 0；每次主动保存都生成独立新包，旧包不被覆盖。
- **SC-005**: 每次配置包加载失败均留在第一页、不会部分覆盖第二页，并在灵动岛显示红点和错误信息，覆盖率为 100%。
- **SC-006**: 每次删除都必须经过二次确认；用户取消确认时配置包被删除的次数为 0。
- **SC-007**: 每次进入或离开“分析中”状态均触发正确的内容宽度更新，文案顶边和半条空白胶囊复现次数为 0。
- **SC-008**: “分析中”状态点在正常动效与减少动态模式下均可见，自动测试覆盖率为 100%。

## Verification Scope *(mandatory)*

- 开发、调试和返修阶段只运行聚焦测试、原失败用例和直接受影响的必要相邻回归；禁止每次修改或每个子批次机械运行后端全量。
- 本 SPEC 的两个 P1 视为一条交付链；全部收敛后才运行一次干净的后端全量、前端测试、`npm run build` 和仓库卫生检查。
- 全量失败后保存失败清单，先只重跑失败用例与受影响范围；没有相关改动不得重跑全量。修复并重新收敛后才允许下一次最终全量确认。
- 收口发布任务默认只做卫生测试、hooks、`git diff --check`、`git status` 和 `scripts/release_check.ps1`（若存在）；不自动要求全量测试。
- 只有用户明确要求“全量/全部测试/完整验证”时，收口任务才执行全量测试。

## Assumptions

- 现有第二页对关键词、城市和画像的有效性要求保持不变；本功能不改变这些业务校验。
- 现有“开始新一轮”、活动任务和现场保护规则保持不变；配置包入口只在允许开始新一轮的场景中工作。
- 配置包默认名称可由当前关键词和城市形成，具体文案、截断与重名展示规则由 Plan 决定，不改变用户可编辑名称的冻结要求。
- 配置包数量上限与列表排序未由用户指定，属于 Plan 阶段的实现细节；入口、保存按钮和成功提示文案已按本轮确认固定。
- 本版本不增加配置包导入、导出、云同步、共享或历史回滚能力。
- 灵动岛修复只处理“分析中”内容键、宽度重测和状态点颜色，不重做灵动岛布局、动画系统或通知模型。

## Out of Scope

- 保存或恢复第三页筛选条件。
- 为 BOSS、智联分别维护配置包副本。
- 自动保存、自动创建配置包或自动启动搜索。
- 当前配置包更新、另存为等两套保存语义；保存统一按新包处理。
- 保存同一配置包的修订历史、比较版本或恢复旧版本。
- 配置包导入、导出、跨设备同步或多人共享。
- 灵动岛整体改版、其它状态视觉重设计或新的通知类型。
