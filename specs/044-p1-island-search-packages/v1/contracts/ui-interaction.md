# UI Contract: 常用搜索配置包

## 第一页入口与选择框

- 第一页上传区显示小型“使用已有配置”入口，并与“跳过简历，直接手动搜索”并排展示。
- 点击后请求 `GET /api/search-packages` 并打开较大的选择框。
- 列表展示全部配置包的名称；无包时显示空状态，不诱导自动创建。
- 点击列表项后请求完整包，校验成功才应用并进入第二页。

## 原子应用顺序

1. 在局部变量中验证 `payloadVersion`、keywords、city、profile 全部存在且类型正确。
2. 生成一个完整的第二页草稿投影。
3. 同步写入关键词、已选关键词、自定义关键词、城市、自定义城市、画像摘要与 `profileFacts`。
4. 写入现有共享第二页草稿槽，记录 `currentPackageId` 与名称。
5. 最后调用现有步骤切换进入第二页。
6. 成功后通过现有灵动岛通知链提示“已使用常用配置”。

任何一步在提交前失败：不写字段、不切页。提交期间出现异常：恢复应用前快照并停留第一页。

## 第二页保存动作

- 无论是否从配置包进入，第二页只展示“保存为常用配置”一个按钮。
- 保存按钮保持紧凑，不撑开第二页卡片；点击后打开居中的小型命名弹窗。
- 每次点击都 POST 创建一套新的并列配置包，原包不变；新包成功后成为列表中最新一项。
- 保存成功后通过现有灵动岛通知链提示“已保存常用配置”。
- 页面不展示当前配置名称，也不提供“更新常用配置”或“另存为”入口。
- 取消命名对话不发请求。
- 编辑第二页但未点击保存，不写配置包 API。

## 管理动作

- 重命名位于选择框内，PATCH 成功后就地更新列表。
- 删除位于选择框内，必须先出现确认；取消不发 DELETE。
- 删除已载入包后，当前轮已回填内容不被清空；后续“保存”仍创建新包。

## 错误通知

- 列表加载失败：选择框保留可重试状态，发 error notice。
- 单包加载/校验失败：`activeStep` 必须仍为第一页，第二页数据不得变化，发 error notice。
- notice 由现有 App 转入 Dynamic Island；tone 为 `error`，由现有样式呈现红色标记与消息。
- 保存、重命名、删除失败：保持原数据和可重试状态，发 error notice。

## Explicit Exclusions

- 选择包不运行 `analyzeResume`。
- 选择包不调用开始搜索/抓取动作。
- 应用包不写 `filterValues`，不恢复第三页状态。
- 选择框不按平台过滤、分组或复制包。
