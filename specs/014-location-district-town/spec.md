# 功能规格：搜索地点支持区/镇（BOSS 区/商圈/镇 + 智联区/县）

**功能目录**：`014-location-district-town`

**创建日期**：2026-08-16

**状态**：已冻结（2026-08-16；grill-me 边界确认 + A/B 需求清单逐条确认后进入 Spec）

**输入**：用户确认的 B054 冻结需求清单 A/B。

## 用户场景与测试

### 用户故事 1 - 在城市小方块内选择区/镇（优先级：P1）

用户确认城市后，点击“关键词 × 城市”里的城市小方块，在其下方展开区/镇选择面板，按平台选择区/县（智联）或区 → 商圈/镇（BOSS）。选中后小方块显示“上海 · 浦东新区”或“益阳 · 赫山区”这样的完整地点；小方块外观保持现有样式，x 仍然删除整个城市，删除地点在面板内清空。

**优先原因**：这是 B054 的核心能力，用户需要把搜索范围从城市收窄到区/镇，且不改变现有页面布局和小方块样式。

**独立测试**：构造已确认城市草稿，点击城市小方块展开面板，完成区/镇选择后断言小方块文字与提交条件都变成完整地点。

**验收场景**：

1. **假如** 用户已添加“上海”城市小方块，**当** 点击小方块，**那么** 在小方块下方展开“区 → 商圈/镇”级联选择面板，页面其余布局不变。
2. **假如** 用户选择“浦东新区”，**当** 确认选择，**那么** 小方块显示“上海 · 浦东新区”，x 仍删除整个城市。
3. **假如** 用户想清空地点，**当** 重新点击小方块并在面板内清空，**那么** 小方块恢复为“上海”，搜索条件回到城市级。
4. **假如** 用户选择“智联”，**当** 展开小方块，**那么** 只提供“区/县”一级选择，不出现 BOSS 商圈/镇。
5. **假如** 城市没有区/镇数据，**当** 点击小方块，**那么** 显示“暂无区/镇数据，按城市级搜索”，不阻断任务。

---

### 用户故事 2 - 多城市 + 多区独立组合（优先级：P1）

多个城市可以同时存在，每个城市独立配置自己的区/镇；同一城市下可多选区，每个“城市 + 区”都是一个独立搜索组合，各自使用每组合页数。任务范围预览、页数计算、任务规模、进度事件和历史展示都按这个组合规则工作，并显示完整地点。

**优先原因**：现有任务范围已经按“关键词 × 城市”组合计数，地点扩展必须保持计数和进度可预测，不能悄悄改变用户已有搜索习惯。

**独立测试**：构造 1 个关键词 × 1 个城市 × 3 个区 × 每区 3 页，断言任务预览为 9 页、任务规模正确，进度事件按组合展示完整地点。

**验收场景**：

1. **假如** 用户添加“上海、北京”两个城市，**当** 分别为它们选择区/镇，**那么** 每个城市的地点独立保存，互不串用。
2. **假如** 用户在上海下选择“浦东新区、徐汇区”两个区，**当** 确认搜索范围，**那么** 系统按两个独立组合执行，不把两个区硬塞进一次平台请求。
3. **假如** 1 个关键词 × 上海 3 个区 × 每区 3 页，**当** 查看范围预览，**那么** 计划页数为 9 页，超出上限时给出明确提示且不自动截断。
4. **假如** 任务开始，**当** 查看进度和历史，**那么** 城市位置统一显示“城市 · 区”，后端保存结构化字段。

---

### 用户故事 3 - 旧任务、无数据与平台切换兼容（优先级：P2）

没有区字段的旧草稿和历史任务保持城市级搜索原样恢复，不自动补区；区码表缺失或加载失败时允许按城市级搜索；切换平台时城市文本保留，区/镇按平台独立保存，不跨平台套用码值。

**优先原因**：功能不能破坏已有用户数据，也不能在平台或数据异常时把任务卡死。

**独立测试**：构造旧任务、无区数据城市、平台切换三类场景，断言均按城市级或独立平台状态正确工作。

**验收场景**：

1. **假如** 旧草稿只有“上海”，**当** 打开草稿，**那么** 仍按“上海”城市级显示和搜索，不出现地点面板强填。
2. **假如** 某城市区码表缺失，**当** 确认搜索，**那么** 按城市级执行并提示“暂无区/镇数据，按城市级搜索”。
3. **假如** 用户在 BOSS 选择“上海 · 浦东新区”，**当** 切换到智联，**那么** 城市“上海”保留，BOSS 区选择不带到智联，智联按自己的区/县数据重新选择。
4. **假如** 历史任务没有地点字段，**当** 查看历史详情，**那么** 展示原城市级范围，不新增地点。

## 边界情况

- 城市小方块只新增“可点击展开”行为，现有外观、x 删除语义和整体布局不变。
- 全国范围与区/镇互斥：选择全国时不提供区/镇选择。
- 区/镇必须属于所选城市；后端校验从属关系，非法组合给出中文错误并阻止启动。
- 无区数据或码表加载失败：按城市级搜索并提示，不阻断。
- 组合页数超过现有 200 页上限：明确提示，不自动截断、不静默降级。
- CLI 不新增公开参数；地点参数只做底层透传，供 Web 工作台调用。
- 旧草稿和历史任务没有地点字段时保持原样，不自动补区。

## 需求

### 功能需求

- **FR-001**：BOSS 支持“区 → 商圈/镇”两级地点，智联支持“区/县”一级地点。
- **FR-002**：城市小方块保持现有样式，点击后在其下方展开地点选择面板；选中后小方块显示“城市 · 区”完整地点。
- **FR-003**：x 仍删除整个城市及其已选地点；地点单独清空只能在展开面板内完成。
- **FR-004**：多城市保留，每个城市独立保存自己的区/镇选择。
- **FR-005**：同一城市下支持多区；每个“城市 + 区”独立作为搜索组合。
- **FR-006**：区可单独作为最终条件；BOSS 商圈/镇是可选下级，不选下级时按整个区搜索。
- **FR-007**：每个“城市 + 区”组合使用各自每组合页数，任务页数、规模和进度按组合计算。
- **FR-008**：前端使用“城市 → 区 → 商圈/镇”级联选择，不允许手输区名；后端校验从属关系。
- **FR-009**：城市无区数据或码表加载失败时，按城市级搜索并给出提示，不阻断任务。
- **FR-010**：区/镇码表以静态 JSON 为主，运行时拉取平台接口兜底。
- **FR-011**：CLI 只做底层地点参数透传，不新增公开命令参数。
- **FR-012**：旧草稿和历史任务没有地点字段时保持原样，不自动补区。
- **FR-013**：切换平台时城市文本保留，区/镇按平台独立保存，不跨平台套用码值。
- **FR-014**：任务范围预览、进度事件、历史详情和结果展示统一显示“城市 · 区”完整地点。
- **FR-015**：任务范围快照保存结构化地点字段，不把拼接文本冒充数据。
- **FR-016**：组合页数超过上限时给出明确提示，不自动截断。
- **FR-017**：验收必须包含 BOSS/智联真实浏览器冒烟，确认区级条件真实生效。

### 关键实体

- **地点条件**：平台、城市名/码、区/县名/码、商圈/镇名/码、选择层级；同一城市下可多个。
- **区/镇码表**：BOSS 区/商圈/镇目录与智联区/县目录，静态 JSON + 运行时刷新兜底。
- **搜索组合**：关键词 × 城市 × 区；每个组合独立翻页、进度和任务规模。
- **任务范围快照**：冻结的关键词、城市、地点条件、每组合页数、组合数与摘要；版本升级后旧快照兼容。
- **展示标签**：由结构化地点条件生成的“城市 · 区”文本，用于前端展示与历史回显。

## 假设

- 已查证：BOSS `businessDistrict.json?cityCode=` 返回区 → 商圈/镇两级；智联 `base/data` 返回 `allCity`/`hotCity` 及区/县子级，区/县通过把 `S_SOU_WORK_CITY` 换成区县码实现。
- 多区通过“每区独立搜索组合”实现，不依赖平台单次请求支持多区；智联平台 UI 本身为单选，拆分后仍可在产品层实现多区。
- 本轮不新增数据库表；地点字段随任务范围快照/脚本参数结构化扩展，旧任务按无地点处理。
- 本轮不新增公开 CLI 参数、不修改桌面版打包流程。
- 城市码表沿用现有静态 + 运行时兜底策略；新增区/镇静态文件进入 `data/` 目录。
