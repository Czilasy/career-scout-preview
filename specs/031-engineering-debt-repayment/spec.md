**Feature Branch**: `031-engineering-debt-repayment`

**Created**: 2026-08-30

**Status**: Draft

**Input**: User description: "深度审查发现的全后端问题全部修进一个 spec：①改旧改错（README/AGENTS 失真、说明文字错位、提示语统一、镜像地址暴露、死配置）；②主文件松绑（23 处反向 import 清零）；③错误留证据（79 处静默吞异常+日志统一+防回潮基线）；④爬虫自管（132 处门面回溯替换）；⑤宪法红线超限文件拆分；⑥事故代码退场（990 行迁手动工具+撤 3 接口）；⑦前端理线（类型豁口清零+发现逻辑问题当场修，样式像素级不变）；⑧测试打桩收尾（隔空改主文件的后门拆除）。全部行为保持重构，验收三道保险。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 文档与暴露面失真清零 (Priority: P1)

项目主人打开 README、AGENTS.md 和 GitHub 公开文件时，看到的内容与事实一致：版本号不再自相矛盾、"超大文件"清单指向真实的超大文件、公开文本里没有自己服务器的地址和 root 账号入口、没有没人用的死配置文件。治理规则（宪法）对贡献者可见。

**Why this priority**: 失真文档会持续误导后续每一次开发决策（021 拆分完成后规则文件仍指向旧大文件，已经发生过）；暴露面是安全问题，修复成本低。

**Independent Test**: 逐项核对文档陈述与仓库实测（版本号、文件行数、公开文本 grep 服务器地址）——不依赖其他故事即可完成验收。

**Acceptance Scenarios**:

1. **Given** 仓库当前真实版本为 v1.8.3，**When** 阅读 README，**Then** 标题与"最新正式版"描述指向一致的事实，不再出现标题 1.8.3 / 正文 1.8.1 的矛盾。
2. **Given** 实测超大文件清单（Python >800 行、Vue >1200 行），**When** 阅读 AGENTS.md 的超大文件小节，**Then** 清单与实测一致（指向 historical_recovery / zhilian_cdp_raw / task_runners 等真实大文件），不再指向三个已拆完的文件。
3. **Given** 公开仓库全部文本文件，**When** 按服务器地址模式检索，**Then** 镜像服务器 IP 与 root 登录串出现次数为 0；发布流程通过加密配置注入地址与账号。
4. **Given** 发布脚本与流水线，**When** 以非 root 部署账号运行镜像同步，**Then** 全流程可用（部署用户名可配置，不再写死 root）。
5. **Given** 仓库中无人引用的配置文件（sonar 残留、残留测试配置段、未使用的覆盖率依赖），**When** 检查仓库，**Then** 已被清除，不再误导"已接入质量平台"的判断。
6. **Given** 治理规则文件（宪法），**When** 检查 git 跟踪清单，**Then** 宪法文件被跟踪且通过凭据/本地路径卫生检查；历史工单目录维持本地不入库。
7. **Given** 前端构建产物的凭据扫描豁免，**When** 卫生测试执行，**Then** 构建产物的文本内容不再被整体豁免（至少覆盖密钥类模式）。

### User Story 2 - 主文件松绑，反向依赖清零 (Priority: P1)

后端 14 个模块、23 处引用不再回头 import 主文件 app.py 拿共享常量和纯函数——这些公共内容落位到独立的共享模块；同一条"任务不存在"提示语只剩一处定义、一份文案；路由注册方式只剩一种。主文件瘦身为纯装配入口，此后新功能不再把它越缠越紧。

**Why this priority**: 这是所有后续维护的源头性债务——每一个新功能都在加深反向依赖；且两份提示语已经产生实际文案漂移。

**Independent Test**: 检索 `from webui.app import` 在 webui/scripts 下（除 app.py 自身与兼容 re-export 块）的结果为 0；全仓 `_MSG_TASK_NOT_FOUND` 只有一处定义；路由注册模式只有一种。

**Acceptance Scenarios**:

1. **Given** 修好后的代码库，**When** 在 webui/ 与 scripts/ 检索对主文件的反向导入，**Then** 除主文件自身和兼容 re-export 外结果为 0（含 4 处带"避免循环"注释的延迟导入）。
2. **Given** 共享常量与纯函数（提示语、操作错误族、日志行数、公开任务状态投影等），**When** 查找它们的定义位置，**Then** 全部落位在独立共享模块，主文件只保留兼容 re-export 一层。
3. **Given** "任务不存在"提示语，**When** 全仓检索定义，**Then** 只有一处，文案为"任务不存在或已被移除"；原来用短文案的 7 处接口响应随之生效（唯一许可的用户可见文字变化）。
4. **Given** task_status.py 中说明文字写错位置的函数，**When** 查看该函数，**Then** 说明文字位于函数体首行正常生效，import 语句位于其后。
5. **Given** 路由注册，**When** 检查全部路由域模块，**Then** 只存在一种注册模式，两种模式并存的现状消失。
6. **Given** 宪法「模块地图」小节，**When** 本故事交付，**Then** 新增/变更模块已在地图登记（路径+一句话职责）。

### User Story 3 - 出错必有留痕，且不会回潮 (Priority: P1)

程序里 79 处"出错就悄悄咽掉"的位置全部处理完毕：该转为显式错误返回的转显式返回、该记日志的记日志、纯清理类的豁免并注明理由。后端业务模块统一走一套日志配置，排查问题时证据可查。自动检查守住底线：静默吞噬数量只许下降，回潮即测试失败。

**Why this priority**: 运维可见性是本轮全部工作的"保险丝"——后续两个大批次（拆分、打桩迁移）期间任何异常都必须能被发现，所以它必须先于拆分类故事就位。

**Independent Test**: 用 AST 统计脚本复核 pass-only 吞异常计数 ≤ 基线且白名单逐条附理由；抽查任一处理点确认留痕路径真实可达。

**Acceptance Scenarios**:

1. **Given** 修好后的 webui/ 与 scripts/，**When** 以 AST 口径统计"纯 pass 吞异常"，**Then** 数量 ≤ 卫生测试基线，且白名单逐条附"为何可吞"的注释。
2. **Given** 一处会影响任务结果的失败，**When** 异常被捕获，**Then** 留痕出现在日志或既有任务日志通道，不再无声消失。
3. **Given** 后端业务模块，**When** 检索散装 print 输出，**Then** 业务模块内为 0（命令行脚本 stdout 不受限）。
4. **Given** 卫生测试套件，**When** 有人新增一处纯 pass 吞异常，**When** 测试运行，**Then** 失败并指出新增位置。
5. **Given** 桌面更新器的状态目录环境变量，**When** 运行更新器测试，**Then** 该变量存在真实用例覆盖（不再是 0 覆盖）。

### User Story 4 - 爬虫模块自己管自己 (Priority: P2)

scripts/boss 包内 20 个文件、132 处"回头找老门面拿会话状态"的引用全部替换：会话状态由爬虫包内独立的 runtime 模块持有，子模块单向依赖它；老文件退化为纯兼容门面。爬虫包从此可以独立理解、独立测试。

**Why this priority**: 与故事 2 同源（物理拆分未解耦），但波及面集中在爬虫层，且该层是缺陷高发区、类型标注最薄的区域。

**Independent Test**: 检索 scripts/boss 子模块中对门面回溯助手的调用为 0；boss 包在无门面参与下可独立 import 并通过其聚焦测试。

**Acceptance Scenarios**:

1. **Given** scripts/boss 全部子模块，**When** 检索门面回溯调用，**Then** 为 0（132 处全部替换）。
2. **Given** 会话状态（网络会话、活动标志等），**When** 查找持有者，**Then** 是爬虫包内的 runtime 模块，而非老门面的模块级全局。
3. **Given** 老门面文件 scripts/boss_cdp_raw.py，**When** 检查其内容，**Then** 仅剩兼容 re-export 与 CLI 入口，无业务逻辑。
4. **Given** 既有爬虫聚焦测试，**When** 本故事交付，**Then** 全部通过且断言未因搬家而放松。

### User Story 5 - 宪法红线归位 (Priority: P2)

踩着宪法红线（Python ≤800 行、Vue ≤1200 行）的文件全部拆分归位：智联抓取单体（900 行）、任务运行编排（864 行）各自按职责拆为内聚模块；前端核心页面（1249 行）瘦回红线内。原入口保留兼容导出，只搬代码、不改行为。

**Why this priority**: 红线长期失效会让"超限拆分必须单独立项"的规矩变成空文；这三个文件此前从未进过任何拆分计划，是"修完不再生 spec"承诺的最后一块。

**Independent Test**: 行数统计：被拆文件 ≤ 宪法上限；拆分后跑后端全量测试与前端测试全绿；原入口旧 import 路径全部可用。

**Acceptance Scenarios**:

1. **Given** 拆分后的智联抓取模块，**When** 统计行数，**Then** 新模块均 ≤800 行且原入口 re-export 兼容旧引用。
2. **Given** 拆分后的任务运行编排模块，**When** 统计行数，**Then** 同上。
3. **Given** 前端核心页面组件，**When** 统计行数，**Then** ≤1200 行，页面渲染结果与拆分前像素级一致。
4. **Given** 每个拆分批次，**When** 交付验证，**Then** 聚焦测试+后端全量测试+前端测试+构建全部通过。

### User Story 6 - 事故代码退出生产前门 (Priority: P2)

2026-07-28 事故的 990 行修复代码整体迁出生产 API 面，落位为需要时手动运行的工具；3 条 recovery 接口从路由表删除；"接口收 run_id 却无视之"的占位设计随之消失。

**Why this priority**: 一次性事故代码常驻生产接口面是无谓的攻击面与维护负担；但它是既有规格（FR-041）产物，迁出需保持能力可手动复用，排在结构类故事之后。

**Independent Test**: 路由表中无 /api/recovery/*；手动工具针对测试库执行预演可用；相关测试改为直接调用工具层且全绿。

**Acceptance Scenarios**:

1. **Given** 修好后的应用，**When** 请求 /api/recovery/preview、/prepare、/execute，**Then** 路由不存在（404），生产 API 面无恢复入口。
2. **Given** 迁出后的手动工具，**When** 以测试库执行预演模式，**Then** 输出与迁出前接口等价的预演结果。
3. **Given** 既有恢复相关测试，**When** 本故事交付，**Then** 已改为直接调用工具层，断言不放松，全部通过。

### User Story 7 - 前端理线：类型闭环、样式冻结 (Priority: P2)

前端核心页面的跨模块依赖袋获得完整类型定义，类型检查重新覆盖全部 composable 边界；散落的 any 豁口清零。理线过程中发现的逻辑问题当场修复、逐条单独提交。全程样式与渲染结果像素级不变。

**Why this priority**: 类型闭环是前端后续一切修改的安全网；样式冻结是用户铁律，作为硬约束贯穿本故事。

**Independent Test**: 前端类型检查通过且 deps:any 与非测试 any 计数为 0；构建产物样式哈希与理线前一致；533 个前端测试全绿。

**Acceptance Scenarios**:

1. **Given** 修好后的前端，**When** 运行类型检查与测试，**Then** 全部通过，跨 composable 依赖有完整类型，`deps: any` 与非测试代码 `: any` 计数为 0。
2. **Given** 理线前后的构建产物样式文件，**When** 对比，**Then** 渲染规则不变（用户界面像素级一致）。
3. **Given** 理线中发现的逻辑问题，**When** 修复，**Then** 每处单独提交并附说明，不与搬移改动混合。
4. **Given** 全部既有前端测试，**When** 本故事交付，**Then** 全绿且断言未放松。

### User Story 8 - 拆掉"隔空改主文件"的测试后门 (Priority: P3)

测试通过隔空替换主文件零件来造假数据的后门拆除：可替换符号改为显式注入（或正式替换点），测试改为正规打桩写法，生产代码不再为测试改变形态（运行时上下文对象的动态兜底属性访问随之移除）。

**Why this priority**: 依赖故事 2 完成才有迁移前提；改动面集中在测试文件，风险隔离最好，故排最后；它是松绑工作的收尾而非新能力。

**Independent Test**: 检索 patch("webui.app.X") 形态的测试打桩为 0；运行时上下文动态门面移除；后端全量测试全绿。

**Acceptance Scenarios**:

1. **Given** 修好后的测试套件，**When** 检索对主文件模块属性的测试打桩，**Then** 为 0，全部改为注入或正式替换点。
2. **Given** 运行时上下文对象，**When** 检查其属性访问，**Then** 动态兜底门面已移除，全部属性显式声明。
3. **Given** 8 个可替换符号（爬虫源、AI 服务、线程库等），**When** 测试需要替换它们，**Then** 经由统一的显式注入点完成。
4. **Given** 后端全量测试，**When** 本故事交付，**Then** 全绿。

### User Story 9 - 发布验证闭环补全 (Priority: P2)

推送到 GitHub 的任意分支会在 Windows 平台（用户实际安装的平台）跑一遍后端与前端测试；macOS 发布流水线在产出安装包之前先过测试门禁；发布检查工具校验 CHANGELOG 最新版本存在对应标签——版本与标签不再脱节。

**Why this priority**: 验证金字塔目前倒置——全量测试只在 Linux 跑、EXE 构建永不进 CI、1.8.2 与 1.7.11 两个已发布版本没有标签且从未触发 DMG 构建。它是"改坏能被抓住"的平台保障，与三道保险验收直接相关。

**Independent Test**: 推送含 Windows 作业的 CI 配置并在 GitHub Actions 观察；本地以"版本无标签/有标签"两种输入运行发布检查验证校验行为。

**Acceptance Scenarios**:

1. **Given** 更新后的 CI 配置，**When** 推送到任意分支，**Then** 除既有 Linux 作业外新增 Windows 作业，执行后端测试套件与前端测试（GitHub 托管 Windows 运行器自带 Chrome，源测试池无需额外浏览器安装）。
2. **Given** macOS 发布流水线，**When** 标签触发构建，**Then** 产出安装包之前先执行测试门禁，测试不过则不产出产物。
3. **Given** CHANGELOG 最新版本没有对应 v* 标签，**When** 运行发布检查，**Then** 报错并指出版本与标签脱节（1.8.2/1.7.11 情形不再重演）。
4. **Given** CHANGELOG 最新版本已有对应标签，**When** 运行发布检查，**Then** 校验通过。

### Edge Cases

- 拆分过程中发现代码无法纯搬移（隐藏耦合、共享可变态）：该批次暂停，在本 spec 内增补任务解决后继续，不开新 spec（冻结规矩）。
- 提示语统一后，若既有测试断言旧文案：同批更新断言，属测试跟随，不计为行为变化。
- 打桩迁移期间某符号无法安全迁移：该符号单独批次处理并在本 spec 内记录原因，不允许无声跳过。
- 镜像地址收进加密配置后，若发布时未配置：镜像同步步骤显式跳过并在流水线输出醒目提示（不静默失败）。
- 白名单豁免（清理类吞噬）必须有注释说明；无注释的豁免视为违规，测试失败。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: README 的版本陈述 MUST 与仓库真实版本一致，标题与"最新正式版"不得矛盾。
- **FR-002**: AGENTS.md 的超大文件清单 MUST 反映实测超大文件（Python >800 / Vue >1200），不得指向已拆完的文件。
- **FR-003**: "任务不存在"类提示语 MUST 全仓仅一处定义，文案统一为"任务不存在或已被移除"；此为唯一许可的用户可见文字变化。
- **FR-004**: task_status.py 中写错位置的函数说明文字 MUST 恢复为有效说明（位于函数体首）。
- **FR-005**: 公开仓库文本文件 MUST NOT 出现镜像服务器地址与 root 登录串；发布流程 MUST 经加密配置注入地址与账号。
- **FR-006**: 发布脚本与流水线 MUST 支持可配置的非 root 部署账号。
- **FR-007**: 治理规则文件（宪法）MUST 纳入 git 跟踪并通过卫生检查；历史工单目录 MUST 维持本地不入库。
- **FR-008**: 死配置（无人引用的质量平台配置、残留测试配置段、未使用的覆盖率依赖）MUST 从仓库清除。
- **FR-009**: 卫生测试对前端构建产物的凭据扫描 MUST NOT 整体豁免。
- **FR-010**: webui/scripts 对主文件的反向 import MUST 清零（除主文件自身与兼容 re-export）；共享常量与纯函数 MUST 落位独立共享模块。
- **FR-011**: 路由注册方式 MUST 统一为一种模式。
- **FR-012**: 纯 pass 吞异常 MUST 按三档处理（显式错误返回 / 日志留痕 / 附注释白名单），处理后计数 MUST ≤ 卫生测试基线且基线只许下降。
- **FR-013**: 后端业务模块 MUST 使用统一日志配置；业务模块内散装 print MUST 清零（CLI 脚本不受限）。
- **FR-014**: 更新器状态目录环境变量 MUST 有测试用例覆盖。
- **FR-015**: scripts/boss 子模块 MUST NOT 经门面回溯读取会话状态；会话态 MUST 由包内 runtime 模块持有；老门面 MUST 保留兼容 re-export 与 CLI 入口。
- **FR-016**: 超限文件 MUST 拆分至宪法红线内（Python ≤800、Vue ≤1200），原入口保留兼容导出，只搬代码不改行为；每批 MUST 通过聚焦测试+后端全量+前端测试+构建。
- **FR-017**: 990 行事故修复代码 MUST 迁出生产 API 面成为手动工具；3 条 recovery 接口 MUST 删除；相关测试 MUST 改为直接调用工具层。
- **FR-018**: 前端跨 composable 依赖 MUST 有完整类型定义；`deps: any` 与非测试 `: any` MUST 清零；发现的逻辑问题 MUST 当场修复并单独提交。
