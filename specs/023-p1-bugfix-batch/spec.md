**Created**: 2026-08-25 | **Status**: Draft（grill-me 冻结需求，14 条）

R1=列表/广泛抓取、R2=详情抓取，各绑定一个账号（下拉单选）；10. 允许同一账号同时是 R1 和 R2；11. ## User Scenarios & Testing

### User Story 1 - 区/县面板任何窗口宽度可用 (P1)

用户在新建任务的关键词×城市区加深圳后，点「深圳」标签本体。无论窗口是全屏还是被拖窄/分屏，面板都准确出现在深圳标签正下方，完整可见，可多选区/县；两字区名（如"龙岗"）完整显示不被压缩。

**为什么是 P1**：B072 是已确认 Bug，窄窗口下无法选择区/县直接影响搜索范围设置（B054 区/县功能在窄窗口不可用）。

**独立测试**：组件测试模拟窄视口（jsdom 设 window.innerWidth 小值），断言面板样式 left/top/width 落在视口内；区/县格子文字完整。

**验收场景**：

1. **Given** 全屏窗口打开区/县面板，**When** 拖窄窗口到最小可用宽度，**Then** 面板始终出现在标签正下方、完整可见、可多选，区名完整。
2. **Given** 窗口窄到极窄（如 300px），**When** 打开面板，**Then** 面板不溢出视口，格子保持最小宽度、面板内可横向滚动，不压字。
3. **Given** 任意宽度下，**When** 点标签外区域/Escape，**Then** 面板正常关闭。

### User Story 2 - 重抓胶囊「暂不处理」不再鬼畜重弹 (P1)

用户在 04 结果页有待确认岗位时看到顶部「是否重抓」胶囊，点「暂不处理」后切智联/BOSS 平台、切页签，胶囊不再重新弹出；切到 0 待确认平台也不再闪绿色"已全部处理"对勾。只有新结果重载（新一轮/重抓出结果）才复位。

**为什么是 P1**：B074 已确认 Bug，鬼畜重弹与误导性对勾直接干扰用户处理待确认岗位。

**独立测试**：组件测试 + Discovery 状态层测试：dismissed 后 count 抖动（平台切换导致归零再反弹）不触发重弹；resultEpoch 变化才复位。

**验收场景**：

1. **Given** 有待确认岗位且胶囊可见，**When** 点「暂不处理」，**Then** 胶囊隐藏；随后切换平台/页签（count 抖动），胶囊不再出现。
2. **Given** 用户切到 0 待确认平台视图（count 归零但岗位未被处理），**When** 视图切换完成，**Then** 不显示绿色"已全部处理"对勾。
3. **Given** 新结果重载（新一轮完成或手动全部重抓出结果），**When** resultEpoch 变化，**Then** 若仍有待确认岗位，胶囊重新出现。
4. **Given** 待确认岗位全部真正处理完，**When** count 归零，**Then** 胶囊直接消失，无对勾、无闪烁。

### User Story 3 - BOSS 账号角色分配 R1/R2 (P1)

用户在账号弹窗顶部看到 `[R1 · 列表/广泛抓取 · 未指定 ▾] [R2 · 详情抓取 · 未指定 ▾]` 两个小长块，分别点开下拉选择账号。跑 BOSS 任务时：列表/广泛抓取阶段用 R1 指定账号的浏览器，JD 详情抓取阶段用 R2 指定账号的浏览器。角色未指定（或指定账号开跑前检测未登录）时自动降级用当前账号，不报错不阻断。

**为什么是 P1**：B073 已确认需求，把列表抓取与详情抓取分到不同账号，规避单账号风控/限流风险。

**独立测试**：后端测试 mock 账号簿（带 roles）与任务创建流程，断言列表阶段任务冻结 R1 账号、详情阶段任务冻结 R2 账号、未指定时降级当前账号；前端组件测试渲染两个小长块与下拉选择、选中显示用户名。

**验收场景**：

1. **Given** 账号弹窗打开，**When** 用户点 R1 小长块，**Then** 弹出账号下拉列表，点选某账号后块内显示该账号用户名。
2. **Given** 账号 A 设为 R1、账号 C 设为 R2，**When** 提交 BOSS 抓取任务，**Then** 列表抓取阶段浏览器绑定账号 A，JD 详情阶段浏览器绑定账号 C。
3. **Given** R1 未指定（或指定账号未登录），**When** 提交任务，**Then** 自动降级用当前账号，不报错不阻断。
4. **Given** 运行中指定账号被风控/登录失效，**When** 任务出错，**Then** 任务暂停+提示原因，用户处理后点「继续」续跑（不自动切换账号）。
5. **Given** 智联平台任务，**When** 提交，**Then** 不受 R1/R2 影响，继续用当前账号。

### Edge Cases

- 账号弹窗中账号列表为空时，R1/R2 下拉显示空态提示。
- 同一账号同时设为 R1 与 R2：两个阶段都用该账号。
- 删除被设为 R1/R2 的账号：对应角色回退为「未指定」（降级当前账号），不报错。
- 下拉选择过程中任务运行中：账号角色变更只影响下次任务，不影响当前运行任务（角色在任务创建时冻结）。
- B074：结果从未加载过时胶囊不出现；isScrapedOnly（纯抓取未筛选）时不出现。

## Requirements

### Functional Requirements

- **FR-001**: LocationPicker 面板 MUST 在任意窗口宽度下定位在城市标签正下方且完整在视口内（左/上/下不越界，宽度不超过视口），区/县格子 MUST 有最小宽度保底（grid auto-fill minmax，两字区名完整显示），极窄视口下面板内部横向滚动而非溢出/压字。
- **FR-002**: 区/县与商圈格子列数 MUST 随面板宽度自适应（宽 3 列、窄降列），区/县名 MUST 完整显示不压缩。
- **FR-003**: B072 修复 MUST 同时覆盖 BOSS 与智联（同一组件），不改后端。
- **FR-004**: PendingRecrawlCapsule 的「暂不处理」隐藏态 MUST 上提/共享，仅按 resultEpoch（新结果重载）复位，不得按 count 归零复位。
- **FR-005**: 绿色「待确认岗位已全部处理」对勾 MUST 移除；处理完胶囊直接消失，无闪烁。
- **FR-006**: 新结果重载（新一轮/全部重抓出结果）后若仍有待确认，胶囊 MUST 重新出现。
- **FR-007**: 账号数据层 MUST 支持角色标记 R1/R2（允许同时），与现有 `browser_accounts.json` 账号模型对齐；API 透出角色并可保存。
- **FR-008**: 账号弹窗 MUST 顶部展示 `[R1 · 列表/广泛抓取]` / `[R2 · 详情抓取]` 两个小长块，点开下拉选账号，选中显示用户名；账号卡片不加控件。
- **FR-009**: BOSS 任务创建时 MUST 按阶段解析角色账号：列表/广泛抓取阶段冻结 R1 账号，JD 详情阶段冻结 R2 账号；角色未指定/指定账号不可用 → 降级当前账号。**仅任务创建点解析；续跑 MUST 沿用 DB 冻结的 browser_account，不重新解析角色。**
- **FR-010**: 角色解析 MUST 仅作用于 BOSS 平台；智联任务不受影响。
- **FR-011**: 开跑前检测角色账号登录态，不可用则降级当前账号；运行中出错走既有暂停+继续路径，不自动切换账号（复用 B057/B067 语义，不新造）。
- **FR-012**: 本期 MUST NOT 实现轮询、数量上限、选号算法。

### Key Entities

- **BrowserAccount.roles**: `list[str]`，取值 `"R1"` / `"R2"` 可同时存在。存于 `browser_accounts.json` 账号记录。

## Success Criteria

### Measurable Outcomes

- **SC-001**: B072 组件测试通过：任意视口宽度面板在视口内、区名完整；全屏回归正常。
- **SC-002**: B074 状态层测试通过：dismissed 后 count 抖动不重弹、resultEpoch 变化才复位、对勾移除、真处理完直接消失。
- **SC-003**: B073 后端测试通过：列表任务冻结 R1 账号、详情任务冻结 R2 账号、未指定降级当前账号、智联不受影响、运行中出错仍走暂停+继续。
- **SC-004**: B073 前端测试通过：两个小长块渲染、下拉选号、选中显示用户名、空账号空态。
- **SC-005**: 用户手动验证：窄窗口选区县正常；待确认流程切平台不重弹；BOSS 任务两个阶段用不同账号浏览器。

## Verification Scope

- 功能交付：聚焦测试（LocationPicker、PendingRecrawlCapsule、Discovery 状态层、pipeline_exec_accounts、任务冻结账号）、后端全量测试、前端测试、`npm run build`、仓库卫生检查。
- 用户端到端真跑验证（SC-005）在交付后进行。
- 不涉及版本提升/打包/发布。

## Assumptions

- B072 面板宽度上限 380px 且不超视口；区/县格子最小宽度保底（auto-fill minmax ≈96px），极窄视口（如 300px）面板内部横向滚动，面板本身不溢出视口。
- B074 隐藏态不持久化到 localStorage，仅会话内有效（刷新/重开应用胶囊重新出现）。
- B073 角色保存在 `browser_accounts.json` 账号记录 roles 字段；角色在任务创建时冻结，运行中修改不影响当前任务；**续跑（resume/continue）一律沿用任务创建时冻结的 browser_account，不重新按角色解析**（用户暂停期间改角色不影响续跑）。
- 删除被指定为角色的账号 → 角色回退未指定，降级当前账号，不报错。
- 运行中出错复用既有暂停/继续/切换账号语义（B057/B067），本 Spec 不新增自动切换逻辑。
- 智联平台本期不参与角色分配。
