# Feature Specification: 任务历史浏览安全与界面一致性修复（035 全量重拆版）

**Feature Branch**: `035-task-history-safety`

**Created**: 2026-09-01（同日全量重拆。首版验收以「任务状态」为衡量标准，导致用户真机发现三个界面问题整条链路无人拦截；本版起**「用户看到的界面」是唯一验收标准**，界面完整性为一等公民，验收全部按模拟用户视角的真实操作路径逐条走查）

**Status**: Draft

**Input**: 冻结需求（用户逐条确认，最高权威，禁止扩写/收窄）：

**A 组（用户原话/已确认边界）**：

- A1 刷新后接回正在跑的任务；看历史、回到最新、刷新都不改变任务真实状态
- A2 看历史期间任务照常跑；「回到最新」回到当前一轮的事实：在跑显示进度、跑完显示成果、不倒退旧一轮
- A3 后台跑完给顶部冒泡提示，不打断看历史；预留 B088 灵动岛（现在只做简单冒泡）
- A4 统一保护：运行中、暂停中、出错中断都算未结束，不被误杀；只有用户主动操作才能结束
- A5 结束唯一入口 = 「结束」按钮，点完跳 04 结果页；不加确认弹窗
- A6 B085：不改任务详情页；日志界面加「全局/运行日志」切换滑块
- A7 旧任务没结束时，任何能开新一轮的入口一律跳转到未完成任务，不弹窗、不自动取消
- A8 验收按模拟用户视角写（真实操作路径逐条走查）

**B 组（已确认的推断）**：

- B1 运行日志 = 任务执行过程日志（检查浏览器、搜到第几页、抓了多少条、成没成）
- B2 顶部冒泡点击后跳转到该轮
- B3 系统同一时间只运行一个任务；未结束任务存在时任何开新一轮入口均跳回
- B4 结束按钮按现有交互保留，不额外加确认

**用户真机发现的问题（硬验收，必须修到用户亲眼确认）**：

- 真机问题①（03 页残留）：任务在抓取中（流程只到 02 抓取，03 AI 筛选还没开始），刷新/恢复后第二页正确显示「正在抓取」，但第三页（AI 筛选）还展示着旧一轮的内容——恢复恢复了任务状态，页面步骤展示没有全局收敛。
- 真机问题②（历史里开新一轮）：任务还在跑，从历史（历史模式查看旧轮次）点「开始新一轮」竟然真的开始了新一轮（旧任务被取消），没有跳回正在跑的任务——上次只堵了部分入口，入口清单没列全。
- 真机问题③（按钮混乱）：正常运行时任务页只有 2 个按钮，从历史回到任务页时按钮变成 4 个、杂乱——按钮由多个状态派生，回到任务页时状态组合不一致，派生出多余按钮。

**根因教训（写进本 Spec 约束后续所有环节）**：上一轮从需求→SPEC→实现→测试→审查→验证，每个环节都以「任务状态」为衡量标准，没有任何环节以「用户看到的界面」为准。本 Spec 起反转：验收、实现、测试、审查、验证全部以用户眼睛看到的界面为唯一标准；界面问题在本 Spec 里是硬验收；审查必须真实渲染/真机操作走查，静态读码不能代替界面走查。

## User Scenarios & Testing

### User Story 1 - 恢复/回到最新后，四个步骤页与任务真实进度全局一致（含真机问题①）(Priority: P1)

任务在 02 抓取中刷新页面后：02 页显示「正在抓取」的真实进度；03 页（AI 筛选）清空旧一轮内容、显示「未开始」；01 页显示本轮参数；04 页不出现旧一轮成果的残留。从历史「回到最新」、从历史回到任务页，同样整体收敛。暂停中、出错中断的任务走同样路径后，各页同样与任务真实状态一致。核心规则：**四个步骤页（01 参数 → 02 抓取 → 03 AI 筛选 → 04 结果）的显示内容，由任务此刻的真实进度一次性推导**——任务到哪步，那步显示进行中的真实状态；还没走到的步骤显示未开始（清空旧内容）；已走完的步骤显示已完成状态。任何一页都不允许保留上一轮残留。

**Why this priority**: P1。真机实测发现（真机问题①）：数据与任务都对，但界面给用户看的是错的——用户会以为 AI 筛选已经跑过/出了结果。这是「界面即事实」的第一原则问题。

**Independent Test**: 模拟用户视角逐页走查：构造任务在 02 抓取运行中 → 刷新 → 逐页核对 01/02/03/04 显示内容与任务真实进度一致、03 无旧一轮筛选内容；再走「看历史 → 回到最新」同路径核对；暂停/中断任务同路径核对。

**Acceptance Scenarios**:

1. **Given** 任务在 02 抓取运行中，**When** 刷新页面，**Then** 02 页显示正在抓取进度，03 页显示未开始（无旧一轮 AI 筛选内容），01 页显示本轮参数，界面无旧一轮成果残留。
2. **Given** 任务在 02 抓取运行中，**When** 从历史点「回到最新」，**Then** 四页显示同样收敛到任务真实进度，03 页无旧内容。
3. **Given** 任务处于暂停中/出错中断，**When** 刷新或回到最新，**Then** 各页与任务真实状态一致，无旧一轮内容残留，任务不被取消。
4. **Given** 任务已进入 03 AI 筛选运行中，**When** 刷新页面，**Then** 03 页显示筛选进度，02 页显示本轮抓取已完成，04 页不出现旧一轮成果。
5. **Given** 上一轮 AI 筛选完成后用户开了新一轮抓取，**When** 查看各步骤页，**Then** 03 页不保留上一轮筛选内容（新一轮开始即清空旧轮展示）。

### User Story 2 - 未结束任务存在时，所有「开始新一轮」入口一律跳回（含历史模式入口，真机问题②）(Priority: P1)

「能开新一轮的入口」完整清单（按用户可见位置，实现与测试必须逐个覆盖，不得再漏）：

1. 04 页「开始新一轮」按钮——**当前轮的 04 页与历史模式查看旧轮次时的 04 页都算**；
2. 01 页「上传并分析」按钮（上传简历 = 隐式开新一轮）；
3. 02 页「开始筛选并 AI 优化」按钮（一键链路）；
4. 02 页「单独抓取」按钮；
5. 启动/刷新页面后的自动开新一轮。

任务未结束（运行中、暂停中、出错中断，**含 02 抓取运行中**）时，以上每个入口都必须：跳回该任务的**真实进度页**（抓取任务回 02 抓取进度页、AI 筛选任务回 03 筛选进度页）；不取消任务、不弹取消确认、不启动新一轮。

**Why this priority**: P1。真机实测发现（真机问题②）：从历史模式的 04 页点「开始新一轮」真的取消了正在跑的任务并开了新一轮——用户视角是「正在跑的流程被无声杀掉」。属流程安全类缺陷，且上次修复正是因入口清单没列全而漏掉这个口。

**Independent Test**: 模拟用户视角逐入口走查：构造抓取运行中/筛选运行中/暂停/中断的任务 → 逐个触发上述 5 个入口 → 核对每次都跳回任务真实进度页、任务未被取消、无新一轮启动；重点覆盖「后台抓取运行中 + 历史模式 04 页 + 开始新一轮」这个真机踩中的组合。

**Acceptance Scenarios**:

1. **Given** 后台 02 抓取运行中，When 用户在历史模式查看旧轮次、在该轮 04 页点「开始新一轮」，**Then** 跳回 02 抓取进度页，抓取任务继续运行、未被取消、未开新一轮（真机问题②的显式验收）。
2. **Given** 后台 03 AI 筛选运行中，**When** 点「开始新一轮」（当前轮或历史轮的 04 页），**Then** 跳回 03 筛选进度页，任务未被取消。
3. **Given** 任务暂停中/出错中断，**When** 逐个触发 5 个入口，**Then** 一律跳回任务真实进度页，无弹窗、无取消、无新一轮。
4. **Given** 任务已真实结束，**When** 触发任一入口，**Then** 正常开始新一轮（不误挡正常流程）。

### User Story 3 - 任务页按钮在任何回到路径后与正常运行完全一致（真机问题③）(Priority: P1)

正常运行时任务页（02 抓取进行中）的标准操作按钮是 2 个：「停止抓取」「结束并保存结果」。用户看历史后回来、刷新恢复后，按钮**仍然恰好是这 2 个**——不出现「进行确认AI筛选条件」「直接查看结果」等多余按钮。看历史这个动作本身不得弄脏任何影响按钮派生的状态。这两个多余按钮只在**抓取真正完成后**才允许出现。任务运行期间不得提供任何把半截结果保存/当作成果查看的入口。

**Why this priority**: P1。真机实测发现（真机问题③）：从历史回到任务页按钮 2 个变 4 个。按钮数量与种类是用户判断「现在流程处于什么状态」的直接依据，错乱的按钮等于错乱的状态告知；且「直接查看结果」在运行中出现可能导致半截结果被保存。

**Independent Test**: 模拟用户视角走查：抓取运行中 → 记录任务页按钮集合 → 看历史 → 回到最新 → 再核对按钮集合一致（恰好 2 个）；刷新恢复路径同查；抓取真正完成后核对「进行确认AI筛选条件」「直接查看结果」正常出现。

**Acceptance Scenarios**:

1. **Given** 任务在 02 抓取运行中，**When** 直接查看任务页，**Then** 恰好 2 个操作按钮（停止抓取、结束并保存结果）。
2. **Given** 任务在 02 抓取运行中，**When** 看历史后「回到最新」再查看任务页，**Then** 按钮仍恰好 2 个，与正常运行完全一致（真机问题③的显式验收）。
3. **Given** 任务在 02 抓取运行中，**When** 刷新页面恢复后查看任务页，**Then** 按钮同样恰好 2 个。
4. **Given** 任务抓取真正完成（正常进入待确认阶段），**When** 查看任务页，**Then** 「进行确认AI筛选条件」「直接查看结果」正常出现——即这两个按钮只由「抓取真实完成」触发，不因看历史被误触发。

### User Story 4 - 后台跑完回最新能看到本轮成果（B087）(Priority: P2)

任务在后台跑时用户去看历史，这期间任务跑完——历史里这一轮的条目状态实时更新（弱提示，不打断浏览），顶部冒泡提示本轮完成；用户点冒泡或「回到最新」，看到的是本轮的最新成果，而不是上一轮旧内容。

**Why this priority**: P2。数据实际都在，只是界面没给，用户会被误导以为流程失败或白跑；与 B086 同场景同源。

**Independent Test**: 模拟用户视角：任务后台运行中用户看历史 + 任务跑完 → 历史条目状态实时更新、顶部冒泡提示、点「回到最新」看到本轮最新成果而非旧一轮。

**Acceptance Scenarios**:

1. **Given** 任务在后台运行，**When** 用户在看历史，**Then** 历史中该轮条目状态实时更新（进行中 → 已完成），不打断浏览。
2. **Given** 后台任务跑完，**When** 用户仍停留在历史，**Then** 顶部冒泡提示本轮完成，点击后跳转到该轮。
3. **Given** 后台任务跑完，**When** 用户点「回到最新」，**Then** 看到本轮最新成果，不是上一轮旧内容。

### User Story 5 - 日志界面可切换全局日志与运行日志（B085）(Priority: P1，已真机验证通过，本版作回归保护)

排查某个任务失败原因时，不用再在「日志」按钮和任务详情之间来回切。打开日志界面后，用滑块在「全局日志 / 运行日志」之间切换：全局日志是整体技术日志，运行日志是这一轮任务的执行过程（检查浏览器、搜到第几页、抓了多少条、成没成），两种内容各是各的、不串。

**Why this priority**: P1（已在上一轮真机验证通过，本轮不改动其行为，验收保留作为回归保护，防止本次界面收敛修复波及日志功能）。

**Independent Test**: 模拟用户视角：打开日志界面 → 滑块切换全局/运行日志 → 两种内容各自正确显示、不互相串；历史轮的运行日志可从历史抽屉打开对应轮次。

**Acceptance Scenarios**:

1. **Given** 用户打开日志界面，**When** 用滑块切换到「运行日志」，**Then** 显示该轮任务的执行过程日志。
2. **Given** 用户打开日志界面，**When** 用滑块切换到「全局日志」，**Then** 显示全局技术日志。
3. **Given** 用户来回切换两种日志，**When** 反复操作，**Then** 内容各是各的、不串、不丢。
4. **Given** 尚未产生任何任务执行日志，**When** 切到「运行日志」，**Then** 显示空态说明，不报错、不空白卡死。

### Edge Cases

- **刷新竞态**：刷新瞬间任务可能真实结束（用户刚点过结束）——此时按已结束处理（回 01 页/历史可查），不得恢复；判据以任务真实状态为准，浏览历史这一动作本身永不产生「已结束」。
- **多轮历史**：后端存在多轮历史记录；恢复/保护只针对「当前未结束任务」，不得因更早轮次的记录误判当前任务已结束或误恢复旧轮次。
- **开新一轮竞态**：用户点「开始新一轮」时旧任务恰好结束——按任务真实状态决定：未结束则跳回该任务，已结束则正常开始新一轮。
- **历史模式的 04 页操作按钮**：历史模式查看旧轮次时，04 页上的「开始新一轮」等操作按钮不得对当前正在跑的任务产生取消/顶替效果（由 US2 的跳回规则覆盖）。
- **冒泡与历史共存**：冒泡出现不打断看历史；用户在历史中可继续浏览，冒泡作为回到最新/查看成果的入口。
- **结束按钮**：结束按钮仍是唯一主动结束入口，结束动作不因用户在看历史而受影响；点完跳 04 结果页，不加确认弹窗。
- **历史轮内容本身**：历史模式查看旧轮次时显示该旧轮的内容是历史功能本身，不属于「残留」；「残留」特指当前轮/恢复路径上出现旧一轮内容。

## Requirements

### Functional Requirements

- **FR-001**: 系统 MUST 在用户浏览历史（进入历史、从历史「回到最新」、从历史回到任务页）时，保持当前任务的真实状态不变（运行中/暂停中/出错中断均保持原状态）。
- **FR-002**: 刷新/重启后，未结束的任务 MUST 被接回：正在运行的继续运行、暂停中的保持暂停、出错中断的提示可继续/放弃；MUST NOT 被自动「开始新一轮」顶掉或取消。
- **FR-003**: 任务结束的唯一入口 MUST 是用户主动点击「结束」按钮；结束动作 MUST NOT 由浏览历史、回到最新、刷新、开始新一轮等任何其它路径触发。
- **FR-004**: 未结束任务存在时，任一「开始新一轮」入口（US2 清单 5 项，含历史模式 04 页按钮）MUST 跳转到该未结束任务的**真实进度页**（抓取任务回 02、AI 筛选任务回 03）；MUST NOT 自动取消旧任务、MUST NOT 弹出取消确认。
- **FR-005**: 系统 MUST 同一时间只运行一个任务（单任务模型）。
- **FR-006**: 后台任务跑完时，历史界面中该轮的条目状态 MUST 实时更新（弱提示），且不打断用户浏览历史。
- **FR-007**: 后台任务跑完时， MUST 提供顶部冒泡提示；点击冒泡 MUST 跳转到该轮（回到最新查看成果）。
- **FR-008**: 「回到最新」MUST 显示当前一轮的真实最新状态：在跑显示进度、跑完显示最新成果；MUST NOT 倒退显示上一轮旧内容。
- **FR-009**: 日志界面 MUST 提供「全局日志 / 运行日志」切换（滑块）；切换后各自显示对应日志内容，MUST NOT 串内容、MUST NOT 丢失内容。
- **FR-010**（真机问题①）: 恢复（刷新/重启接回）与「回到最新」后，四个步骤页的显示内容 MUST 由任务此刻的真实进度一次性推导：任务进行到的步骤显示真实状态；未走到的步骤 MUST 显示未开始（清空旧一轮内容）；已走完的步骤显示已完成状态。任何步骤页 MUST NOT 保留上一轮残留内容。
- **FR-011**（真机问题②）: 未结束任务存在时（含 02 抓取运行中），任一「开始新一轮」入口 MUST 跳回该任务真实进度页，MUST NOT 取消任务、MUST NOT 启动新一轮。跳回落点 MUST 与任务类型匹配（抓取任务回 02、AI 筛选任务回 03），MUST NOT 一律跳 03。
- **FR-012**（真机问题③）: 浏览历史 MUST NOT 置位或污染任何影响任务页按钮派生的状态（如「抓取已完成」）；从任何路径回到任务页后，按钮集合 MUST 与正常运行时完全一致（抓取运行中恰好 2 个：停止抓取、结束并保存结果）。
- **FR-013**（真机问题③附带风险）: 任务运行期间 MUST NOT 出现「直接查看结果」等会把未完成任务的半截结果保存或当作成果展示的入口；此类入口只允许在对应阶段真实完成后出现。

### Key Entities

- **当前任务**: 正在运行或未结束的任务，含状态（运行中/暂停中/出错中断/已结束）与类型（抓取/AI 筛选）；浏览历史不得改变其状态，只有用户主动「结束」才可结束。
- **历史轮次**: 各轮任务的记录与成果，可随时查看；「回到最新」指向当前一轮的真实状态，而非历史旧轮。
- **步骤页显示状态**: 01/02/03/04 各页在任务任一真实进度下应显示的内容，由任务真实进度唯一推导；「未开始」为合法显示状态。
- **任务页标准按钮集**: 任务在某一真实状态下，任务页应显示的操作按钮集合（抓取运行中 = 停止抓取 + 结束并保存结果，共 2 个）；任何回到路径后必须与此一致。
- **全局日志**: 应用整体技术日志（现有「日志」入口所看内容）。
- **运行日志**: 单轮任务的执行过程日志（检查浏览器、搜到第几页、抓了多少条、成没成）。

## Success Criteria

### Measurable Outcomes

- **SC-001**（真机问题①）: 用户亲自点验——抓取中刷新 → 只有 02 页显示进度、03 页不出现旧一轮内容、按钮恰好 2 个。
- **SC-002**（真机问题②）: 用户亲自点验——历史里点「开始新一轮」→ 跳回正在跑的任务、不开新一轮、任务未被取消。
- **SC-003**（真机问题③）: 用户亲自点验——从历史回到任务页 → 按钮数量与种类和正常运行完全一致（2 个）。

- **SC-005**: 日志界面滑块切换全局/运行日志，内容正确不串不丢（含历史轮运行日志）。
- **SC-006**: 自动化门禁——聚焦测试 + 后端全量测试 + 前端测试 + 构建 + 仓库卫生检查通过；前端测试 MUST 覆盖 FR-010/011/012/013 的界面验收（页面显示内容、按钮集合、入口清单逐个），不得只测任务状态字段。

## Assumptions

- **A1（B085 运行日志定义）**: 「运行日志」指单轮任务的执行过程日志（检查浏览器、搜到第几页、抓了多少条、成没成），即当前任务详情中可见的执行过程；与全局技术日志相区别。切换滑块置于日志界面内，不改动任务详情页。
- **A2（冒泡交互与扩展）**: 顶部冒泡点击后跳转到该轮（回到最新查看成果）；本轮仅实现简单冒泡，设计上为 B088（顶栏灵动岛）预留接入空间，但不在本 Spec 范围内实现灵动岛。
- **A3（单任务模型）**: 系统同一时间只运行一个任务；未结束任务存在时，任何「开始新一轮」入口均跳回该任务。
- **A4（结束按钮）**: 保留现有「结束」按钮的交互，不额外增加确认弹窗；结束后跳转 04 结果页。
- **A5（B087 弱提示）**: 历史中该轮条目状态实时刷新为弱提示，不弹窗、不打断浏览；顶部冒泡为强于条目的提示，仍不打断浏览。
- **A6（上一轮已实现部分的处置）**: B085 日志滑块（含历史轮运行日志）与 B087 冒泡已实现且日志场景已真机验证通过，本轮保留行为不变，验收作回归保护；本轮修复聚焦三个真机问题对应的 FR-010~FR-013 与既有 FR 的界面化验收。
