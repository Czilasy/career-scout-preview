# B096 HTTP 行为契约（设计草案）

接口路径与 JSON 键为实施方案，最终以同等可观察语义、兼容既有单平台 API 为准；这些内部命名不是新增产品需求。所有端点沿用当前应用的画像/权限上下文，不返回浏览器 profile 路径、Cookie 或密钥。

| 动作 | 建议接口 | 成功可观察结果 | 失败边界 |
| --- | --- | --- | --- |
| 创建“全部” | `POST /api/flows`，含 `selection=all`、两平台条件及确认、一次启动键 | 返回一个 `flow_id` 和两条平台线；服务端先持久化关系，再各自提交任务 | 未确认、已有运行/暂停流程为 409；禁用平台为 409/503 且指出平台；不能静默改单平台 |
| 创建单平台新一轮 | 既有单平台启动接口内部创建 `selection=boss/zhilian` 的单轨 Flow，或统一复用 Flow 创建能力 | 返回既有兼容响应并绑定一个 `flow_id` 和一条平台线；当前结果、恢复和历史按该 Flow 定界 | 任一当前 Flow 仍运行或暂停时阻止新一轮；不得绕过“全部”流程门禁 |
| 查询当前流程 | `GET /api/flows/current?profile_id=…` | 显式 `flow_id`、选择、两平台的阶段/状态/错误/已有结果标记；刷新后同一身份 | 无流程为空态；画像不匹配不泄露其他流程 |
| 查询流程详情 | `GET /api/flows/{flow_id}` | 两平台独立运行状态及既有 run ID 关联，状态以持久事实校准 | 找不到/画像不匹配为不可访问 |
| 单线操作 | `POST /api/flows/{flow_id}/tracks/{platform}/{pause|resume|stop}` 或复用现有 task API | 只作用指定平台；幂等/冲突处理与现有操作一致 | 不得关闭另一平台浏览器或改变其状态 |
| 当前结果 | `GET /api/flows/{flow_id}/results` | 仅本流程已产生的岗位与各平台状态；筛选结果未形成时，仍可呈现该线已持久化的部分抓取岗位并标明失败及未完成 AI 筛选；可整理岗位带正确来源平台/run | 不能回退到“平台最新结果”兜底，不能伪造、重复计入岗位或把未筛选岗位计入已筛选口径 |
| 归档本流程 | 现有新一轮生命周期的归档调用增加明确 `flow_id`（内部可复用 Flow 服务） | 沿用现有用户操作和触发时机，仅将本流程结果归档，其他流程的当前结果与历史保持原状 | 不新增用户归档动作；不得沿用按画像归档所有未归档快照的宽范围写入 |
| 历史 | 现有历史接口增 Flow 分组投影，详情可按 `flow_id` 查询 | 一个外层流程项，内含两平台各自结果与状态；失败且无岗位的平台也占一个内层项；单平台旧轮次仍可读 | 画像隔离；不凭前端合并相近时间记录，不因缺少结果快照丢失平台状态 |

创建的原子边界：前置检查及 Flow/Track 建立在同一持久事务内；两项外部任务启动不能放在 SQLite 事务内。若某一提交失败，写入该 Track 的失败事实，另一 Track 保留运行/结果。对于并发点击/网络重试，服务端以启动键或等价唯一约束返回同一流程或明确冲突，不创建第二轮。

既有单平台入口继续返回和接受其原有数据形态，但迁移后每次新建单平台轮次都必须在内部创建并绑定真实单轨 Flow；旧客户端无需改用新 API。所有新轮次共享“任一当前 Flow 运行或暂停时不得再开新一轮”的门禁。现有抓取/AI 运行日志与状态可追溯到 Flow/Track，不以 UI 本地状态替代。对已完成平台的收藏、反馈、单岗位补抓等既有整理操作，传递该岗位真实来源 run；另一平台仍运行时也可使用。错误响应须包含稳定错误码与可展示原因，具体文案沿现有统一提示体系确定。
