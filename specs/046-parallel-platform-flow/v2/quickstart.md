# Quickstart: B096 V2 实施与验收

## 前置条件

1. 使用用户指定的现有功能工作目录，分支为 `feature/parallel-platform-flow`；稳定版 main 保持独立，不修改或合并。
2. 保留 V1 未提交工作，不覆盖、不回退。
3. 不读取 `design/**`。
4. 正式 E2E 前运行 `uv run python scripts/db_info.py` 确认 `env=live` 和最新 Flow。
5. BOSS、智联真实登录态均已就绪；缺任一登录态不得把替身测试称为 E2E。

## 开发验证顺序

1. 统一映射与配置快照：跑映射、对话框、主题、常用配置和迁移聚焦测试；验证平台微调不回流、统一字段级覆盖、无确认状态。
2. 页面分轨合流：覆盖智联先/BOSS 先、近同时、暂停、失败和第二平台晚到；断言进度来自 `/api/task-state` 且每平台一个 `TaskProgress`。
3. 结果与恢复：覆盖结果合流、灵动岛、02/03/04 刷新和历史；断言阅读现场保持。

## 自动化最终门禁

整条链收敛后执行一次：

```powershell
uv run python -m unittest discover -s tests
Set-Location webui
npm test
npm run build
Set-Location ..
uv run python -m unittest tests.test_repo_hygiene
git diff --check
git status --short
```

全量失败时保存失败清单，只重跑失败用例与直接受影响范围；修复并聚焦通过后才能再次做最终全量。

## 真实源码 E2E

本次修复的直接验收：在 02/03 选择一轨暂停、继续或结束保存，确认另一轨状态和操作保留；详情批次时两种选择只作用于所选实例；抓取已完成而 AI 运行时返回 02，旧抓取卡无操作按钮。真实失败 Track 沿后端终态门禁不提供无效继续入口。两种顺序、结果原地加入、阅读现场、返回/刷新与新轮分别记录自动化/正式运行证据，不能互相替代。

按正式入口启动，不使用临时数据库、测试客户端或 mock。

1. 选择“全部”，确认中性主题和六类统一建议。
2. 修改一个一对多映射字段，在 BOSS、智联页核对实际选择。
3. 做一次平台微调，再改同一统一字段，核对字段级覆盖和专属字段保留。
4. 点击一次主按钮启动，记录实际先完成平台。
5. 确认 02 两行原进度、领先平台进入 03、落后平台继续。
6. 返回 02，确认后续变化不抢页面；再进入 03。
7. 领先平台进入 04 后设置筛选/排序、滚动并展开岗位。
8. 第二平台完成后确认结果原地加入、现场不丢、灵动岛只提示一次。
9. 在 02、03、04 可构造现场刷新，确认当前页、入口、状态和结果恢复。
10. 打开历史，确认同一 Flow 两条 Track 和冻结条件。

记录 Flow id、两个平台 run id、完成顺序和页面观察；不得记录 Cookie、Token 或岗位隐私正文。

## EXE 最小充分真实验证

自动化和源码 E2E 通过后，按现有打包流程构建本地 EXE（不发布、不上传）。验证“全部”主题与映射、一次启动双轨、领先平台进入 03/04、第二平台原地合流、灵动岛通知及 04 刷新恢复。未完成时只能报告“源码已验证，EXE 未验证”。
