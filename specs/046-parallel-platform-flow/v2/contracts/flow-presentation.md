# Contract: Flow 页面投影与分轨合流

## 1. 权威输入

- Flow：`GET /api/flows/current?profile_id=...`
- 真实进度：`GET /api/task-state/{run_id}?profile_id=...`
- 当前流程结果：`GET /api/flows/{flow_id}/results?profile_id=...`
- 本地页面现场：现有 workflow/scene state

不得以固定百分比、前端计时或平台速度推断后台阶段。

## 2. 页面投影

| 页面 | 展示条件 | 平台内容 |
|---|---|---|
| 02 抓取 | Flow 已启动 | 两条 Track 各自的 `scrape_run_id` 快照，完成后仍保留 |
| 03 AI | 任一 Track 已有 AI run/进入 AI/完成 | 只展示已进入 AI 的平台，按首次进入时间纵向追加 |
| 04 结果 | 任一 Track 有结果快照，或 Flow 结果确认有可展示部分岗位 | 只展示当前 Flow 已持久化结果 |

每个进度项必须渲染既有 `TaskProgress.vue`；平台操作按钮仍按 Track 独立转发。

## 3. 解锁与导航

1. 同一 Flow 的解锁集合只增不减。
2. 首个平台进入 AI：解锁 03；非首次水合且用户未手动停留时自动进入 03。
3. 首个平台结果可见：解锁 04；非首次水合且用户未手动停留时自动进入 04。
4. 第二平台到达相同阶段不重复跳页。
5. 用户点回更早的已解锁页后设置手动停留；后续变化不得改 `activeStep`。
6. 用户主动点回最高解锁页后解除手动停留。
7. 刷新先恢复本地 `activeStep`，再水合 Flow；有效页原样保留，无效页钳制到最近可达页，水合本身不自动前进。

## 4. 稳定顺序

- 优先真实任务 `started_at` 升序。
- 当前会话已观察到的进入顺序一经记录不再变化。
- 时间相同或缺失时沿用 Flow Track 初始顺序。
- 后加入平台只能追加，不得把已显示平台换位。

## 5. 结果原地加入

当新平台结果签名首次出现：读取当前 Flow 完整结果；不切 Flow、scene identity、当前分类或平台筛选；不重建 `JobWorkspace`；新结果按当前规则进入集合；发出一次 `{flowId}:{platform}:{resultRunId}` 灵动岛通知。首次刷新水合已有结果时不发幽灵通知。

## 6. 失败与部分结果

- 一条 Track 失败不改变兄弟 Track。
- 失败 Track 有岗位时，04 保留岗位，并显示平台失败及“未完成 AI 筛选”。
- 无岗位时只显示失败状态。
- 失败不得把整个 Flow 伪装成成功，也不得重新锁住已解锁页面。

## 7. 主题

- `selection=all` 或当前选择“全部”：主题作用域为 `all`。
- light 使用中性黑/深灰；dark 使用中性白/灰。
- 单平台清除 `all` 覆盖，恢复 BOSS/智联品牌。
- 结果加载、历史恢复等旧平台写入不得越过 `all` 作用域。
