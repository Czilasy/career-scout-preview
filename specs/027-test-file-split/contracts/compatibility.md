# Contracts: 测试大文件拆分重构（027）

## C1: 测试收集契约

- 收集命令不变：`uv run python -m unittest discover -s tests`（CI 口径）。
- 收集总数不变：任何批次边界与终检，收集到的用例总数与基线快照一致。
- 子目录完整收集：7 个新子目录内全部 `test_*.py` 均被递归收集（以清单对账实证，不依赖口头保证）。
- 共享帮手模块（`harness.py`、`builders.py`）与 `__init__.py` 不被收集、不产生用例。

## C2: 等价性契约

- 清单恒等：每批之后与终检，「类名.方法名」含重复排序列表与基线快照逐行零差异。
- 行为恒等：每批之后后端全量测试全绿，结果（通过/跳过构成）与基线一致。
- 代码体逐字：每个用例的方法体、断言、装饰器、测试数据以 git diff 审查确认为纯搬运（删行与增行内容一致），无改写。

## C3: 改动范围契约

- 产品代码零改动：`webui/**`、`scripts/**`、`webui/src/**`、`.github/**`、`hooks/**`、`pyproject.toml`、`uv.lock` 全程无 diff。
- 测试改动范围：仅限 7 个被拆文件的删除、新子目录及其文件；2000 行以下的既有测试文件、`tests/fixtures/`、非测试脚本零改动。
- `specs/` 文档与 BACKLOG 的状态更新不在上述限制内。

## C4: 纪律契约

- 发现既有测试缺陷不修，原样搬运并记 BACKLOG。
- 每批一个 `refactor` Conventional Commit，全绿前不提交；不自动 push。
- 带理由的 ≤2200 行豁免必须写入该批提交说明。
- 版本不提升；不触发打包与发布动作。
