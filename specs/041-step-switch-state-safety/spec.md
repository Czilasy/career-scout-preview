# Feature Specification: 步骤页切换状态交接安全（B098 + B093 + B092）

**Feature Branch**: `041-step-switch-state-safety`

**Created**: 2026-09-12

**Status**: Draft

**Input**: 用户冻结需求（经逐条边界质询锁定，最高权威，禁止扩写/收窄）：

统一设计原则一句话：**各管各的，互不打扰。** 后台任务不被用户位置打断，用户离开不打断后台，回来按真实状态展示；切页不重建清场，该留的留该清的清。

三条 bug 单合并立项：
- **B098**（P1，Bug/架构）：切换步骤页时把该页整块拆掉重建，记录在页面内部的东西随之丢失；灵动岛点击落点错位、最坏把现场清成空白上传页。本 Spec 冻结四块边界：A 必须保留、B 必须重置、C 灵动岛各态落点、D 补抓/重抓不切页。
- **B093**（P1，Bug）：上传简历、AI 分析中时仍可点灵动岛或切其他页，分析完毕后状态错乱、灵动岛误报浏览器找不到/刷新失败。原 bug 单写的修法（一上传就立即断开旧连接锁住用户）已被用户升级为：分析中不锁、后台照跑、回来按真实进度落点。
- **B092**（P1，Bug）：只抓取流程下结果页确认筛选条件时仍只展示六类，第七类（招聘者活跃时间）没跟前六类一起出现。后端第七类 schema 已存在，前端只抓取流程结果页确认那步没把它接进来。

关联：`specs/035-task-history-safety`（任务状态恢复与各页一致，已落地，本 Spec 在其上补「页面内部现场保留」）、`specs/036-titlebar-dynamic-island`、`specs/037-dynamic-island-v3`（灵动岛态机已落地，本 Spec 补「各态点击落点」）、`specs/028-recruiter-activity-filter`（第七类已实现，本 Spec 补「只抓取流程结果页确认接进来」）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 切页、翻历史、刷新都不丢页面内现场（B098 · A 块）(Priority: P1)

用户在某一轮的操作现场（滚动位置、选中哪条、草稿、详情开合、已加载目录等）是这一轮自己的；切步骤页、翻历史别的轮次、刷新页面都不许动它，回来按原样接上。历史各轮的查看现场也各自留着（只存实际翻过的那几轮），但历史轮次不留草稿——草稿是「正在调、还没定」的东西，历史轮次结果已定稿，只有该轮已定的筛选状态。

**必须保留清单**（切页/翻历史/刷新后这些都在）：
- 页面二（广泛抓取）：画像输入框已撑开的高度；城市/区县面板已加载的区与商圈目录、面板展开/收起状态；折叠卡片内的滚动位置；未记开始时间的任务「已用秒数」接着计，不从零重算。
- 页面四（查看结果）：排序方式；筛选条件（含未确认草稿）；已往下滚加载出来的批次；当前选中哪条岗位、「手动选过」的标记；右侧详情开合、JD 读到哪、列表滚到哪。
- 页面一、页面三：按统一原则，凡记在页面内的状态都留（这两页现场本就轻，但口径不留特例口子）。

**Why this priority**: P1。用户的操作现场无故丢失、需要重复操作，且部分重置由系统自动切页触发、用户无法避免——这是「各管各的、互不打扰」原则最直接的违反。

**Independent Test**: 构造一轮在页面四滚到第 3 批、选中第 5 条、详情展开、筛选草稿未确认 → 切到页面二再回页面四 → 上述现场全部保留；再翻历史第 N 轮看一眼 → 回当前轮 → 现场原样接上；历史第 N 轮下次再翻，其滚动位置接上上次。

**Acceptance Scenarios**:

1. **Given** 当前轮页面四已滚到第 3 批、选中第 5 条、详情展开、筛选草稿未确认，**When** 切到页面二再切回页面四，**Then** 滚动位置、选中条、详情开合、草稿全部保留，不回到默认。
2. **Given** 当前轮页面四有上述现场，**When** 翻历史第 N 轮看一眼再回当前轮，**Then** 当前轮页面四现场原样接上，未被清空。
3. **Given** 用户翻历史第 N 轮时滚到某位置，**When** 切走再翻回第 N 轮，**Then** 第 N 轮的查看现场（滚动、选中、详情开合）接上上次；但第 N 轮不存在「未确认草稿」，只展示该轮已定筛选状态。
4. **Given** 页面二画像框已撑开高度、区县面板已加载目录并展开，**When** 切走再回页面二，**Then** 高度、目录、展开状态保留，不需重新加载。
5. **Given** 任一轮次任一页面有现场，**When** 刷新页面，**Then** 现场从持久化/任务状态恢复，按原样接上，不回默认。
6. **Given** 历史轮次很多但只翻过其中 3 轮，**When** 查看状态存储，**Then** 只为翻过的 3 轮存查看现场，未翻过的用默认，不无限膨胀。

### User Story 2 - 只有主体身份变才清现场，其他一律不清（B098 · B 块）(Priority: P1)

现场绑在「哪个画像 + 哪一轮 + 哪个平台」上。只有主体身份变了才清成默认，其他场景（切页、翻历史、刷新、后台跑完冒泡）一律不清。

**必须重置场景与清空内容**：
- **切换求职画像**：清掉属于旧画像的一切——历史抽屉里的轮次列表与详情、城市/区县草稿、页面四当前轮结果现场（选中、草稿、滚动、详情位置）；新画像从干净开始（页面四空、画像框重置、城市回默认、历史抽屉空）。
- **开新一轮（同一画像）**：旧轮不「清掉」，它**降级成历史轮**，其现场按 US1 规矩作为该历史轮的查看现场保留；新轮页面四回默认（默认排序、选中第一条、滚到顶、无未确认草稿）；已确认筛选条件算旧轮定稿状态，跟着旧轮走，不串到新轮。
- **切换平台（BOSS↔智联）**：旧平台草稿隔离保留在旧平台，不串到新平台；新平台用自己的草稿和现场。

**清成的默认态**：该轮真实结果 + 默认排序 + 选中第一条 + 滚到顶 + 无未确认草稿。

**Why this priority**: P1。B098 同时存在反方向问题——该清没清（切画像时历史抽屉残留、城市草稿串到新画像参与搜索范围）。留与清两边都钉死，不留灰色地带。

**Independent Test**: 构造画像 A 有 3 轮历史 + 页面四现场 + 城市草稿 → 切换到画像 B → 历史抽屉空、城市回默认、页面四空；再切回画像 A → 画像 A 的历史 3 轮与现场原样恢复。

**Acceptance Scenarios**:

1. **Given** 画像 A 有历史 3 轮、页面四有现场、城市草稿选了某区，**When** 切换到画像 B，**Then** 历史抽屉空、城市回默认、页面四空，画像 B 从干净开始。
2. **Given** 画像 A 已切走到画像 B，**When** 切回画像 A，**Then** 画像 A 的历史 3 轮、页面四现场、城市草稿原样恢复，互不串台。
3. **Given** 当前轮是第 8 轮、页面四有现场，**When** 开新一轮（第 9 轮），**Then** 第 8 轮降级为历史轮、其查看现场保留，第 9 轮页面四回默认（默认排序、选中第一条、滚到顶、无草稿）。
4. **Given** BOSS 平台有草稿，**When** 切到智联平台，**Then** BOSS 草稿留在 BOSS、不串到智联，智联用自己的草稿；切回 BOSS 草稿原样。
5. **Given** 切页、翻历史、刷新、后台跑完冒泡任一发生，**When** 查看现场，**Then** 现场不被清（只有 US2 三个主体变更场景才清）。

### User Story 3 - 灵动岛各态点击落到正确现场，绝不清场（B098 · C 块）(Priority: P1)

点灵动岛胶囊或通知面板里的行，去「此刻最该处理的事 + 任务真实进度」对应的现场；落点永远回当前轮对应页，历史现场原地保留；任何路径都不许把页面清成空白上传页。

**胶囊各态点击落点**：
- 空闲（无任务无结果）→ 页面一
- 分析中（简历在分析）→ 页面一（显示分析中）
- 运行中·抓取 → 当前轮页面二
- 运行中·筛选 → 当前轮页面三
- 跑完（有/无待确认）→ 当前轮页面四
- 暂停 → 任务卡住的那步页（抓取中卡→页面二，筛选中卡→页面三，按真实进度）
- 出错 → 任务卡住的那步页（同上，按真实进度）

通知面板里那些行点击：去该通知对应的现场，规矩同上。

**Why this priority**: P1。B098 灵动岛特有严重问题：正在浏览历史轮时点灵动岛被静默退出历史、现场被清成空白上传页；落点错位到未启用页面三；占位期间点击被吞掉且锁死后续。这使灵动岛「一眼知道状况、一点就到现场」的承诺落空。

**Independent Test**: 构造当前轮第 8 轮跑完、用户正在翻历史第 3 轮 → 点灵动岛 → 切回第 8 轮页面四，历史第 3 轮现场原地保留；再构造任务暂停在抓取阶段 → 点灵动岛 → 落到页面二（不是页面三）。

**Acceptance Scenarios**:

1. **Given** 当前轮第 8 轮跑完、用户正在翻历史第 3 轮，**When** 点灵动岛胶囊，**Then** 切回第 8 轮页面四，历史第 3 轮查看现场原地保留，用户想回历史再翻。
2. **Given** 任务暂停在抓取阶段（页面三未启用），**When** 点灵动岛，**Then** 落到页面二（真正能处理的地方），不落到未启用的页面三。
3. **Given** 任务出错在筛选阶段，**When** 点灵动岛，**Then** 落到页面三，按真实进度派生，不无脑送页面二。
4. **Given** 简历分析中，**When** 点灵动岛，**Then** 落到页面一显示分析中。
5. **Given** 启动加载占位期间，**When** 点灵动岛，**Then** 要么等加载完执行这次点击，要么明确不响应，但绝不吞掉点击还锁死下一次同目标点击。
6. **Given** 任何点击路径，**When** 触发，**Then** 永远不出现「页面被清成干净空白上传页」的结果。

### User Story 4 - 补抓 JD / 全部重抓不切页，后台跑 + 灵动岛进度 + 页面四原地更新（B098 · D 块）(Priority: P1)

在页面四点「补抓 JD」或「全部重抓」，不再自动切到页面三再切回页面四。补抓/重抓在后台跑，进度由灵动岛体现（运行中态），页面四现场全部保留；完成后灵动岛变跑完态，页面四原地增量展示新结果，现场不动。

**Why this priority**: P1。现在补抓/重抓会先自动切页面三、完成后切回页面四，即使不主动切页也必然重置一次现场——这是「后台干活清了用户现场」的打扰，违反原则。

**Independent Test**: 构造页面四滚到第 3 批、选中第 5 条、详情展开 → 点「补抓 JD」→ 不切页、灵动岛显示补抓进度、页面四现场不动 → 完成后第 5 条内容更新、现场（滚动/选中/详情开合）保留。

**Acceptance Scenarios**:

1. **Given** 页面四有现场（滚动/选中/详情开合/筛选草稿），**When** 点「补抓 JD」或「全部重抓」，**Then** 不切页，留在页面四，补抓/重抓在后台跑，灵动岛显示进度。
2. **Given** 补抓/重抓进行中，**When** 查看页面四，**Then** 现场保留，不被重置。
3. **Given** 补抓/重抓完成，**When** 灵动岛变跑完态，**Then** 页面四原地展示新结果，岗位内容更新（新 JD、新判定），用户的排序方式、选中岗位（按身份跟随，不按列表位置）、滚动、详情开合保留。
4. **Given** 补抓/重抓中用户想看筛选详情，**When** 主动点灵动岛去页面三，**Then** 按 US3 落点规矩去页面三，但不强制切。

### User Story 5 - 简历分析中不锁用户，后台照跑，回来按真实进度落点（B093）(Priority: P1)

用户上传简历点分析后，不被锁住。后台简历分析照常跑，分析中用户可以点灵动岛、去历史翻别的轮次。用户回当前流程（主动切回或点「回到最新」）：分析完了 → 落 02 抓取页；没完 → 落 01 简历页、显示分析中。灵动岛在分析中态显示「分析中」，点回页面一。

**Why this priority**: P1。现状分析中允许点灵动岛/切页，分析完毕后状态错乱、灵动岛误报浏览器找不到/刷新失败。原 bug 单「一上传就立即断开旧连接锁住」的修法被用户升级为更宽更对的「不锁、后台跑、回来按进度落点」。

**Independent Test**: 构造上传简历点分析、分析中 → 去历史翻第 5 轮 → 分析后台继续 → 点「回到最新」：若分析完→落页面二，若没完→落页面一显示分析中；分析完毕自动进页面二。

**Acceptance Scenarios**:

1. **Given** 简历分析中，**When** 用户点灵动岛或去历史翻别的轮次，**Then** 不被锁、不打断后台分析，后台照常跑。
2. **Given** 分析中用户去了历史，**When** 点「回到最新」或主动切回当前流程，**Then** 分析完了→落页面二；没完→落页面一显示分析中。
3. **Given** 简历分析在后台跑完，**When** 分析完成，**Then** 自动进入页面二（当前轮流程推进）。
4. **Given** 简历分析中，**When** 查看灵动岛，**Then** 显示「分析中」态，点击回页面一。
5. **Given** 分析中用户离开后回来，**When** 查看页面一，**Then** 不出现「浏览器找不到/刷新失败」等与真实进度不一致的误报；用户看到的报错与真实失败一致。

### User Story 6 - 只抓取流程结果页确认条件时第七类条件跟六类一起出现（B092）(Priority: P1)

用户走只抓取流程（不在页面二确认筛选条件、直接抓、抓完到结果页手动确认条件）时，结果页确认条件那一步把第七类「招聘者活跃时间」跟前六类一样摆出来、可看、可选、可确认，与页面二的条件集合一致。

**Why this priority**: P1。第七类条件后端已实现（spec 028），但只抓取流程下结果页确认那步没把它接进来，用户无法在完整条件集上完成确认。

**Independent Test**: 走只抓取流程抓完一轮 → 进结果页确认条件 → 七类条件全部出现、可选项与页面二一致、可确认生效。

**Acceptance Scenarios**:

1. **Given** 走只抓取流程抓完一轮，**When** 进结果页确认筛选条件，**Then** 第七类「招聘者活跃时间」跟前六类一起出现，可选项与页面二一致。
2. **Given** 结果页确认条件时选了第七类某档，**When** 确认提交，**Then** 第七类选择生效，参与后续判定。
3. **Given** 页面二能设的第七类选项集，**When** 对比只抓取流程结果页确认的第七类选项集，**Then** 两者一致，不缺不漏。

### Edge Cases

- 当前轮后台跑完时用户正在翻历史 → 不打扰，灵动岛冒泡提示，用户回当前轮看到的是最新结果，历史轮现场原地保留。
- 补抓/重抓后用户选中的岗位在列表中位置变了（因重新排序）→ 选中按岗位身份跟随，不按列表位置丢；若该岗位被重抓后消失，选中回第一条并提示。
- 历史轮次翻过多个 → 每个翻过的轮次查看现场各自保留，互不串台；未翻过的用默认，不无限存。
- 切画像时历史抽屉里有正在查看的历史轮 → 抽屉清空，回到新画像干净态，旧画像历史不串入。
- 切平台时旧平台正有未确认草稿 → 草稿留在旧平台，不串入新平台参与新平台搜索范围。
- 启动加载占位期间连点灵动岛多次 → 不吞不锁，加载完成后只执行一次有效落点，不重复切页。
- 简历分析失败 → 按真实失败展示，不出现「浏览器找不到」式误报，用户回页面一看到真实失败原因。
- 暂停任务在页面二，用户点灵动岛 → 落页面二；若暂停时页面二未启用（任务还没到抓取），按真实进度落到对应启用页，不送未启用页。

## Requirements *(mandatory)*

### Functional Requirements

**A 块 · 必须保留**：
- **FR-001**: 切换步骤页时，页面内部记录的现场（滚动位置、选中、草稿、详情开合、已加载目录、面板展开、计时等）MUST 原样保留，不得因切页而拆掉重建导致丢失。
- **FR-002**: 翻历史别的轮次时，当前轮现场 MUST 原地保留，用户回当前轮按原样接上；历史各轮的查看现场（滚动、选中、详情开合）MUST 各自保留（只存实际翻过的轮次），但历史轮次 MUST NOT 保留「未确认草稿」，只展示该轮已定筛选状态。
- **FR-003**: 刷新页面后，现场 MUST 从持久化/任务状态恢复，按原样接上，不回默认。
- **FR-004**: 现场 MUST 绑在「画像 + 轮次 + 平台」身份上，切页/翻历史/刷新/后台跑完冒泡 MUST NOT 改动现场。

**B 块 · 必须重置**：
- **FR-005**: 只有以下三个主体身份变更场景才清现场：切换求职画像、开新一轮（同画像）、切换平台；其他场景 MUST NOT 清现场。
- **FR-006**: 切换求职画像时 MUST 清掉属于旧画像的一切（历史抽屉轮次与详情、城市/区县草稿、页面四当前轮结果现场），新画像从干净默认开始。
- **FR-007**: 开新一轮时旧轮 MUST 降级为历史轮（其查看现场按 FR-002 保留），新轮页面四回默认（默认排序、选中第一条、滚到顶、无未确认草稿），旧轮已确认筛选条件跟着旧轮走，MUST NOT 串到新轮。
- **FR-008**: 切换平台时旧平台草稿 MUST 隔离保留在旧平台，MUST NOT 串到新平台参与新平台搜索范围。
- **FR-009**: 清成的默认态为：该轮真实结果 + 默认排序 + 选中第一条 + 滚到顶 + 无未确认草稿。

**C 块 · 灵动岛落点**：
- **FR-010**: 灵动岛胶囊各态点击落点 MUST 按任务真实进度派生：空闲→页面一；分析中→页面一；运行中抓取→当前轮页面二；运行中筛选→当前轮页面三；跑完→当前轮页面四；暂停/出错→任务卡住的那步页（按真实进度，不无脑送固定页）。
- **FR-011**: 点灵动岛/通知行 MUST 切回当前轮对应页，历史轮现场 MUST 原地保留，MUST NOT 出现「被静默退出历史后清空现场」的路径。
- **FR-012**: 任何点击路径 MUST NOT 把页面清成空白上传页（硬红线）。
- **FR-013**: 启动加载占位期间点击 MUST NOT 被吞掉且锁死后续同目标点击；要么等加载完执行，要么明确不响应但放行下一次。
- **FR-014**: 通知面板行点击 MUST 去该通知对应现场，规矩同胶囊点击。

**D 块 · 补抓/重抓**：
- **FR-015**: 点「补抓 JD」/「全部重抓」MUST NOT 自动切页，MUST 留在页面四，补抓/重抓在后台跑，进度由灵动岛体现。
- **FR-016**: 补抓/重抓期间页面四现场 MUST 全部保留（排序、选中、滚动、草稿、详情开合、已加载批次）。
- **FR-017**: 补抓/重抓完成后页面四 MUST 原地增量展示新结果，用户选中的岗位 MUST 按身份跟随（不按列表位置丢），排序方式保留、内容变了自然重排。

**B093 · 分析中**：
- **FR-018**: 简历分析中 MUST NOT 锁用户，后台分析 MUST 照常跑，分析中用户可点灵动岛、去历史翻别的轮次。
- **FR-019**: 用户回当前流程（主动切回或点「回到最新」）时 MUST 按真实进度落点：分析完→页面二；没完→页面一显示分析中。
- **FR-020**: 简历分析完成后 MUST 自动进入页面二（当前轮流程推进）。
- **FR-021**: 灵动岛 MUST 支持「分析中」态，显示分析中，点击回页面一。
- **FR-022**: 分析中及失败展示 MUST 与真实进度一致，MUST NOT 出现「浏览器找不到/刷新失败」等与真实状态不一致的误报。

**B092 · 第七类条件**：
- **FR-023**: 只抓取流程下结果页确认筛选条件那一步 MUST 把第七类「招聘者活跃时间」跟前六类一样展示、可选、可确认，与页面二条件集合一致。
- **FR-024**: 第七类在只抓取流程结果页确认的可选项 MUST 与页面二一致，不缺不漏；确认后 MUST 生效参与判定。

**通用约束**：
- **FR-025**: 本规格改动 MUST 落在树干（通用层，所有平台/页面共用）；树枝（平台侧、页面侧）仅适配各自现场项，新增平台/页面通过登记现场项即获得同样行为。
- **FR-026**: 本规格 MUST 优先复用现有任务状态恢复（035）、灵动岛状态机（036/037）、第七类判定（028）能力；现场外置/独立存档的实现方式由 Plan 定，现有能力不够处可在 Plan 中新增机制，本 Spec 只定边界。

### Key Entities

- **步骤页现场**：记录在某一页面内部的状态（滚动、选中、草稿、详情开合、已加载目录、面板展开、计时等），绑在「画像 + 轮次 + 平台」身份上。
- **轮次身份**：画像 + 轮次编号 + 平台三者组合，是现场归属的唯一标识；身份变则清，身份不变则留。
- **查看现场**：历史轮次的轻量查看状态（滚动、选中、详情开合），只存实际翻过的轮次；与「草稿」对立——草稿只属于当前轮操作中，历史轮无草稿。
- **灵动岛态**：空闲/分析中/运行中抓取/运行中筛选/跑完/暂停/出错，各态点击落点由任务真实进度派生。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 切页、翻历史、刷新后，US1 列出的必须保留项 100% 保留，不回默认。
- **SC-002**: 只有切换画像/开新轮/切平台三个场景清现场，清后达到默认态；其他场景不清现场，覆盖率 100%。
- **SC-003**: 灵动岛各态点击落点 100% 正确（按真实进度派生），任何路径都不出现「页面被清成空白上传页」。
- **SC-004**: 补抓/重抓不切页、现场保留 100%，完成后结果增量更新、选中岗位按身份跟随。
- **SC-005**: 简历分析中可离开、后台照跑，回来按进度落点（完→02/没完→01分析中），不出现误报。
- **SC-006**: 只抓取流程结果页确认条件时第七类 100% 出现、可选可确认，与页面二选项集一致。
- **SC-007**: 切画像时历史抽屉、城市草稿、页面四现场清干净，不串到新画像；切平台时草稿不串台。

## Verification Scope *(mandatory)*

- 功能/重构/拆分交付：验证范围为相关模块聚焦测试、后端全量测试、前端测试、`npm run build`、仓库卫生检查。
- 收口发布任务：默认只做卫生测试、hooks、`git diff --check`、`git status` 和 `scripts/release_check.ps1`（若存在）；不自动要求全量测试。
- 只有用户明确要求「全量/全部测试/完整验证」时，收口任务才执行全量测试。
- 界面类验收 MUST 按模拟用户视角真实操作路径逐条走查，静态读码不能代替界面走查（035 教训）。

## Assumptions

- 现有任务状态恢复（035）、灵动岛状态机（036/037）、第七类判定（028）能力可直接复用，不新增数据库表。
- 现场「外置/独立存档」的具体实现方式（存哪、用什么机制）由 Plan/Tasks 定，本 Spec 只定「该留的留该清的清」边界。
- B092 后端第七类 schema 已存在（BOSS/智联 filter_schema.fields 均含 recruiter_activity），本 Spec 只需让只抓取流程结果页确认那步把它接进来，属前端适配。
- 历史轮次查看现场采用懒存（只存实际翻过的轮次），上限受用户实际翻看行为约束，不无限膨胀。
- 选中岗位在重抓后按「身份」跟随，不按列表位置；身份标识沿用现有岗位唯一标识。
- 用户已明确需求、边界经逐条质询冻结，不再另行 clarify。
